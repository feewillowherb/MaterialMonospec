## Context

基线为 MaterialClient `1d14322`。稳定任务记住重量，在等待抓拍后才读取实时车牌；事务结束后无周期检查地写回 recordId。下磅收尾与建单通过 Merge(5) 并发。调查测试确认跨周期读取/回写及 Finalize 失败残留；改牌读取异常本身被内部捕获，仍继续清理。完整目标环境验收尚未执行。

## Goals / Non-Goals

目标：A 的任务不读写 B 的数据；同周期创建幂等；旧记录收尾故障不阻塞下一车。

不修改正常离磅阈值、Urban 车牌缓存业务规则、音柱隔离及并发度；不保证通过应用 CycleId 识别 SDK 无关联信息的旧回包；不改附件失败 Pending 规则。不把无车牌、无图片当作记录同步拒绝条件。抓拍耗时诊断另案。

## Decisions

### 1. 周期对象及身份

实际从 OffScale 进入新称重周期时创建 Guid.NewGuid()，不能在每次采样或判稳时换号。重复稳定状态属于原周期。确认离磅后再次上磅产生新号。另外两处既有边界也产生新号，并且不经过 OffScale：

- 直接调用 `CreateWeighingRecordAsync` 时，若当前周期已结束、已提交、失败或已舍弃，先开始新周期再创建。同一 `WeighingCycle` 上的重复创建仍然只有一次提交。判稳回调使用已捕获的周期，不因这条直接调用规则换号。这样保留 Urban 稳定上传里“同车牌拦截、换车牌可再建一单”的行为，同时每条记录仍有自己的 CycleId。
- 已产出车牌保持到期（`TryReleaseExpiredProducedHold`）时，封存当前周期并开始新周期，然后清除当前 RecordId。每周期仍只有一条记录，到期后可以再次建单。

启动恢复不把旧记录恢复成当前在磅周期。

用命名 record 传递 `WeighingCycleSnapshot` 与 `WeighingCycleVehicleInfo`。快照含 CycleId、稳定重量、已知车牌及车辆信息、DeliveryType、判稳时间。周期状态由自身方法变更，Service 不逐字段写实体，不新增 mapper 或纯逻辑 DI。逻辑周期对象不必是数据库实体。

判稳时捕获所属周期信息，建单不再读取全局实时车牌。仍处于同周期时允许既有的晚到识别更新该周期候选信息；结束周期时封存，旧记录改牌及 Urban anomaly recalc 只能读取封存的该周期数据。检查全部副作用入口，尤其 UrbanWeighingRecordSideEffects 当前读取全局 PlateNumberService 的路径。

### 2. 创建与周期切换并发

每周期维护创建状态（未开始、创建中、已提交、失败/已舍弃），状态转换由周期对象同步保护。重复请求不能同时 Insert。数据库调用不能在普通 lock 中 await；选择每周期异步同步机制，不能把全局锁持有到抓拍结束以阻塞离磅或下一车。

抓拍等待期间不占创建提交的周期锁。返回后若周期已结束且尚未取得创建资格，则舍弃任务并记录日志，不建空记录。若创建已经开始，使用封存原周期信息完成或失败，已提交记录不删除；它只关联原周期 RecordId，不回写新的 CurrentCycle。提交前后的竞态均由创建状态和固定周期引用处理，不能只比较一次 CurrentCycleId。

记录以类型归属方法保存 ExtraProperties["WeighingCycleId"]（Guid 字符串）。进程内同周期唯一创建由同步状态保证，不依赖车牌去重。事务提交不确定时不盲目重跑 Insert；先按已保存 CycleId 对账，无法确定时记录失败，不伪造成功。

### 3. 下磅释放与旧记录收尾

下磅先将周期封存并从当前周期分离，清理该周期的实时缓存关联，使下一车可开始；将固定周期快照交给旧记录收尾。不能在旧任务结束时无条件 ClearCache/ResetCycle 清除 B 的信息。

若下磅时创建仍在途，结束周期标记由创建完成路径感知；提交成功后为旧记录安排收尾。若未建单则无需恢复任务。改牌、Urban Finalize 与重试都传固定 RecordId 和封存上下文，不重新取当前记录 ID。旧周期迟到照片舍弃，已提交记录缺图可标为不完整。

### 4. 持久恢复状态与边界

设计默认：初次收尾失败后最多后台重试 3 次，分别等待 5、30、120 秒；单进程逐个领取到期任务，不占称重 Merge(5) 槽。达到上限标记 Exhausted，不自动开始新一轮。次数、间隔集中定义，不散落魔法值。

ExtraProperties["WeighingCycleRecovery"] 使用版本化结构：CycleId、固定 RecordId、封存收尾数据、Status（Pending/Running/Completed/Exhausted）、AttemptCount、NextAttemptAtUtc、LastErrorCode、UpdatedAtUtc。错误信息截断且不存敏感凭证。附加业务异常写入 ExtraProperties["WeighingCycleAnomalies"]，诊断标记不改变既有 IsAnomaly/SyncStatus 业务含义。

新记录事务内持久保存原周期信息及待完成收尾状态，使提交后进程中断仍可恢复；尚未离磅的当前周期不能被后台提前收尾。调度以周期已结束为前提；进程重启后无当前车辆占用旧周期，可恢复持久未完成记录。启动扫描仅处理带本 change 版本标识的记录，不猜测历史记录的周期。

每次重试在副作用之前持久增加计数，成功后标记 Completed。认领、完成和失败各自使用新的工作单元提交，不挂在已经完成的建单事务上，也不把副作用包进同一次提交。重启不会重置额度；上次 Running 按一次已消耗尝试处理，在剩余额度内恢复。收尾必须按记录 ID 幂等：重复设置 Pending 不能把已经 Synced 的记录重新排队，不能重跑建单。诊断保存或数据库不可用时不反复热循环，记录错误并按有界调度退避；已存在持久状态可重启恢复，但不能承诺数据库完全不可写时仍能保存最新错误。

### 5. 同步行为保持

没有本地图片或车牌时允许既有同步；附件上传失败保留 Pending 的规范不变。收尾恢复失败不得被误当作同步成功，也不能为绕过错误伪造图片、车牌。对已提交记录的就绪推进按固定 RecordId 处理，正常 Urban stable-upload 及异常标记逻辑保持。

## Risks / Validation

- 快照可能影响晚到改牌：保留同周期更新，封存后禁止借用新周期；用连续车辆测试覆盖。
- ExtraProperties JSON 查询及反序列化须核对当前 SQLite/ABP 映射；实现前做最小持久化、重启重读验证。若不支持可靠恢复扫描，先修订设计，不能只做内存队列冒充持久恢复。
- 仅单客户端进程内幂等，不新增跨进程共享数据库支持。重启前提交结果不确定必须对账。
- 测试覆盖抓拍前后、Insert/commit 前后离磅，旧任务回写、并发建单、Finalize 失败、重试耗尽、重启接续、无图无牌及附件失败仍 Pending。故障注入不能宣称现场抓拍存在延迟故障。

## Rollout / Acceptance

先验证 ExtraProperties 持久结构与收尾幂等，再实现周期传播和恢复。旧记录缺少新字段按原逻辑读取，不回填历史周期。无 schema 迁移；回滚前停止恢复 worker，保留诊断字段，记录待恢复项，不静默遗忘。

ICD 目标 L3：正常连续称重及本 change 声明的失败行为在目标客户端可用；回归测试提供保护，但不以构建或测试通过推断目标环境验收。独立记录命令、基线、配置、日志与记录 ID；环境缺失时保持对应任务未完成。
