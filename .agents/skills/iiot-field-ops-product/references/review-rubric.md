# IIoT & Field Operations Product Review Rubric

用于对工业物联网 / 现场运维管理台（如项目与工控机监控、称重/通行核查、异常审批、远程日志、OTA 更新）进行系统化产品完善度评审。

---

## 维度 1：异常分诊与可扫性（Triage & Scanability）
- [ ] 主列表是否支持 1 次点击筛出「异常 / 离线 / 待处理」站点或记录？
- [ ] 状态色语义是否全站统一（在线/成功=绿、离线/异常/失败=红、待处理/警告=橙、未注册/未知=灰）？
- [ ] 表格列中是否混入了不产生现场处置动作的冗余指标或次要设备信息？
- [ ] 关键识别列（项目名、车牌、工控机/抓拍机状态）默认是否无需横向滚动即可一眼看见？

## 维度 2：设备状态与时间语义（State & Time Honesty）
- [ ] 工控机状态与外设状态（如抓拍机）是否语义独立、不互相掩盖？
- [ ] 老客户端/降级接入模式是否明确标注，避免被误判为新客户端故障？
- [ ] 仅需日期的字段（如授权过期时间）是否用 `yyyy-MM-dd` 而非冗长的 `HH:mm:ss`？
- [ ] 排查类时间（最后在线、抓拍/称重时间、同步时间）是否清晰对齐且时区一致？

## 维度 3：证据核查与动线闭环（Evidence & Workflow Closure）
- [ ] 称重、卡口、成品、异常审批列表是否行内直接展示 2 张现场缩略图（懒加载 + 点击放大），无需逐条点「查看照片」弹窗？
- [ ] 行内图片是否使用轻量 URL/缩略图端点，而非列表直出大体积原图 Base64 或逐行 N+1 查询？
- [ ] 缺图或图片加载失败时是否有明确占位（及已知异常原因提示），而非裂图或空白？
- [ ] 核查行内「车牌 / 重量 / 2 张图 / 异常原因 / 操作」是否处于连贯视线带？
- [ ] 从项目/工控机异常行是否能顺畅带参跳转到称重记录、日志排查或 OTA 更新？

## 维度 4：表格与筛选人机工程（Table & Filter Ergonomics）
- [ ] 所有业务表是否为独立吸顶滚动容器，且**所有表头均支持用户手动拖拽调整列宽**？
- [ ] 长项目名搜索下拉是否与窄输入框解耦，支持宽弹层自动换行完整展示项目全称？
- [ ] 筛选条件、日期区间、分页是否同步至 URL Query（刷新不丢、可复制链接分享）？
- [ ] 日期筛选是否提供快捷选项（今日 / 近 3 天 / 近 7 天），空态是否有扩大时间范围的引导？
- [ ] 地址等低频长文本列是否默认收窄 + 溢出省略 + hover Tooltip 查看全文？

## 维度 5：操作安全与专业文案（Safety & Copy）
- [ ] 写操作（开关同步、重置同步、审批、推送 OTA、批量删除）是否有 Loading 防连点与明确结果提示（且不被刷新瞬间清空）？
- [ ] 会话失效（401）时是否清晰引导重新登录，而非静默报错或空白页？
- [ ] 页面文案是否 100% 为业务/运维名词，无研发术语、架构说明、Mock/FEV/OpenSpec 文案泄漏？

---

## 评审结论分级标准

| 级别 | 判定标准 | 处理要求 |
|------|----------|----------|
| **Blocker** | 导致运维选错项目、误判设备状态、无法完成排查闭环或列表性能不可用 | 必须在本轮修订前解决 |
| **Friction** | 高频任务需要多余点击/弹窗/反复拖滚动条/刷新丢条件 | 强烈建议在本轮一并解决 |
| **Polish** | 列宽微调、日期格式统一、空态引导、视觉节奏优化 | 随当前迭代顺手收口 |
