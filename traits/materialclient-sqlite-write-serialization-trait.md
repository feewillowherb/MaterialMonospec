# MaterialClient SQLite 写入串行化

适用于 MaterialClient 中新增或修改的 SQLite 业务写入、ABP UoW 和跨 DbContext 写入。

- 同一进程对同一 SQLite 文件的业务写入 MUST 串行。写入口先取得该数据库文件的写入资格，再开始写事务，提交或回滚并释放事务后归还资格。
- 内层辅助方法 MUST 沿用调用方的 UoW。禁止在同一数据库文件的写事务内使用 `requiresNew: true` 发起独立写入。需要分阶段提交时，上一阶段结束并释放事务后，由外层协调下一阶段。
- 需要原子完成的跨 DbContext 写入 MUST 共用实际连接和事务，并在真实 SQLite 文件上验证。提前 `autoSave` 只用于确实依赖数据库生成值或需要提前检查约束的场景。
- 网络、硬件和文件操作安排在写事务外。普通查询无需排入写队列。事务提交前执行的事件处理只能沿用当前写事务，独立写入应安排在提交后。
- 多进程写入由部署流程协调。升级工具写部署库时，应用必须退出并释放连接。
