## 3. 建议讨论的收敛方向

1. **统一客户端身份（单一 `ClientIdentity`）**：全仓统一 `ClientId` 生成规则（`Client:Id` 非空优先 → 确定性机器标识 / `Environment.MachineName`），消除 `DeviceStatusEventHandler`、`ClientLogPullService`、`ClientOtaControlService` 三处各自拼接的问题。
2. **下沉共享层，Urban 与 Recycle 共用一套维护骨架**：将日志拉取、SignalR 心跳与设备状态上报下沉至 `MaterialClient.Common`（或独立维护模块），`Urban` 与 `Recycle` 只需声明 `ProductCode` 即可零重复接入；同步下线服务端平行空壳 `RecycleDeviceStatus` 与 `/recycle/device-status`。
3. **合并 Hub 注册与引入轻量周期心跳**：用单一 `ClientHello / ClientHeartbeat` 统一承载在线保活、`AppVersion`、`Capabilities`、`ClientKind` 与最新状态，修复 `_isStarted` 与 `DeviceStatusEventHandler` 假节流/热路径读库问题。
4. **日志拉取瘦身与修 Bug**：先修 0 字节挂死、`Path.GetFullPath` 校验与空串回退；后续按需评估将大文件日志拉取从 SignalR 64KB 内存分片改为 HTTP/tus 复用现有附件上传通道。
