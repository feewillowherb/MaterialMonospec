# 01 — 现状考古

## 1. 双轨上传（必须分清）

```text
[Material 主程序]
  本地 Lpr/Photo* → OssUploadService.PutObject(AK/SK) → Aliyun OSS
                 → AttachmentFile.OssFullPath
                 → MaterialPlatform POST /api/File/UpdateAttaches（仅元数据）

[Urban 产品]
  本地 Lpr/UrbanPhoto → UrbanAttachmentSyncService
                      → multipart 或 tus → UrbanManagement
                      → FileService 写 Uploads/{AccessCode}/
                      → 返回 AttachmentFile Guid → Receive/过车 DTO
```

Urban **不**走 Material 的 OSS 同步；Material **不**走 UM 附件 API。

---

## 2. Material：客户端直传 OSS（已存在）

### 配置

| 项 | 落点 | 代码是否使用 |
|----|------|--------------|
| `AliyunOss:RegionId` | `repos/MaterialClient/src/MaterialClient/appsettings.secret.json`（Urban host 亦有同段） | 是（当作 OSS endpoint host） |
| `AliyunOss:Key` / `Secret` | 同上 | 是 → `new OssClient(RegionId, Key, Secret)` |
| `AliyunOss:BucketName` | 同上 | 是 |
| `AliyunOss:MaxSize` | 同上 | 绑定；上传路径**未强制校验** |
| `AliyunOss:Endpoint` / `UseSsl` | secret JSON 有 | **未**绑定到 `AliyunOssConfig`，无效字段 |

绑定：`MaterialClientCommonModule` → `Configure<AliyunOssConfig>("AliyunOss")`。

公开 `appsettings.json` **无** `AliyunOss`；凭据全在 secret。

### 核心类型

| 类型 | 路径 |
|------|------|
| `AliyunOssConfig` | `repos/MaterialClient/src/MaterialClient.Common/Configuration/AliyunOssConfig.cs` |
| `IOssUploadService` / `OssUploadService` | `.../Services/OssUploadService.cs` |
| `AttachmentService.Sync*ToOssAsync` | `.../Services/AttachmentService.cs` |
| `AttachmentPathUtils.GetOssObjectKey` | `.../Utils/AttachmentPathUtils.cs` |
| `UpdateAttachesInputDto` | `.../Api/Dtos/UpdateAttachesInputDto.cs` |
| NuGet | `Aliyun.OSS.SDK.NetCore`（Directory.Packages.props） |

### 上传行为

1. `EnsureOssClient()`：长期 Key/Secret 构造 `OssClient`（无 SecurityToken）。  
2. `PutObject(bucket, ossObjectKey, localPath)`：整文件简单上传，非分片。  
3. URL：`https://{BucketName}.{RegionId}/{ossObjectKey}`（字符串拼接，非预签名）。  
4. Object key：`{PhotoJianKong|PhotoPiaoJu|Lpr}/{yyyy}/{MM}/{dd}/{attachmentId}_{fileName}`；`UrbanPhoto` 与 `Lpr` 同根 `Lpr/`。  
5. 触发：`PollingBackgroundService` / 过磅 UI → `SyncPendingAttachmentsToOssAsync`（仅已推送运单且 `OssFullPath == null`）。  
6. 成功后调 Material Platform `UpdateAttaches`：`Bucket` + `BucketKey` + `BizId/BizType` 等元数据，**不再传二进制**。

### 安全现状

- 桌面端持有**长期** AccessKey → 反编译 / 配置拷贝即可滥用 Bucket。  
- 与阿里云「客户端勿固化长期密钥」官方建议冲突。  
- Urban host 的 `appsettings.secret.json` 也拷了同段配置，但对 Urban 附件同步是死配置。

## 3. Urban：上传到 UM 本地盘（当前主路径）

### 客户端

| 类型 | 路径 | 职责 |
|------|------|------|
| `UrbanAttachmentSyncService` | `repos/MaterialClient/src/MaterialClient.Urban/Services/UrbanAttachmentSyncService.cs` | 按设置选 multipart 或 tus |
| `UrbanServerUploadService` | `.../UrbanServerUploadService.cs` | 称重上传前先 `UploadAttachmentsAsync` |
| `UrbanPassageUploadService` | `.../UrbanPassageUploadService.cs` | 过车图上传 |
| `IUrbanManagementApi` | `.../Api/IUrbanManagementApi.cs` | Refit：multipart / tus commit / legacy Base64 |

默认：`POST /api/urban-attachment/upload-multipart`。  
`SystemSettings.EnableChunkedAttachmentUpload`：tus + `POST .../tus/commit`。  
过车图：tus 未实现，强制 multipart fallback。

同步类型：`AttachType.Lpr`、`AttachType.UrbanPhoto`。

### UrbanManagement

| 类型 | 路径 | 职责 |
|------|------|------|
| `UrbanAttachmentController` | `repos/UrbanManagement/src/UrbanManagement.App/Controllers/UrbanAttachmentController.cs` | multipart / tus commit |
| `UrbanAttachmentAppService` | `.../Core/Services/UrbanAttachmentAppService.cs` | legacy Base64 |
| `FileService` | `.../Core/Services/FileService.cs` | 落盘、可选压缩、建 `AttachmentFile` |
| `StorageOptions.FilesPhysicalPath` | 默认 `Uploads/` | 相对 ContentRoot |
| `AttachmentFile` | `.../Core/Entities/AttachmentFile.cs` | **仅** `LocalPath` / `FileName` / `AttachType`，**无** OSS 字段 |

盘路径形态：`{ContentRoot}/Uploads/{buildLicenseNo}/{ticks}_{index}.jpg`。

**无** `Aliyun.OSS` 包、无 STS、无预签名 API。

### 下游依赖本地盘

审批预览、`GovCheckpointSyncManager` / `GovProductSyncManager` 等通过 `FileService.Read*Attachment*` **读本地文件**转 Base64 再推政务。若改为纯 OSS 对象，这些读路径必须改为「按 key 从 OSS 拉流」或「服务端缓存副本」。

## 4. BasePlatform 先例（服务端持钥）

`FdSoft.BasePlatform` 通过 `AliyunOssHelper` 在**服务端** `UploadFile` / `DownloadFile` / `DownloadBytes`（如 `CommonController`、考勤相关 Controller）。客户端不持有该 Helper 的密钥。模式是「二进制经服务端中转或服务端读写 OSS」，不是 STS 直传，但说明：**AK/SK 已放在服务端一侧**，可复用运维经验给 UM 持钥。

## 5. OpenSpec / 规范对照

| Spec / 归档 change | 含义 |
|--------------------|------|
| `urban-client-attachment-sync` | Urban → UM 上传契约（现行） |
| `attachment-file-storage` | UM 本地盘 + 压缩 |
| `file-api-relative-path-normalization` | Material OSS 上传前路径归一化 |
| archive `add-urban-attachment-multipart-upload` / `chunked-upload` | 明确**未**引入 OSS 直传 |
| archive `urban-client-attachment-upload` 非目标 | 「不改造主程序 OSS 同步」 |

现行规范**尚未**描述 Urban → OSS 直传；落地需新 OpenSpec change，而不是静默改 runner。
