# 客户端 Aliyun OSS 直传 — 总览

> **日期**：2026-09-11  
> **类型**：代码考古 + 方案选型（仓库知识）  
> **范围**：`MaterialClient`（含 Urban 产品）/ `UrbanManagement`；对照 `FdSoft.BasePlatform` 现有服务端 OSS 用法

## 一句话

Material 产品**已经**用长期 AccessKey 直传 Aliyun OSS；Urban 产品当前把图传到 UM **本地盘**。目标「客户端直传 OSS、appsettings 不配 OSS」应走 **UM（或其它服务端）签发 STS / 预签名 → 客户端 PutObject → 元数据回写 UM**，而不是把 Bucket/Key/Secret 写进客户端配置。

## 结论（先读）

| 产品 | 今日上传目标 | 客户端是否持有 OSS 凭据 |
|------|--------------|-------------------------|
| Material（主程序） | Aliyun OSS 直传 `PutObject`，再 `UpdateAttaches` 元数据到 Material Platform | **是**（`appsettings.secret.json` → `AliyunOss:Key/Secret/...`） |
| Urban（`MaterialClient.Urban`） | multipart / tus → UM `Uploads/` 本地存储 | **否（业务路径）**；secret 里仍有 `AliyunOss` 段但 **Urban 同步未调用** `IOssUploadService` |
| UrbanManagement | 无 OSS SDK；`AttachmentFile.LocalPath` only | N/A（盘上文件） |

安全约束：**禁止**把长期 AccessKey / Bucket Endpoint 固化进客户端 appsettings（含 secret）。客户端只应持有业务 API 地址；OSS Endpoint/Bucket/临时凭证由服务端按会话下发。

## 非目标

- 不在本夹开 OpenSpec change / 不改产品代码  
- 不把 BasePlatform `AliyunOssHelper` 整仓迁到 UM（仅作「服务端持钥」先例）  
- 不宣布 L3 验收通过
