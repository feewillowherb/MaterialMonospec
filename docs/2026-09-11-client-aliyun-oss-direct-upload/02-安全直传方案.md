# 02 — 安全直传方案（客户端不配 OSS）

## 目标约束

1. 客户端 **appsettings（含 secret）不得** 配置 `AliyunOss` 的 Endpoint / Bucket / AccessKey / Secret。  
2. 图片**二进制**直达 Aliyun OSS，不经 UM 带宽中转（可保留「元数据登记」小请求）。  
3. UM 仍能审批预览、政务同步读到图。  
4. 桌面端已有 `Aliyun.OSS.SDK.NetCore`，优先复用 SDK，而不是 HTML PostObject 表单。

官方选型摘要（[客户端直传](https://help.aliyun.com/zh/oss/user-guide/uploading-objects-to-oss-directly-from-clients/)）：

| 模式 | 适用 | 与本仓契合度 |
|------|------|--------------|
| **STS 临时凭证 + OSS SDK** | 桌面/App、可分片/断点、多次 Put | **推荐**（Avalonia + 已有 SDK） |
| 服务端 PostPolicy 签名 + PostObject | Web 表单、单对象、强约束大小/类型 | 可选；桌面非首选 |
| 预签名 URL（PUT/GET） | 单对象、短时、实现薄 | 可选；大批量称重图时 STS 更省往返 |

## 推荐架构（Urban 直传）

```text
MaterialClient.Urban                    UrbanManagement                         Aliyun
─────────────────                       ───────────────                         ──────
1. 鉴权后请求上传票据
   POST /api/.../oss-upload-ticket ──►  AssumeRole / 签发 STS
                                        （RAM 角色策略：仅 Put 指定前缀）
                                  ◄──  { endpoint, bucket, objectKeyPrefix,
                                         accessKeyId, accessKeySecret,
                                         securityToken, expiration }
2. OssClient(endpoint, tempAK, tempSK, token)
   PutObject(bucket, objectKey, localFile) ──────────────────────────────────► OSS
3. POST /api/.../oss-upload-complete ──► 校验 object 存在 / 登记 AttachmentFile
   （bucket + key + attachType + AccessCode）   （OssObjectKey；LocalPath 可空或镜像）
                                  ◄──  AttachmentFile Guid[]
4. 既有 Receive / 过车 API 继续带 Guid
```

### 客户端配置只剩什么

| 可保留 | 禁止 |
|--------|------|
| `UrbanManagement` BaseUrl / 鉴权 | `AliyunOss:*` 任意长期字段 |
| 业务开关（是否启用直传） | 写死 Bucket / Region |

运行时 Endpoint、Bucket、临时密钥一律来自 **ticket 响应**（可短时内存缓存至 `expiration` 前刷新）。

### Object key 建议

由 **服务端** 生成前缀，避免客户端乱写路径：

```text
urban/{AccessCode}/{yyyy}/{MM}/{dd}/{attachType}/{guid}_{safeFileName}.jpg
```

客户端只拼最终文件名或使用服务端返回的完整 `objectKey`。Policy / RAM session policy 限制 `Resource` 为该前缀 `/*`。

### UM 侧持钥

- 长期 AK/SK 或 ECS/ACK 实例角色：只在 **UrbanManagement 服务端**（或独立签发服务）。  
- 配置名示例：`AliyunOss` / `OssOptions` 进 UM `appsettings` / 环境变量 / 密钥库 — **不**下发到客户端安装包。  
- BasePlatform 已有服务端 Helper 经验，可对照运维，但 UM 建议自管配置，避免跨产品硬耦合，除非明确要统一签发中心。

## 方案对比（落地选型）

### A. STS + SDK（推荐）

**优点**：与现有 `OssUploadService` 形态接近；可批量 Put；可后续分片。  
**缺点**：UM 需接 STS AssumeRole；客户端要带 `SecurityToken` 构造 `OssClient`。  
**改造点**：新建 `IOssCredentialAppService`（或 Controller）；改造 `UrbanAttachmentSyncService` 用临时客户端上传；`OssUploadService` 可抽「凭据提供者」以免继续读本地 `IOptions<AliyunOssConfig>`。

### B. 预签名 PUT（每文件一条 URL）

**优点**：客户端甚至可不依赖完整 OSS SDK（HttpClient PUT）；权限面极窄。  
**缺点**：N 张图 = N 次向 UM 要签名；断点续传差。  
**改造点**：`POST ticket` 入参含 `fileName/contentType/size`，返回 `uploadUrl` + `objectKey`。

### C. 继续经 UM 中转再由 UM 写 OSS

**优点**：客户端零 OSS 知识。  
**缺点**：**不满足**「直传 OSS、减压 UM」目标；与本次意图相反。仅作过渡或内网兜底。

### 不推荐

- 把现有 Material 的长期 Key 继续拷进 Urban secret「先直传再说」。  
- 客户端写死 Endpoint，仅从服务端拉 Secret（Endpoint 仍暴露运维面，且 Secret 下发等于仍持钥）。

## Material 主程序（顺带债）

主程序已直传但持长期钥。同一套 STS ticket 可后续收敛：

1. Material Platform 或专用签发服务发 STS。  
2. `OssUploadService` 改为 `IOssCredentialProvider`（本地 config 仅测试环境可选）。  
3. 删除客户端 `AliyunOss:Key/Secret`。

可与 Urban 同 change 或拆 `refactor-material-oss-sts`；Urban 优先不影响 Material Platform 契约。

---

## UM 读图策略（直传后必选其一）

| 策略 | 说明 |
|------|------|
| **按需从 OSS GetObject** | `FileService` 以 `OssObjectKey` 拉流；审批/政务同步改读流。AK 仅服务端。 |
| **直传后 UM 异步镜像到本地** | 仍占盘；实现简单但失去「不占 UM 存储」红利。 |
| **预签名 GET 给浏览器** | Web 审批直接链 OSS；政务推送仍需服务端取字节。 |

推荐默认：**服务端持钥 GetObject**；Web 大图可用短时预签名 GET。

压缩：今日压缩在 UM `FileService`。直传后可选：

- 客户端上传前本地压缩；或  
- OSS 图片处理 / 服务端拉取后再压（政务路径）。

## API 草图（record，非 tuple）

```csharp
// UM → Client
public record OssUploadTicketDto(
    string Endpoint,
    string BucketName,
    string ObjectKeyPrefix,
    string AccessKeyId,
    string AccessKeySecret,
    string SecurityToken,
    DateTimeOffset Expiration);

public record OssUploadCompleteItemDto(
    string ObjectKey,
    string FileName,
    AttachType AttachType,
    long? FileSizeBytes);

public record OssUploadCompleteResultDto(
    IReadOnlyList<Guid> AttachmentIds);
```

客户端禁止把 ticket 持久化到磁盘配置；仅内存缓存至过期。
