# 隔离现状与问题

以下源码路径均相对 MaterialMonospec 根目录；按上述提交基线阅读，后续源码变化需重新核对。事实摘录与质量判断分开表述。

## 1. 数据归属尚未收束

源码依据：

- `repos/MaterialClient/src/MaterialClient.Common.SolidWaste/Services/SolidWasteExtensionStore.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Services/SolidWasteService.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Entities/SolidWasteInfoExtensions.cs`

观察：Store 从内核实体的固废属性复制到扩展表；导出优先使用扩展快照，部分字段回退旧属性；回填仅插入缺失扩展行，不覆盖已有行。

INFERRED：当前属于双份数据的过渡结构，未完全完成字段所有权迁移。已有扩展行与内核属性不一致时，不存在统一的启动修复路径。不能据此断言所有实际写入路径都会产生不一致，仍需核对全部写入入口、事务和读取方。

应先明确扩展表是领域权威，还是可重建的只读投影。两者需要不同的写入与恢复规则。

## 2. 公共层仍包含产品业务

源码依据：

- `repos/MaterialClient/src/MaterialClient.Common/Services/ISolidWasteExtensionStore.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Services/WeighingMatchingService.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Services/SolidWasteService.cs`

观察：Common 仍包含固废接口、快照、导出服务与字段扩展；公共匹配服务直接调用固废 Store。独立产品程序集已存在，但产品语义仍分散在公共层。

INFERRED：程序集隔离强于领域隔离。继续增加产品可能增加公共流程中的专属依赖。是否需要抽象生命周期扩展点，应结合现有产品差异决定，不应仅为形式上的解耦新增复杂框架。

## 3. 宿主职责复用依赖源码链接

源码依据：

- `repos/MaterialClient/src/MaterialClient.SolidWaste/MaterialClient.SolidWaste.csproj`
- `repos/MaterialClient/src/MaterialClient.SolidWaste/MaterialClientSolidWasteModule.cs`
- `repos/MaterialClient/src/MaterialClient/MaterialClientModule.cs`

观察：固废项目链接标准宿主中的 StartupService、MinimalWebHostService 和 PollingBackgroundService 源码。两边各自维护配置与服务组合；标准宿主注册 StreetsConfig、SolidWasteTypeConfig，固废模块未见对应注册。后者是否被其他模块补齐及是否影响界面行为仍待核对。

INFERRED：源码链接短期避免复制，长期却依赖另一个可执行项目的内部布局。公共宿主基础设施放入稳定共享程序集更容易维护；产品配置仍应留给各宿主组合。

## 4. 身份和路径依赖可变全局状态

源码依据：

- `repos/MaterialClient/src/MaterialClient.Common/Hosting/HostProductIdentity.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Hosting/HostBootstrap.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Utils/PathManager.cs`

观察：产品身份、启动配置、数据根分别存于可变 static 状态，通过启动顺序建立一致性。

INFERRED：一进程一产品使这种做法具有现实可接受性，但不变量没有被类型完整表达。候选改进是一次初始化的宿主上下文，统一身份、路径和配置；不应把所有无 I/O 的辅助逻辑都注册成 DI 服务。

## 5. 已有合理边界

SolidWasteDbContext 不承载公共 Waybill、WeighingRecord 模型，扩展通过逻辑 ID 与唯一索引关联。扩展实体使用 Apply 方法维护自身状态。StandardDbContext 当前为空，主要提供产品迁移归属；是否值得保留这一对称结构，应由未来标准产品专属数据需求决定。

相关源码：`repos/MaterialClient/src/MaterialClient.Common.SolidWaste/EntityFrameworkCore/SolidWasteDbContext.cs`、`repos/MaterialClient/src/MaterialClient.Common.SolidWaste/Entities/`、`repos/MaterialClient/src/MaterialClient.Common.Standard/EntityFrameworkCore/StandardDbContext.cs`。
