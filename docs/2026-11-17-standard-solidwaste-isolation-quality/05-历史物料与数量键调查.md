# 历史 MaterialId 与 WaybillQuantity 调查

日期：2026-11-17。ACTIVE。历史源码和样本统计为 CONFIRMED，差异成因归纳为 INFERRED。仅调查设计，未修改代码或样本。

## 历史用途与退出过程

MaterialClient 历史提交 `06b2db6ef6a66eb28e77f5adafdead2fe7129b53`（refactor(solid-waste): remove MaterialId ExtraProperties usage）明确删除两项键常量与 SetSolidWasteMaterialInfo/PatchSolidWasteMaterialInfo 方法。

该提交之前，两方法把物料 ID 和运单数量写入 ExtraProperties。匹配流程把称重记录的旧物料键复制到运单；注释明确 SolidWaste 的 WaybillQuantity 约定为 GoodsWeight（自动派生），写入运单 OrderGoodsWeight。这不是已确认的独立合同计划数量。

同一提交将打印侧物料读取从旧键改为 waybill.MaterialId，取消匹配、编辑处的旧键维护。`48f87a53`（refactor(viewmodel): update SolidWasteWeighingDetailViewModel to use entity fields）将称重界面改读 record.Materials.FirstOrDefault()?.MaterialId，运单界面改读 waybill.MaterialId，删除旧数量键读取。相关修改亦可沿 `42ab3e66`、`b6224481` 集成历史追溯。

结论：两个键是已退出当前正常调用链的旧存储表示，而不是本轮隔离新引入的字段。所查历史 diff 没有对应的数据清理；样本仍保留旧值，与此一致。不能据此断言历史所有版本都没有其他迁移。

## MaterialId 的差异

运单旧键 2,217 行，199 行与正式列相等，2,018 行不同。主要组合：旧580→正式601共1,719行，旧579→601共130行，旧582→603共83行，旧581→602共50行，旧583→604共35行。

旧 ID 580、582、583 在样本 Materials 中已不存在；579、581 为软删除，601、602 仍存在。旧键与运单物料子表匹配163行，不匹配2,054行。称重记录旧键与 MaterialsJson 匹配328行，不匹配1,032行。

INFERRED：分布支持旧物料键在停止维护后滞留、正式物料发生调整的解释；不支持把旧键重新覆盖正式列。未追踪到所有物料重映射的原始写操作，不能断言每组 ID 都是同义替换或确认是谁修改。

建议：保持当前正式列/MaterialsJson 的业务权威，不把旧键作为迁移回填源覆盖它们。删除旧键前保留可追溯旧库或差异记录；若需要恢复旧物料展示，再单独研究映射，不能仅凭 ID 差异恢复。

## 对升级方案的修正

不建议为这两个旧键重新增加活跃的固废业务列，也不建议让它们进入新的四项字段迁移链。其旧业务用途已被正式字段接替。

可讨论的清理策略：保留不可变的升级前快照；导出差异清单及来源身份；正常业务维持正式字段权威；待明确允许清理历史缓存后按键删除。三条数量差异可作为人工裁决的小集合。离线历史证据保留与让旧键继续参与正常业务，是两个不同决定。

当前用户决定的目标仍是 ExtraProperties 仅保留净重显示标记。上述方案是达到目标时避免静默丢失历史信息的候选设计，不表示已获准丢弃这些旧值，也未执行清理。
