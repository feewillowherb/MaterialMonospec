# 01 缓存生命周期

> 源码行为标 `CONFIRMED`。第 3 节起是 2026-11-11 讨论记下的设计，标 `PENDING_VALIDATION`。

## 1. 现行上传门闩

稳定边沿在 [`AttendedWeighingService`](../../repos/MaterialClient/src/MaterialClient.Common/Services/AttendedWeighing/AttendedWeighingService.cs) 建本地称重记录并抓拍。Urban 扩展此时为 `SyncStatus.WeighingInProgress`。

进入 `OffScale` 时调用 [`WeighingRecordService.RewriteAndResetCycleAsync`](../../repos/MaterialClient/src/MaterialClient.Common/Services/AttendedWeighing/WeighingRecordService.cs)：

1. 按配置重写车牌  
2. [`UrbanWeighingRecordSideEffects.FinalizeWeighingCycleAsync`](../../repos/MaterialClient/src/MaterialClient.Common.Urban/Services/UrbanWeighingRecordSideEffects.cs) 重算异常，并把 `WeighingInProgress` 升为 `Pending`  
3. `IPlateNumberService.ClearCache()`  
4. `WeighingStateManager.ResetCycle()`

三条进 `OffScale` 的边沿都走这条收口：未稳就离开、稳定后异常离开、`WaitingForDeparture` 正常下磅。

[`WeighingStreamPipeline.CreateStatusStream`](../../repos/MaterialClient/src/MaterialClient.Common/Services/AttendedWeighing/WeighingStreamPipeline.cs) 里，`weight < MinWeightThreshold` 的一次采样就把状态收到 `OffScale`。已有 `recordId` 且重量仍高于阈值时，状态被压在 `WaitingForDeparture`，不会因再次稳定再建一单。

[`WeightStabilityEvaluator`](../../repos/MaterialClient/src/MaterialClient.Common/Services/AttendedWeighing/WeightStabilityEvaluator.cs) 要求窗口内每个点都高于阈值，且极差 ≤ `WeightStabilityThreshold * 2`（默认 0.05 吨的两倍，即 0.1 吨）。默认窗口 3 秒。

因此：重复稳定本身在「单还在、且 `weight > MinWeightThreshold`」时不会开第二张单。第二张单出现在现行逻辑已经进入 `OffScale`、周期被清掉之后又一次稳定。`MinWeightThreshold` 来自 `WeighingConfiguration`，可配置，默认 0.5 吨。

## 2. 缓存目的

Human，2026-11-11：缓存用来解决 busy 模式下相同车牌重复触发稳定，导致已经生成或已经上传的地磅数据再产生一次。

两种都算已经产生：

| 状态 | 含义 |
|------|------|
| 已生成称重记录 | 这一笔已经有 `WeighingRecord`。此时可以仍是 `WeighingInProgress` |
| 已上传 | 这一笔已经升到 `Pending` 或更后的同步状态 |

同一张牌再次进入稳定，若再插一条称重记录或再上传一次，就是要挡住的重复。缓存键是这一笔上的车牌。另一张牌不由这个缓存挡住。

## 3. 两份缓存

| | 选牌缓存 | 已产生缓存 |
|--|----------|------------|
| 现状 | 已有。`PlateNumberService` 按牌累计次数、时间、颜色 | 没有 |
| 用途 | 这一轮投票选出写进称重单的牌 | 记住已经生成或已经上传的那张车牌，挡住它再次稳定后又产生新数据 |
| 写入 | 每次地磅车牌推送 | 开关打开且称重记录生成时写入该牌。之后升到 `Pending` 仍留着这张牌 |
| 现行清空 | 下磅收口立刻 `ClearCache()` | — |
| 设计清空 | 仍跟投票轮次走 | 与现行进入 `OffScale` 同一边沿 |

选牌缓存的 20 分钟高优先级窗口、`EnableLatestPlateNumber`、`LockedAt` 都回答「缓存里哪张票多」。它们不记录「这一笔称重记录已经生成或已经上传」。两份清空不要放进同一次调用。

## 4. 已产生缓存何时清

讨论结论（Human，2026-11-11）：不另写一套离开条件。已产生缓存在现行进入 `OffScale` 的同一边沿清除，并清掉 busy 模式里尚未进入 `OffScale` 的全部缓存条目。已经写入的称重记录和已经上传的数据不删。

现行条件在 [`WeighingStreamPipeline.CreateStatusStream`](../../repos/MaterialClient/src/MaterialClient.Common/Services/AttendedWeighing/WeighingStreamPipeline.cs)：`WaitingForStability`、`WeightStabilized`、`WaitingForDeparture` 在 `weight < config.MinWeightThreshold` 时进入 `OffScale`。`AttendedWeighingService` 对这三条边沿调用 `RewriteAndResetCycleAsync`。`MinWeightThreshold` 可配置，默认 0.5 吨。等于该阈值时，现行 `switch` 不进入 `OffScale`。这里不看 `WeightStabilityEvaluator`，本夹不另加稳定或停留时间。

```text
称重记录生成
    → 写入已产生缓存
随后升到 Pending
    → 同一笔继续留在缓存里
weight > MinWeightThreshold，同一车牌再次稳定
    → 命中，不再生成称重记录，不再上传
现行逻辑进入 OffScale（weight < MinWeightThreshold）
    → 立即清除尚未进入 OffScale 期间缓存的全部条目
清除之后重量又满足上磅条件并稳定
    → 允许生成新的一笔
自称重记录生成起满 15 分钟，仍未进入 OffScale
    → 兜底清除。再次稳定可以再产生一笔，这次重复接受
```

读数在 `MinWeightThreshold` 附近抖一下，现行逻辑会进入 `OffScale` 并清缓存；重量再次高于阈值并稳定时，同一车牌可以再生成一笔。这是沿用现行 `OffScale` 的结果。缓存挡住的是尚未进入 `OffScale`、且 `weight > MinWeightThreshold` 时，同一车牌再次稳定。

2 分钟不能当清除时间：一般过磅可以到 10 分钟，2 分钟时车往往还在磅上，会把同一笔再产生一次。

一般过磅 2–10 分钟（Human，2026-11-11）是车停在磅上的时间。先前只把它当成这段时长，兜底清除没有写上：重量若一直没有让现行逻辑进入 `OffScale`，缓存会留到进程结束。

Human 同日补充：能接受 **15 分钟**间隔之后再上传或再生成重复的地磅数据。兜底自称重记录生成起满 15 分钟。这个间隔长于一般过磅的 2–10 分钟。时钟不因后来的再次稳定而重新计时，否则 busy 里反复稳定会把兜底一直往后推。15 分钟到了就清除；下一次稳定可以再生成、再上传。2 分钟仍不作为清除时间。

两条清除互不替代。现行进入 `OffScale` 时立刻清除，下一趟不用再等满 15 分钟。15 分钟只覆盖「重量一直没有使现行逻辑进入 `OffScale`」的情况。

## 5. 命中时做什么

命中已产生缓存时，这一笔不再产生：

- 不创建新的 `WeighingRecord`
- 不把已有扩展再升一次 `Pending`
- 不调用上传队列

只挡上传、仍建一张新的 `WeighingInProgress` 单，本身就是重复产生。命中点放在建单之前。

命中条件是缓存里的那张车牌再次稳定。没有写入车牌时对不上，不由这个缓存挡住。换成另一张牌也不命中；换牌之后要不要单独成单，仍见 2026-11-10 那夹。

## 6. 配置

开关只给 Urban 宿主。界面可见性对齐现有 `ShowUrbanAnomalyDetectionSettings`（Urban 宿主才显示）。默认关。

关闭时保持第 1 节：下磅收口才升 `Pending`。已产生缓存不写入、不参与判断。

打开时：本段还没有称重记录时，第一次 `WeightStabilized` 生成记录并写入已产生缓存，再走与 `FinalizeWeighingCycleAsync` 相同的上传准备（异常重算 + `WeighingInProgress` → `Pending`）。上传完成后缓存仍保留这张车牌。`weight > MinWeightThreshold` 时，同一车牌再次稳定命中缓存，不再生成、不再上传。选牌缓存不要在这次上传时清掉，下磅投票仍可能用到它。

`EnableMatchOnStable` 继续只发运单匹配。Urban 策略跳过匹配。新开关不复用这个布尔值。

## 7. 边界

| 情况 | 结果 |
|------|------|
| 同一车牌已生成称重记录，`weight > MinWeightThreshold`，再次稳定 | 不再生成新数据，也不再上传 |
| 同一车牌已经升到 `Pending`，再次稳定 | 这张牌留在缓存里，不再产生 |
| 现行逻辑进入 `OffScale`（`weight < MinWeightThreshold`） | 立即清除尚未进入 `OffScale` 期间缓存的全部条目。已生成的称重记录和已上传数据仍在 |
| 进入 `OffScale` 之后又高于 `MinWeightThreshold` 并稳定 | 允许生成新的一笔 |
| 自称重记录生成起满 15 分钟，仍未进入 `OffScale` | 兜底清除。再次稳定可以再上传或再生成，这次重复接受 |
| 已生成记录时还没有牌，稍后又稳定 | 缓存对不上车牌，不由它挡住 |
| 已缓存车牌 A，稳定时来的是车牌 B | 不命中。B 不由这个缓存挡住 |
| 软件重启 | 忽略。缓存只在内存，不落盘 |
| 前车未确认下磅、后车另一牌要单独成单 | 不属于这个缓存的目的。那是 2026-11-10 里「新稳态再认一辆」的另一条缓解，本夹不采用 |

道闸仍按现行状态边沿：`WaitingForDeparture` 开出口，`OffScale` 清会话。本夹不改道闸。
