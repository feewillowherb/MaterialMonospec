# 00 调研总览 — Urban 稳定后上传与已产生缓存

> 生命周期：`ACTIVE`。  
> 源码对照日期：2026-11-11。设计来自同日讨论，状态 `PENDING_VALIDATION`。  
> 这不是 OpenSpec change，也不是 Human `APPROVED`，不能当授权改代码。

## 1. 诉求

本夹是 [`docs/2026-11-10-urban-busy-weighing-upload-on-stable/`](../2026-11-10-urban-busy-weighing-upload-on-stable/00-调研总览.md) 的另一种缓解（Human 确认，2026-11-11）。那夹的研究状态仍是挂起，本夹不把它改写成已收束。

本夹要解决的 busy 情况：同一车牌在地磅上重复触发稳定，而这一笔已经生成过称重记录或已经上传，却又产生新数据。

本夹的缓解更窄：

| | 2026-11-10 那夹 | 本夹 |
|--|-----------------|------|
| 稳定后升 `Pending` | 要 | 要。Urban 配置，默认关 |
| 同一段在磅再稳定 | 一次一传，不再建单 | 同样不再建单 |
| 闩何时释放 | 见到空磅，或重量相对上一笔已上传稳态出现新稳态 | 两条：现行进入 `OffScale`（`weight < MinWeightThreshold`）时清除全部缓存条目；或自称重记录生成起满 15 分钟。不另写离开条件 |
| 同一车牌再次稳定 | 讨论过一次一传 | 15 分钟内且 `weight > MinWeightThreshold` 时，不再产生新数据 |
| 换一张牌再稳定 | 还在讨论能否认成下一辆 | 不由这个缓存挡住。缓存只认已经产生那一笔的车牌 |

缓存的目的（Human，2026-11-11）：解决 busy 模式下相同车牌重复触发稳定、导致再产生新数据。记下的是已经生成称重记录或已经上传的那张车牌。`weight > MinWeightThreshold` 时，这张牌再次稳定不再生成、不再上传。清除跟现行进入 `OffScale` 的条件走：`weight < WeighingConfiguration.MinWeightThreshold`。该值可配置，默认 0.5 吨。满 15 分钟也可兜底清除，之后的重复接受。

## 3. 结论

| # | 结论 | 状态 |
|---|------|------|
| C1 | 稳定时建单并抓拍。`WeighingInProgress` → `Pending` 发生在进入 `OffScale` 后的 `FinalizeWeighingCycleAsync` | `CONFIRMED` |
| C2 | `OffScale` 由单次采样触发：`weight < MinWeightThreshold`（默认 0.5 吨）。稳定要满窗，默认 `StabilityWindowMs` 3000、间隔 200ms | `CONFIRMED` |

| C5 | 已产生缓存与选牌缓存分开。称重记录一生成就写入当时的车牌；已上传的同一张牌继续留在缓存里 | `PENDING_VALIDATION` |
| C6 | 不另写离开条件。已产生缓存在现行进入 `OffScale` 时清除全部条目。条件是 `weight < WeighingConfiguration.MinWeightThreshold`（可配置，默认 0.5 吨），与 `WeighingStreamPipeline` 相同。已写入的称重记录和已上传数据不删 | `CONFIRMED`（Human，2026-11-11） |
| C7 | 缓存仍有效且 `weight > MinWeightThreshold` 时，同一车牌再次稳定不再生成新的称重记录，也不再上传 | `PENDING_VALIDATION` |
| C8 | 现行进入 `OffScale` 并清空缓存之后，再次上磅并稳定，允许生成新的一笔 | `PENDING_VALIDATION` |

| C10 | 本夹是 2026-11-10 繁忙过磅的另一种缓解：稳定后上传，并用缓存挡住同一车牌重复稳定后再产生新数据 | `CONFIRMED`（Human，2026-11-11） |
| C11 | 缓存的目的是解决 busy 模式下相同车牌重复触发稳定，导致已经生成或已经上传的数据再产生一次 | `CONFIRMED`（Human，2026-11-11） |
| C12 | 一般车辆过磅时间为 2–10 分钟（Human，2026-11-11）。2 分钟不作为清除时间，避免一次正常过磅中途再产生 | `CONFIRMED`（Human 时长） |
