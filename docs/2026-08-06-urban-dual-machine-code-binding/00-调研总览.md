# Urban 双机器码绑定 — 调研总览

**日期**: 2026-08-06  
**范围**: MaterialClient.Urban 项目授权（ProductCode 5001）由「1 项目 ↔ 1 机器码」扩展为「1 项目 ↔ 最多 2 台机器码」  
**结论摘要**: **可落地，但不是客户端局部改动**；必须联动 BasePlatform + UrbanManagement + MaterialClient，并改写现有 F4「后激活踢掉前机」语义。工作量中高（约 8–15 人天）。

## 已确认产品决策

| 项 | 结论 |
|----|------|
| 目标场景 | **双机同时在线称重**（非主备切换） |
| 技术方案 | 项目级机器码**允许名单（最多 2）**；验签由「严格相等」改为「∈ 名单」；每台 JWT 仍只含本机 `machineCode` |
| 不采纳 | 维持单权威覆盖写；仅改客户端；逗号拼接塞单字段 |

## 一句话现状

激活时把本机机器码写入 `JC_ProductAuthority.MachineCode` 与 `GovProject.MachineCode`（覆盖写）；JWT 内嵌单一 `machineCode` claim；服务端 F4 与客户端 `StaticLicenseChecker` 均按**严格相等**校验。第二台机激活 = 第一台机被吊销——与「同时在线」冲突，必须改。

## 建议下一步

1. 再定 2 个运营规则（写入 proposal 前）：满 2 台后再激活如何处理；谁可解绑。  
2. 与 BasePlatform 确认存储形态（第二字段 vs 子表）与目录 API 兼容。  
3. 主仓库开 OpenSpec：`openspec create add-urban-dual-machine-code`（或同等命名）。
