# Urban 双机器码绑定 — 调研总览

**日期**: 2026-08-06  
**范围**: MaterialClient.Urban 项目授权（ProductCode 5001）由「1 项目 ↔ 1 机器码」扩展为「1 项目 ↔ 最多 2 台机器码」  
**结论摘要**: **可落地，但不是客户端局部改动**；必须联动 BasePlatform + UrbanManagement + MaterialClient，并改写现有 F4「后激活踢掉前机」语义。工作量中高（约 8–15 人天）。

## 已确认产品决策

| 项 | 结论 |
|----|------|
| 目标场景 | **双机同时在线称重**（非主备切换） |
| 槽位模型 | 项目级 **设备1 / 设备2** 两槽；验签由「严格相等」改为「∈ {槽1, 槽2}」；每台 JWT 仍只含本机 `machineCode` |
| 写入/换机 | **生成激活码时选择设备1或设备2**；激活写入对应槽；槽已占用则 **覆盖该槽**；另一槽不动 |
| AccessCode / AuthEndTime | **两槽共享**同一套项目 `AccessCode` 与 `AuthEndTime` |
| 解绑 / 清空 | **不做**；换机仅通过「发对应槽位激活码 → 覆盖」 |
| 不采纳 | 维持单权威全局覆盖；仅改客户端；逗号拼接塞单字段；独立解绑/清空功能 |

## 一句话现状

激活时把本机机器码写入 `JC_ProductAuthority.MachineCode` 与 `GovProject.MachineCode`（覆盖写）；JWT 内嵌单一 `machineCode` claim；服务端 F4 与客户端 `StaticLicenseChecker` 均按**严格相等**校验。第二台机激活 = 第一台机被吊销——与「同时在线」冲突，必须改。

## 建议下一步

1. 与 BasePlatform 确认存储形态（`MachineCode` + `MachineCode2` vs 子表）与目录 API 兼容。  
2. 主仓库开 OpenSpec：`openspec create add-urban-dual-machine-code`（或同等命名）。
