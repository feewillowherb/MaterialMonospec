# 01 — 指导哲学

Pipeline 是 **Agent 的可重复作业系统**，不是聊天记录，也不是测试框架替代品。

下面 **P1–P12** 是生成与执行的底线；**P13–P18** 从图模型补强（Goal 互斥、Socket、隔离、成文粒度）。场景可变，标准不可变。

---

## 我们相信

### P1 工件先于动作（Artifacts Before Action）

没有落盘的 `pipeline.md` + `config.yaml`，就没有「执行」。

即兴操作（打开浏览器、连库、改文件）只允许出现在**生成阶段的澄清**，不允许冒充一次 run。  
理由：没有工件就无法重跑、无法 diff、无法把证据挂到变更上。

### P2 生成与执行分离（Split Generate and Run）

| 阶段 | 职责 | 禁止 |
|------|------|------|
| **Generate** | 问清意图 → 分类 family → 写工件 | 默认不跑副作用（浏览器登录、写库、调生产） |
| **Run** | 读工件 → 走状态机 → 采证 → 停在人闸 | 不改业务代码；不发明缺失配置 |

用户明确说「生成并执行」时，仍是**两段式**：先写完工件，再进入 run。不要混成一段无法复现的超长对话。

这与规范工作流同构：propose 产出变更文件夹，apply 按任务执行。

### P3 场景入、族出（Scenario In, Family Out）

用户给的是**场景**（「我要确认列表页有数据」「我要把 CSV 写进表」）。  
AI 输出的是某个 **family 的实例**，不是一次性脚本。

Family 是有限集合（见 `02`）。新场景优先**归入已有族**；只有现有族的状态机、证据包、密钥形状都装不下时，才立新族。

立新族的代价：新模板 + 新生成/执行约定 + 新失败策略。不要因为字段不同就立新族。

### P4 三层持久化（Commit / Secret / Run）

| 层 | 典型文件 | Git | 可变性 |
|----|----------|-----|--------|
| **Commit** | `pipeline.md`、`config.yaml`、`secrets.example.yaml`、`acceptance.md` 模板 | 提交 | 随意图缓慢变 |
| **Secret** | `secrets.local.yaml` | **禁止提交** | 人本机 |
| **Run** | `runs/<timestamp>/` | **默认不提交** | 每次全新目录，禁止覆盖 |

三条一起违反任意一条，pipeline 就不再可协作：要么泄密，要么无法重跑，要么仓库被二进制/日志撑爆。

### P5 证据优于神谕（Evidence Over Oracle）

Agent **不是**业务正确性的最终判定器。

| 级别 | 含义 | 谁判 |
|------|------|------|
| L0 可达 | 步骤跑通、目标可访问 | Agent |
| L1 非空壳 | 无配置中的失败占位（如「加载失败」） | Agent 提示 |
| L2 契约可见 | 配置的期望文本/字段/计数出现 | Agent 提示 |
| L3 业务正确 | 对得上真实世界 | **用户** |

Run 结束状态只能是「等待验收」，直到用户回复 pass / fail。  
Agent 可以写自评，**不得**把 pipeline 标为验收通过。

### P6 状态机可执行（Executable State Machine）

`pipeline.md` 必须能被 Agent 当成状态机跑，而不是散文备忘。

每个状态写清：输入、动作、成功判据、失败策略（停 / 继续 / 重试上限）、产出路径。  
「尽量」「看看」「适当等待」不是状态；`readySelector` 或明确超时才是。

### P7 显式非目标（Named Non-Goals）

每条 pipeline 必须写「不做」。至少覆盖：

- 不修改业务代码（除非该 family 的目标就是受控写入，且只写声明的目标）  
- 不提交 secrets / runs  
- 不替代规范文档与自动化测试  
- 不把 L3 自称通过  

非目标是范围保护。没有它，执行 Agent 会「顺便修一下」。

### P8 人闸不可跳（Human Gates）

下列情况必须停下来问人，禁止猜测：

- 缺失密钥、连接串、路径  
- 目标标识未知（URL、表名、环境）且无法从已提交 config 读取  
- 破坏性动作（写库、删除、对生产）前的确认——除非 config 已显式 `confirmDestructive: skipped` 且用户在生成时同意  
- 最终验收  

人闸是安全边界，不是礼貌。

### P9 一次一跑、产物不可变（Immutable Runs）

每次执行新建 `runs/<yyyy-MM-ddTHHmmss>/`。  
禁止把新截图覆盖进旧目录「省事」。对比靠两份 run，不靠一份被改写的文件。

### P10 缺证必声明（No Silent Skip）

证据项若启用却采不到：仍要写对应文件，标明 `source: missing` / `count: 0` 与已尝试路径。  
静默跳过会让报告看起来「一切正常」。缺证比假证更危险的唯一情况，是报告假装有证。

### P11 不问不编造（Ask, Don't Invent）

禁止编造：路由、表名、字段、选择器、账号、环境地址。  
生成阶段缺字段 → Ask。执行阶段 config 无效 → 停并报告，不「智能补全」一个可能毁掉环境的目标。

### P12 管道不是规范（Pipeline ≠ Spec）

Pipeline 证明「某次在某环境上看到了什么 / 做了什么」。  
规范（OpenSpec / 设计文档）才是「系统应该怎样」。

- 修产品行为 → 走变更提案，不塞进 pipeline runner  
- 引用证据 → change 里链到某次 `runs/` 或拷贝到 docs，不让 pipeline 目录成为真相源  
- **现行「如何再验」不得只活在调研夹**；`docs/` 指向 `pipelines/`，不能当协议唯一落点

## 从图模型补强（P13–P18）

细节与成文骨架见 `06`。此处只定判断标准。

### P13 一槽一现行图（One Active Graph per Goal）

同一 Goal（「如何证明 X 已可验收」）最多一条 `active` Graph。换方案 = 旧图 `retired` 并指向继任，不是图内并行两套、也不是同一对象上混跑。

### P14 交接靠 Socket（Sockets Over Prose）

上下游用 `<family>-<state>` 交接，并声明 Cook 是 `in-place` 还是 `new-object`。只写「然后做下一步」无法移植、无法 Switch、无法判断该不该重跑全链。

### P15 认对象靠 Context（Bind, Don't Guess Names）

Bind 优先级：标记 → 结构指纹 → 显式指针 → 显示名（禁止当唯一键）。歧义则停。这是 P11 在「操作对象」上的特化。

### P16 成文看边界（Split on Boundary, Not Bulk）

默认成文单位是 Subnet / 一条 slug 的 Cook 链。满足 ≥2 条硬边界（可复用、稳定 Socket、独立 Gate、独立 Invoke、互斥可替换、母文已糊）才拆。禁止一句话一个文档 Node；也禁止该拆不拆。

### P17 脚本隔离至落地（Isolate Until Landed）

管线脚本默认放 `pipelines/<slug>/scripts/`（或等价隔离区），标 `experimental`。Invoke 可挂载 ≠ 产品功能。Gate 通过后须经 OpenSpec **引用该 Graph** 才迁入业务代码。

### P18 同态微调须再闸（Patch Then Re-Gate）

已达 Output socket 后允许局部补丁，但必须再 Validate + Gate。合同 bug 回写 Invoke；特例不污染主 Cook；上游错态则回滚重走，禁止叠微调。

## 我们拒绝

| 反模式 | 为什么坏 | 正确做法 |
|--------|----------|----------|
| 聊天即流水线 | 不可重跑、不可审查 | 先生成 `pipelines/<slug>/` |
| 单命令包办生成+执行且无工件 | 失败后无法从同一点重来 | 两段式；工件是断点 |
| 密码写进 `pipeline.md` | 泄密 | 只进 `secrets.local.yaml` 或会话 |
| Agent 宣布「验收通过」 | 假阳性 | 人闸 |
| 覆盖上次 run | 丢失对照 | 时间戳新目录 |
| 采集失败当没发生 | 误导 | 写 missing 文件 |
| 每条需求一个新框架 | 无法复用命令 | 归入 family |
| runner 里修业务代码 | 范围爆炸、无法回滚到规范 | 非目标 + 另开 change |
| 无限重试 | 打挂验证码/接口/库 | 显式上限（默认 2） |
| 用 CI 像素对比冒充 MVP | 错工具；联调需要人眼+证据 | 先 Agent 采证；稳定后再抽自动化 |
| 协议只活在日期调研夹 | 无法独立 cook | 固化进 `pipelines/`，调研只深链 |
| 同一 Goal 两套 active | 混跑、无法指认现行 | 互斥；旧标 retired |
| 只有步骤无 Socket | 无法接线 / 无法判断重跑范围 | Input/Output + Cook 语义 |
| 显示名当唯一键 | 多副本绑错对象 | Context 优先级 |
| 能跑就进业务包 | 实验态冒充合同 | 隔离 + OpenSpec 引用 Graph |
| 一句话一个 md Node | 碎片无法维护 | 默认 Subnet；≥2 条边界才拆 |

## 与相邻系统的边界

```
调研 docs/YYYY-MM-DD-*     未定论、失败史、会话     可指向 pipelines，不是协议唯一落点
        │  定论后提升
        ▼
AI Pipeline Graph          现行「如何再验」         pipelines/<slug>/
        │  Gate 通过后引用 Graph
        ▼
规范系统（OpenSpec）       描述「应该是什么」       变更提案 / specs
        │  实现归档
        ▼
业务代码                   产品合同                 repos/ 核心包（非隔离脚本）
        │
        ▼
CI / 无人值守              「是否绿」               测试工程（稳定后可抽）
```

`runs/` 是某次 cook 的事实记录，挂在 Graph 下，仍不是产品 SHALL。  
成功标准：同一 slug 能重跑、Socket 能交接、Gate 由人签、密钥不进 git、脚本未冒充正式功能。

## 设计伦理（短）

- **最小权限**：secrets 只含本 pipeline 需要的键；报告脱敏 token / cookie / 连接串。  
- **默认非破坏**：读路径（observe / probe）默认；写路径（ingest）必须 `dryRun` 可开、失败可回滚或明确不可回滚。  
- **本地默认**：生成与执行默认对准本机/开发环境；指向共享或生产时必须在 config 里显式 `environment` 并在人闸确认。  
- **可解释**：报告必须能让未参与本次对话的人看懂「跑了什么、缺什么、等谁判」。
