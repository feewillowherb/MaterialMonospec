# 03 — 生成协议

本章是 **AI 接到「按场景生成 pipeline」时的操作说明书**。按序执行。缺字段就 Ask，不要编造。

哲学冲突时服从 `01`。字段名服从 `02`。填空形状见 `05`。

---

## 0. 护栏（全程）

- 不把真实密钥写入可提交文件。  
- 默认不执行副作用；用户说「生成并执行」则**先写完工件再 run**。  
- `pipelines/<slug>/` 已存在 → Ask：覆盖 / 换 slug / 取消。  
- 目标系统非 `local` → 生成结束前确认 environment。  
- 不修改业务仓库代码来「让 pipeline 更好跑」，除非用户单独授权。配套脚本只进 `pipelines/<slug>/scripts/`，标 `experimental`。  
- 同一 Goal 已有 `active` Graph → Ask：retired 旧图并替换 / 另开 Goal / 取消。  
- 成文粒度服从 `06`：不要把口述碎成一句话一个文件。

---

## 1. 收场景（Intake）

从用户话语中抽取；缺失则问，一次问齐缺口，避免连环十问。

### 1.1 必问（没有就不能写 config）

| # | 字段 | 问法（可意译） |
|---|------|----------------|
| 1 | 目的一句话 / Goal | 跑完要证明或完成什么？这是哪一个互斥槽？ |
| 2 | Family | 若用户已指定则用；否则你分类后**复述确认** |
| 3 | Slug | 用户给或从目的派生 kebab-case，派生则确认 |
| 4 | Target / Context | 系统怎么指到（指针）；有何指纹/标记；歧义怎么办 |
| 5 | 成功长什么样 | 至少 L0；有则收集 L1/L2；Socket 起止态 |
| 6 | 是否替换旧 Graph | 同 Goal 已有 active 时必须问 |

### 1.2 按族追加

| Family | 追加必问 |
|--------|----------|
| observe | 目标列表（id + 名称 + 路径）、是否要登录、证据开关 |
| ingest | 源文件、目标表/集合、匹配键、是否 dryRun |
| probe | endpoint 列表、方法、期望状态码 |
| reconcile | 左侧源、右侧源、对齐键 |
| transform | 输入路径、输出路径、转换规则指针 |

### 1.3 密钥

只问本族需要的键。提供则写入 `secrets.local.yaml` 并提醒勿提交；拒绝落盘则在摘要里写「run 时再问」。

### 1.4 不要问（有默认）

- run 目录命名（永远时间戳）  
- 是否覆盖旧 run（永远不覆盖）  
- L3 是否由 Agent 判定（永远否）  
- 是否把 runs 提交 git（默认否）

---

## 2. 分类并复述

用一段固定结构复述，得到用户点头（或用户已写明族）：

```text
Family: <id>
Goal: <互斥槽一句>
Graph slug: <kebab>
Status: active（旧图：retired → 本 slug / 无）
Sockets: <start> → <end>  Cook: in-place | new-object
非目标: <2–5 条>
Context: <指针/指纹；歧义则停>
副作用: 只读 | 写本地 | 写系统（dryRun=）
Invoke: 命令 / pipelines/<slug>/scripts（experimental）
人闸: 密钥 / 破坏性确认 / 验收
```

分类犹豫时：选**副作用更小**的族，把多出来的采集做成可选 collector。

---

## 3. 填写 Brief（逻辑卡）

在写文件前，先在内部（或写入 `design-brief.md`）填完这张卡。未填完禁止脚手架。

```yaml
id: ""                       # slug
family: observe              # 五选一
goal: ""                     # 互斥槽
status: active
purpose: ""
sockets:
  start: ""
  end: ""
cook: new-object             # in-place | new-object
nonGoals:
  - 不修改业务代码
  - 不提交 secrets/runs
  - 不替代规范与 CI
  - Agent 不宣布 L3 通过
environment: local           # local | shared | production
stopOnError: false
target: {}                   # 非机密
secretsKeys: []              # 只列键名
steps: []                    # 观察对象 / 导入映射 / 探测点…
collectors:
  - id: ""
    required: true
    when: always
humanGates:
  - missing-secrets
  - acceptance
failurePolicy:
  retries: 2
  stopOnError: false
adapters: {}                 # 如 auth.mode
```

`04` 有两张填好的 sample。生成时复制结构，换值，不要复制 sample 的假 URL 到真实项目——真实值来自用户。

---

## 4. 脚手架

1. 选择母版：`pipelines/_templates/<family>/` 若存在，否则 `pipelines/_template/`，再否则按 `02` 的最小文件集**新建**并在摘要中声明「本次从本体合成，建议回写为该族模板」。  
2. 创建 `pipelines/<slug>/`。  
3. 复制 `pipeline.md`、`config.yaml`、`secrets.example.yaml`、`acceptance.md`。  
4. 替换占位符：`{{slug}}`、`{{baseUrl}}`、sample 步骤。  
5. 按 brief 写入 family 块与 collectors。  
6. 可选：把 brief 存为 `design-brief.md`（可提交，不含密钥）。  
7. 若用户给了密钥：写 `secrets.local.yaml`（gitignore）。  
8. 不要创建真实 `runs/` 内容；可选 `runs/.gitkeep`。  
9. 若有隔离脚本：只写在 `pipelines/<slug>/scripts/`，并在 runbook 标明 `experimental`。  
10. `pipeline.md` 用 mermaid（或声明 ASCII 降级）画出 Cook chain，边上标 Socket。  
11. 更新 `pipelines/README.md` 的 Goal → Graph 索引；替换旧图时把旧行移到 Retired。

`pipeline.md` 的状态机必须与 `config.yaml` 的步骤一一对应。禁止 runbook 写 5 步、config 只有 2 个 target。上下游 Socket 对不齐则禁止假装可 Wire。

---

## 5. 生成命令要不要新建

| 情况 | 行动 |
|------|------|
| 已有 `/gen-<family>-pipeline` 且族匹配 | 遵守该命令；本协议作补全 |
| 新族或通用入口 | 可同时草拟 `.cursor/commands/gen-<family>-pipeline.md` 与 `run-...`，**仅当用户要落地命令时才写文件** |
| 用户只要这一条实例 | 只生成 `pipelines/<slug>/`，不扩散改命令 |

命令正文应包含：护栏、必问字段、模板路径、禁止项。细则放模板，不放命令（命令膨胀后再抽 skill）。

---

## 6. 摘要（生成结束必给）

告诉用户：

- slug、family、路径列表  
- 步骤/目标条数  
- secrets 是否落盘  
- 必做证据项  
- 下一步：`/run-<family>-pipeline <slug>` 或等价说明  
- 问：**是否立即执行？**

未经询问不要开始 run。

---

## 7. 若用户说立即执行

1. 确认工件已完整（config 无 `{{` 占位符，密钥已解决或将在 run 人闸询问）。  
2. 切换到该族的 run 协议：通用骨架见 `02` §5，特化见实例 `pipeline.md`。  
3. 新建时间戳 run 目录。  
4. 先装 collector，再 execute。  
5. 写 `report.md`，状态为等待验收。  
6. 问 pass / fail；得到回复前不改 acceptance 为通过。

---

## 8. 质量门（生成后自检）

- [ ] slug 与 `config.id` 一致  
- [ ] family 合法  
- [ ] 非目标已写  
- [ ] 无可提交文件中的密码/连接串  
- [ ] 每个 required collector 在 runbook 里有对应步骤与输出路径  
- [ ] 人闸包含验收  
- [ ] ingest/transform 写系统时有 dryRun 或显式「不可 dryRun + 已确认」  
- [ ] 未编造用户没给的路由/表名  
- [ ] Goal / sockets / cook 语义已写；同 Goal 无第二个 active  
- [ ] Context 未把显示名当唯一键  
- [ ] 拆文件满足 `06` ≥2 条边界（或明确不拆）  
- [ ] 脚本未写入业务包  

任一项失败：补问或改文件，不要把半成品当完成。
