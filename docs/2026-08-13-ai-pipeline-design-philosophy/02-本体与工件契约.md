# 02 — 本体与工件契约

生成任何 pipeline 之前，用本章的词。不要另造同义词（例如把 run 叫 job、把 family 叫 type），除非在 brief 里声明别名。

---

## 1. 词汇

| 词 | 含义 |
|----|------|
| **Scenario** | 用户用自然语言描述的需求 |
| **Family** | 有限的管道种类；决定状态机骨架、默认证据、密钥形状 |
| **Slug** | kebab-case、字母开头的实例 id，等于目录名 |
| **Brief** | 生成阶段填写的意图卡（逻辑模型；可只存在于对话，建议写入 `design-brief.md`） |
| **Artifact** | `pipelines/<slug>/` 下可重复文件 |
| **Adapter** | family 内可替换的步骤实现（如 auth 方式、取证源优先级） |
| **Run** | 一次不可变执行；目录 `runs/<timestamp>/` |
| **Evidence** | run 内证明「发生过什么」的文件 |
| **Human gate** | 必须等人的状态 |
| **Judge** | L3 判定者，默认是用户 |
| **Goal** | 同一终态问题的互斥槽；每槽最多一条 active Graph |
| **Graph** | 现行验收网络；实例 = `pipelines/<slug>/`，人读投影 = `pipeline.md` |
| **Node** | Bind / Cook / Validate / Gate / Switch |
| **Subnet** | 默认可移植的复合 Node（模板或可引用 slug） |
| **Socket** | 交接态 `<family>-<state>` |
| **Wire** | 上一段 Output = 下一段 Input |
| **Context** | 如何 Bind 操作对象（标记 > 指纹 > 指针 > 显示名） |
| **Cook** | 变换或产数据；`in-place` \| `new-object` |
| **Invoke** | 触发方式（命令 / 脚本 / API） |
| **Status** | `active` \| `retired` |

图模型细则见 `06`。生成实例时 **family + Graph 词汇一起写**：family 决定证据与密钥形状；Graph 决定互斥、交接与成文。

---

## 2. Family 分类（先归类，再实例化）

场景按**主意图**归入一族。主意图只能有一个；次要采集用 config 开关，不另立族。

| Family | 主意图 | 典型副作用 | 默认证据 | 密钥形状（sample） |
|--------|--------|------------|----------|-------------------|
| **observe** | 看见表面是否健康 | 只读（浏览器/文件） | 截图、HTTP、应用日志 | `username` / `password` |
| **ingest** | 把外部数据写入系统 | 写库/写文件 | 计数、dry-run 报告、样例行 | `connectionString` |
| **probe** | 向系统发问并记录回答 | 只读调用 | 请求/响应、状态码 | `token` / `connectionString` |
| **reconcile** | 对上两路或多路真相 | 只读 | 两侧摘录 + diff | 各源密钥 |
| **transform** | 把 A 变成 B（不写生产库） | 写本地产物 | 输入哈希、输出文件 | 通常无；或输入路径凭证 |

### 归类规则

1. 「打开页面看数据」→ **observe**（即使顺便记 HTTP）。  
2. 「CSV/JSON 进库」→ **ingest**。  
3. 「打几个 API / 读 Redis 看值」→ **probe**。  
4. 「页面数字是否等于库/接口」→ **reconcile**（不要做成 observe 里夹一段 SQL 却不声明）。  
5. 「格式转换、生成夹具」→ **transform**。  
6. 混合场景：**拆成两条 pipeline**，或主族 + 可选 collector。禁止一条 slug 同时「导入并验收 UI」还只写一份状态机。

### 何时立新族

同时满足才立：

- 状态机主干与现有五族都对不上；  
- 密钥与证据形状显著不同；  
- 预期至少还会有第二条实例。

否则：现有族 + adapter（例如 observe 的 `auth.mode: form | sso | none`）。

## 3. 仓内位置（逻辑树）

生成时按此树写；路径标识符保持英文。

```text
.cursor/commands/
  gen-<family>-pipeline.md      # 可选：一族一个生成命令
  run-<family>-pipeline.md      # 可选：一族一个执行命令
  # 或一族尚未稳定时：gen-pipeline / run-pipeline + family 参数

pipelines/
  README.md
  .gitignore                    # secrets.local.* 与 runs/
  _template/                    # 默认母版（或 _templates/<family>/）
    pipeline.md
    config.yaml
    secrets.example.yaml
    acceptance.md
  <slug>/                       # = 一条 Graph 实例
    pipeline.md                 # Graph 投影（runbook / Cook chain）
    config.yaml                 # 可提交意图
    secrets.example.yaml
    secrets.local.yaml          # gitignored
    design-brief.md             # 可选：生成时的 brief 存档
    scripts/                    # 隔离 cook 脚本（experimental；非业务包）
    runs/
      <yyyy-MM-ddTHHmmss>/
        report.md
        acceptance.md
        ...                     # family 规定的证据子目录
```

命名：

| 项 | 规则 |
|----|------|
| slug | kebab-case，字母开头；与场景主题相关，不含环境机密 |
| 证据文件 id | kebab-case；作文件名 |
| run 目录 | 本地时间 `yyyy-MM-ddTHHmmss` |
| 命令 | `/gen-<family>-pipeline`、`/run-<family>-pipeline` |

## 4. 工件职责

### 4.1 `pipeline.md`（runbook）

必须能脱离聊天独立执行。固定章节：

1. **目的 / Goal** — 一句；若替换旧验法，列出 retired 继任关系  
2. **Status** — `active`（默认）  
3. **非目标** — 列表  
4. **配置指针** — `./config.yaml`、`./secrets.local.yaml`  
5. **Sockets** — Start/End 或逐步 Input/Output；Cook：`in-place` \| `new-object`  
6. **Context** — 如何 Bind；歧义则停  
7. **状态机 / Cook chain** — 编号步骤或 mermaid；边上标 Socket；含失败策略  
8. **证据包** — 路径表 + 必做/可选  
9. **Invoke** — 命令或 `scripts/`；标明 `experimental` 或已落地  
10. **人闸 / Gate** — 缺密钥 / 破坏性确认 / 验收  
11. **判定级别** — L0–L3 谁判  
12. **Handoff** — Output 态与下游可能消费什么  

禁止：真实密码、仅对本次对话有意义的「如上所述」、把显示名当唯一 Context。

### 4.2 `config.yaml`（可提交意图）

逻辑字段（family 可扩展，但下列键尽量稳定）：

```yaml
id: sample-slug                 # = 目录名 = Graph 实例
family: observe                 # observe | ingest | probe | reconcile | transform
goal: ""                        # 互斥槽短名；同 goal 不得两个 active
status: active                  # active | retired
environment: local              # local | shared | production（非 local 必须人闸）
stopOnError: false
secretsRef: secrets.local.yaml
sockets:
  start: session-anonymous
  end: observe-captured
cook: new-object                # in-place | new-object（本 Graph 主语义）

# family 专有块（名称随族变化，位置固定在根下）
target: {}                      # 系统地址、表、路径等非机密
steps: []                       # 或 pages / endpoints / mappings
capture: {}                     # 证据开关
expect: []                      # L1/L2 启发式
```

原则：

- **可提交的都不是机密**。主机名若含内网且团队同意可提交；账号、密码、token、连接串不行。  
- 用引用而非内联密钥：`secretsRef`。  
- 默认安全：`ingest.dryRun` 默认可为 true；`environment: production` 必须显式。

### 4.3 密钥

`secrets.example.yaml`：键名 + 假值，可提交。  
`secrets.local.yaml`：真值，gitignore。用户拒绝落盘则只留在会话，run 时再问。

脱敏（证据落盘时）：password、connection string、token、Authorization、Cookie、完整 Set-Cookie。

### 4.4 Run 产物

每次 run 至少：

| 文件 | 作用 |
|------|------|
| `report.md` | 步骤、链接到证据、Agent 自评、状态=等待验收 |
| `acceptance.md` | 人填之前保持 pending |

其余子目录由 family 的证据包决定。启用却为空 → 仍建文件并声明原因。

## 5. 执行状态机（通用骨架）

所有 family 共用此外骨架，只替换中间 `execute`：

```text
init
  → load_config
  → resolve_secrets          # 缺则人闸
  → preflight / Bind         # Context 解析对象；歧义则停；破坏性则确认
  → execute / Cook           # family 特化；先装 collector
  → Validate + collect_evidence
  → write_report
  → await_user_acceptance    # Gate；不可静默通过
  → end
```

失败策略写在 config：

- `stopOnError: false` — 记录后继续后续步骤（observe 常用）  
- `stopOnError: true` — 立即停（ingest 写库常用）  
- 重试：默认上限 **2**，写在对应步骤旁

## 6. 证据包模型

每项证据是一条 **collector**：

```yaml
id: http
required: true          # true = 缺证必声明，不可省略文件
when: always            # always | family-default | scene
sink: http/             # 相对本次 run 目录
redact: [authorization, cookie]
```

**required 的含义**：不是「世界必须有数据」，而是「必须有一份说明文件」。零请求也要 `count: 0`。

采集顺序原则：**先安装收集器，再触发动作**（先挂钩再导航；先打开日志时间窗再操作）。事后补采会丢证据。

## 7. Adapter（族内变化，不是新族）

把「怎么登录 / 怎么取码 / 日志在哪」做成有序列表，失败则下一个，最后 `ask`。

```yaml
auth:
  mode: form            # form | sso | none | token-header
  sources:              # 有序列表
    - network
    - log
    - ask
```

Adapter 属于 config，不属于新 family。Sample 见 `04`。

## 8. 命令与模板的关系

| 成熟度 | 做法 |
|--------|------|
| MVP / 一族只有一条实例 | 模板在 `pipelines/_template/`；命令正文写清 family |
| 一族多实例 | `pipelines/_templates/<family>/` + `/gen-<family>-pipeline` |
| runbook > ~200 行 | 再抽 skill；命令只保留护栏与步骤索引 |

生成命令：**复制模板 → 填 brief → 替换占位符**。禁止从空白 invent 一套与本体冲突的目录。
