## 2. 端点总表（服务端视角）

管道顺序（`UrbanManagementAppModule.OnApplicationInitializationAsync`）：`/ClientLogs` 静态文件 → `wwwroot` 静态文件 → Routing → CORS(`SignalRPolicy`) → 本地化 → `HttpTrafficMeteringMiddleware` → `MapControllers` → `MapTus("/api/urban-attachment/tus/")` → `MapHub<DeviceStatusHub>("/hubs/devicestatus")` → `MapBlazorHub` → `MapFallbackToPage("/_Host")`。

## 3. 客户端实际依赖（MaterialClient.Urban）

客户端只有两个与 UM 相关的地址配置，C# 代码里没有写死主机：

| 配置键 | 生产值 | 用途 |
|--------|--------|------|
| `UrbanManagement:BaseUrl` | `http://191.12.234.212:5233` | Refit `IUrbanManagementApi`（240 s 超时）、`IUrbanAuthApi`（30 s）、tus `HttpClient` |
| `SignalR:ServerUrl` | `http://191.12.234.212:5233/hubs/devicestatus` | `DeviceStatusSignalRClient`，自动重连 + 持久重连 |

完整接口清单见 [`02`](02-客户端接口兼容契约.md)。要点：

- Urban 的 Refit 客户端**无鉴权头**；SignalR 仅在配置 `SignalR:AccessToken` 时带 token（现网默认未配，`INFERRED`）。
- 客户端解析的是**直接 DTO 响应体**（`recordId`、`attachmentIds`），激活接口用自定义 `HttpResult`（`success/msg/data`）。
- 客户端上传失败会在下一轮轮询（`Urban:UploadPollingPeriodMs`，默认 80 s）重试 → 切换期间的短暂停机可被客户端自愈（`INFERRED`：依据客户端"未同步记录轮询上报"机制）。

## 4. 进程内状态（决定拆分边界）

| 位置 | 状态 | 影响 |
|------|------|------|
| `DeviceStatusHub` 27、33、375、597 行 | `static Dictionary`：连接限流时间窗、`connectionId → proId` 映射、日志能力注册表、文件传输表 | Hub 只能**单实例**，多实例需先外置 |
| `ClientLogAppService` 37–44 行 | `static ConcurrentDictionary`：等待客户端回包的 `TaskCompletionSource`、文件分块缓冲、PathMap | 日志拉取的发起方（Blazor 页面 / `ClientLogController`）必须与 Hub **同进程** |
| `TusAttachmentResultStore` 21 行 | `ConcurrentDictionary<string fileId, Guid attachmentId>` | tus 完成回调与 `tus/commit` 必须落到**同一实例** |
| tus 文件存储 | `{ContentRoot}/Uploads/_tus`（`TusDiskStore`，60 分钟过期） | 需持久卷；多实例需共享卷 + 外置结果表 |
| ABP 分布式缓存 | Redis（`Redis:Configuration`，默认 `127.0.0.1:6379`），键前缀 `UM:`；设备状态、连接、注册表 | 已经是进程外状态，天然支持拆分；容器化后需提供 Redis 容器 |
| Blazor Server 电路 | 每个浏览器会话一条 SignalR 电路 | 管理端多实例需粘性会话；单实例最简单 |
| Data Protection | 未显式配置（`AddDataProtection` 无匹配） | 容器重建后密钥丢失 → Blazor/防伪令牌失效，需持久化 |

## 5. 跨进程推送路径（拆分后需要 backplane 的地方）

| 推送发起方 | 推送目标 | 证据 |
|-----------|----------|------|
| `UrbanWeighingRecordAppService.ApproveAsync` → `ServerApprovalSyncPushService` | `WeighingRecordApproved` → 项目组内客户端 | `ServerApprovalSyncPushService.cs` 51 |
| `DeviceStatusService`（Hub 与 `ClientStatusSnapshotBackgroundWorker` 调用） | `device_{type}` 组 | `DeviceStatusService.cs` 124 |
| `ClientLogAppService` | 指定 `connectionId` 的客户端 | `ClientLogAppService.cs` 148、204 |
| Hub 内部 | `client_connection`、`LogRequesters` 组 | `DeviceStatusHub.cs` 142、235、564、689、740 |

只要发起方与 Hub 不在同一进程，就必须给 SignalR 加 Redis backplane（`Microsoft.AspNetCore.SignalR.StackExchangeRedis`）。backplane 只影响服务端之间的消息转发，**不改变客户端协议**。

## 6. 后台任务

| Worker | 启用条件 | 外部副作用 |
|--------|----------|-----------|
| `GovSyncBackgroundWorker` | `BackgroundServices:Polling` 或 `BasePlatformSync:Enabled` 为 true | 向政府平台上报称重/卡口/成品；从 BasePlatform 拉项目 |
| `ClientStatusSnapshotBackgroundWorker` | `ClientStatusSnapshot:Enabled` | 写在线状态快照 |

两者都**必须全局单实例**；多实例会导致政府平台重复上报。现有配置开关已能按容器关闭，无需改代码。

| 项 | 现状 |
|----|------|
| Provider | `AbpEntityFrameworkCoreSqliteModule` + `options.UseSqlite()`（`UrbanManagementCoreModule.cs` 24、47） |
| 设计时工厂 | `UrbanManagementDbContextFactory` 使用 `UseSqlite("Data Source=:memory:")` |

## 9. 时间

代码中 30+ 处使用 `DateTime.Now`（`GovSyncBackgroundWorker`、`JwtAntiTamperService`、`FileService` 等）。IIS 宿主跟随 Windows 本地时区（东八区）；Linux 容器默认 UTC → 必须在容器设置 `TZ=Asia/Shanghai`，否则落库时间、Gov 上报时间、授权到期判断全部偏移 8 小时。
