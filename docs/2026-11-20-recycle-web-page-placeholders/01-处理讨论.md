# 处理讨论

本页保留原始候选拆分。第一批范围及调整以 [评审与 Decision](02-评审与Decision.md) 为准。生产管理已从当前版本侧栏隐藏，下面表里的日产量行留到该页重新打开时再做。

## 原则

1. 库里已经有的列，接到现在的格子上。不为了让格子有字而新造状态。
2. 保存后一定被丢掉的控件，先从页面拿掉。用户不该再看到一次「保存成功、刷新还原」。
3. 上报中文只翻译已经写入的 `RecycleSyncStatus`。`Succeeded` 继续只来自真实平台响应 `code` 200，本讨论不改上报实现。
4. 附件和「运输中」依赖业务事实，不放进同一次显示修正。

## 第一段：把现有列接上，并拿掉假控件

落地规模：S（约 5万–15万 token）。范围只在 `repos/UrbanManagement` 的 Recycle 页面和 `RecycleWebEndpoints` 的行投影。不加表，不改迁移。

| 现在的格子 | 处理 |
|------------|------|
| 车辆录入时间 | 用 `CreationTime` |
| 生产发送时间 | 用 `LastSyncedAt`，没有同步过就空白 |
| 运输出货时间 | 用 `WeighedAt` |
| 运输人 | 用 `TransporterName`，没有就空白 |
| 收货方列 | 列名改为卸点，绑定 `UnloadPoint`。收货方名称没有单独的列 |
| 合同、生产的上报状态 | `None` 与 `Pending` 显示「未上报」，`Succeeded` 显示「已上报」，`Failed` 显示「上报失败」。筛选项用这四个中文 |
| 车辆市上报 | 车辆没有 `SyncStatus`。列保持「未上报」，直到另有同步记录可读。不要在投影里写死一个永远不变的成功 |
| 车辆状态 | 去掉编辑框和这一列。运输中应由未收货的运输记录得出，不在车辆上存一个手改开关 |
| 批量导入 | 去掉按钮 |
| 合同 PDF、收货凭证 | 去掉选择文件的控件。`RecycleAttachments` 留到下一段 |
| 生产标识编号 | 去掉这一列。没有业务编号就不显示空白列 |
| 运输阶段 | 去掉那五个阶段。列表用已有事实：没有皮重为「待补皮重」，已称重且没有 `ReceivingTime` 为「待收货」，已有收货时间为「已收货」。批量上报按记录自身的同步状态选择出厂或收货，不再依赖 `loopPhase` |
| 新建合同生产方、过磅默认车牌和毛重 | 改为空白。过磅不再预填 `浙DE5145` 和 70 吨 |

## 第二段：附件

落地规模：M（约 15万–40万 token）。合同 PDF 和收货图片走已有的 `RecycleAttachment`。页面在文件真正保存之后才显示文件名。

这一段不和第一段绑在同一个 change 里。

文件以本地文件存放，不把内容写成数据库二进制列。`RecycleAttachments` 现在也没有内容列，只有 `StorageKey`、`FileName`、`ContentType`、`Size`。`RecycleAttachmentAppService.SaveAsync` 已经按这个形状写盘：

```text
{ContentRoot}/{StorageOptions:FilesPhysicalPath}/Recycle/{ProId:N}/{BusinessId:N}/{新Guid}{原扩展名}
```

`StorageKey` 记下相对 ContentRoot 的路径，例如 `Uploads/Recycle/{ProId}/{BusinessId}/{文件}.pdf`。数据库只留这条路径和文件名、类型、大小。

其它服务把宿主机目录 `UM_UPLOADS_HOST_PATH` 挂到容器 `/app/Uploads`，并设置 `StorageOptions__FilesPhysicalPath=Uploads/`。仓库里的 `um-recycle` 还没有这块挂载，也没有这组配置。文件要在重建容器后还在，Recycle 必须挂同一块目录。打开文件时按 `StorageKey` 读这块目录里的文件，不从数据库读出字节。

## 第三段：运输中

落地规模：M（约 15万–40万 token）。同一 `ProId` 下，该车牌存在已称重且 `ReceivingTime` 为空的 `RecycleTransportRecord` 时，车辆列表显示「运输中」，否则显示「未运输」。这是查询结果，不是车辆表上的可编辑列。

不要加一个用户随便拨动、又和运输记录脱节的状态字段。

## 不在这三次里做的事

- 不把市平台同步标成成功，除非已有响应 `code` 200。
- 不补「标识编号」的生成规则。没有业务定义就继续不显示。
- 不在本 topic 里改 `repos/`。进入产品行为还要 Human `APPROVED` 和 OpenSpec change。
