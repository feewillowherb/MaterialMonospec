# Recycle Web 页面占位字段

本页记录发现问题时的页面行为。评审已形成第一批的建议范围，产品实施待 Human `APPROVED`。

Cursor 交接见 [评审与 Decision](02-评审与Decision.md)。[处理讨论](01-处理讨论.md) 保留原始候选方案。

## 问题

Recycle Web 四个页面的名单来自接口，但有一批格子和编辑项不读写已存储的数据。车辆管理里把「车辆状态」改成「运输中」再保存，列表仍是「未运输」，就是这一类。

页面入口：

| 路径 | 源文件 |
|------|--------|
| `/vehicles` | `repos/UrbanManagement/src/UrbanManagement.Recycle/client/src/views/Vehicles.vue` |
| `/contracts` | `repos/UrbanManagement/src/UrbanManagement.Recycle/client/src/views/Contracts.vue` |
| `/productions` | `repos/UrbanManagement/src/UrbanManagement.Recycle/client/src/views/Productions.vue`。当前版本已从侧栏隐藏，打开该路径回到车辆管理 |
| `/transports` | `repos/UrbanManagement/src/UrbanManagement.Recycle/client/src/views/Transports.vue` |

列表行在 `repos/UrbanManagement/src/UrbanManagement.Recycle/RecycleWebEndpoints.cs` 的 `*PageRow.FromDto` 里组装。

## 固定字或未落库

这些项刷新后仍是固定字、空白，或保存请求里的值被丢掉。

| 页面 | 页面上的内容 | 源码 |
|------|----------------|------|
| 车辆管理 | 车辆状态 | `VehiclePageRow.FromDto` 固定 `"未运输"`。`Vehicles.vue` 的 `save` 不提交 `runStatus`。`RecycleVehicle` 没有这一列 |
| 车辆管理 | 录入时间 | `FromDto` 固定 `""`。实体有审计字段 `CreationTime` |
| 车辆管理 | 市上报 | `FromDto` 固定 `"未上报"`。实体没有 `SyncStatus` |
| 车辆管理 | 批量导入 | `noticeImport` 只提示当前不读取文件 |
| 合同管理 | PDF 附件 | 页面只保留文件名。`ContractPageWrite` 没有附件字段。`FromDto` 的附件名固定 `""`。表 `RecycleAttachments` 只存 `StorageKey` 路径，不存文件字节。页面保存路径还没有调用 `RecycleAttachmentAppService.SaveAsync` |
| 生产管理 | 标识编号 | `ProductionPageRow.FromDto` 的标识编号固定 `""`。`RecycleDailyProduction` 没有这个字段 |
| 生产管理 | 发送时间 | `FromDto` 固定 `""`。实体有 `LastSyncedAt` |
| 运输清单 | 阶段 | 页面筛「待收货 / 待出厂上报 / 已出厂上报 / 待收货上报 / 已完成」。接口返回的是 `transportStatus`（「待补皮重」或「已称重」），没有 `loopPhase`。列因此为空，批量上报按这些阶段过滤后认为所选记录不可上报 |
| 运输清单 | 运输人 | `TransportPageRow.FromDto` 固定 `""`。`RecycleTransportRecord.TransporterName` 存在 |
| 运输清单 | 收货凭证 | 选择图片后只把文件名放进表单。`TransportEnrichWrite` 没有该字段 |

## 库里有值、列没接上

| 页面 | 列 | 已存储的值 |
|------|----|------------|
| 运输清单 | 出货时间 `shipTime` | `RecycleTransportRecord.WeighedAt`。`FromDto` 没有把它放进这一列 |
| 运输清单 | 收货方 `consignee` | 收货保存写下的是 `UnloadPoint`。列表列绑定的是收货方，所以这一列是空的 |

## 文案和枚举不一致

合同管理、生产管理的上报状态来自 `RecycleSyncStatus.ToString()`，页面上是 `None`、`Pending`、`Succeeded`、`Failed`。筛选项写的是「已上报 / 未上报」，两边对不上。

`Succeeded` 只表示库里已经记下的同步状态。本 topic 不改变「没有平台 `code` 200 就不标成功」这条规则。

## 会保存、但默认值是写死的

| 位置 | 默认 |
|------|------|

这两处改掉之后，会按填写内容保存。

## 复核

2026-11-20 再对四个页面的列和保存请求。没有新的空白列。

- 运输清单没有「运输人」列。`TransportPageRow.FromDto` 把运输人固定成空字符串，页面当前不显示这一列。Decision 要显示 `TransporterName`，是补列。
- `ContractPageRow`、`ProductionPageRow`、`TransportPageRow` 的 `LastMockMessage` 固定为 `""`。日产量「刷新上报」和收货保存因此读不到接口说明，提示落到页面里的兜底句子。Decision 已要求按 HTTP 结果提示。
- 编辑车辆时请求里的 `isEnabled` 固定为 `true`。页面没有停用控件，列表上的「启用」来自数据库。这不是占位列。

## 和本 topic 无关的已接通字段

车牌、皮重、运输人电话、合同编号、签订日期、购买方、收货地址、产品明细、产量、运输毛重和收货时间，走的是对应表的列。138 上那两份合同和两辆车来自 Graph `recycle-web-contract-vehicle-seed` 的 Run `2026-11-20T134207`，不是本 topic 的页面占位。
