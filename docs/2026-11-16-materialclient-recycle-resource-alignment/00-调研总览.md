# MaterialClient.Recycle 对齐资源化 Web 与 Urban 采集端

创建日期：2026-11-16。生命周期：ACTIVE。知识状态：PENDING_VALIDATION（命名决策已 CONFIRMED，职责与协议仍待定）。

本 Topic 记录重构 `MaterialClient.Recycle` 的产品目标，以及与资源化 Web 的命名、职责边界。它是需求对齐笔记，不是 OpenSpec change，也没有改 `repos/MaterialClient` 或 `repos/UrbanManagement`。

## 本单目标

把资源化利用做成「Web 管业务表单、工控端只采集」的一对客户端：

| 角色 | 现有工程 | 期望职责 |
|------|----------|----------|
| 我方平台 | 统称 **UrbanManagement.Recycle**（Web 现状为 `UrbanManagement.XiaoShanResource`，ProductCode **5041**；英文收敛到 Recycle） | 业务表单；接收工控上传；再向杭州市资源化利用厂接口 V1.0 上报 |
| 工控桌面端 | `MaterialClient.Recycle`（ProductCode **5020**，`WeighingMode.Recycle = 301`） | 对齐 `MaterialClient.Urban`：采集**毛重**和车牌并上传；皮重在 Web 车辆池；不在客户端填供应商/材料等表单 |

二者是同一套业务系统的两端，不是两套产品。平台侧与客户端侧的改造说明见 [`02-recycle客户端重构.md`](02-recycle客户端重构.md)、[`03-urbanmanagement-recycle实现.md`](03-urbanmanagement-recycle实现.md)。

### Web 承接

- **车辆管理** = 车辆信息池（皮重查表），**不是**业务主数据。
- **合同管理** = 合同目录（可上报 §2.4）。
- **生产管理** = 日产量（§2.5），见 1116 截图；**不是**工控过磅落点。
- **运输清单** = 工控上传落点；补全合同号、产品、收货凭据等；产品净重来自平台计算。
- 详见 [`04-业务闭环.md`](04-业务闭环.md)、[`05-生产管理与运输清单页面.md`](05-生产管理与运输清单页面.md)。
- Mock 两页 OpenSpec：`add-xiaoshan-resource-production-transport`。

### 工控端（`MaterialClient.Recycle`）

对齐 `MaterialClient.Urban` 的采集端模型：

- **要做**：毛重、车牌、现场照片 → 上传我方平台（落入 **运输清单**）。
- **不做**：合同号、材料、供应商、收货凭据；不维护皮重、不算净重。
- 皮重来自车辆信息池；净重由平台 `毛重 − 皮重` 计算；业务明细在 Web **运输清单**补全后再报 §2.2。

### 上传链路（已确认）

2026-11-16 Human 确认数据两跳：

1. **工控端 → 我方平台**：`MaterialClient.Recycle` 先把采集数据上传到我方平台（与 `MaterialClient.Urban` 先上 UrbanManagement 同构；具体服务/路由另开设计）。
2. **我方平台 → 市平台**：再由我方平台对接 [`docs/SyncDoc/杭州市资源化利用厂数据接入接口V1.0.md`](../SyncDoc/杭州市资源化利用厂数据接入接口V1.0.md)（含既有 §2.2 等开放接口）。

工控端不直连市平台。第二跳在我方平台侧完成（Worker / 同步服务等，实现另定）。这取代历史草稿里「客户端直连 §2.2」的方向。

- Web 工程 `Resource` → `Recycle` 的最终类型名与 compose 名（方向已定，字符串另开 change）。
