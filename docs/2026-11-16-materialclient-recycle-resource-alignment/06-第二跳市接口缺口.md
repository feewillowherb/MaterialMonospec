| 结论 | 说明 |

| **不够直接满足** | 四页形状对齐成品出厂主链（§2.4 / §2.5 / §2.2 + 车辆池），但 **按 V1.0 必填逐项核对仍有缺口** |

## §2.6 成品运输车辆 — 判定：不满足（若要坚持报满 §2.6）

页面是 **皮重信息池**，不是 §2.6 完整主数据表。

| V1.0 字段 | 必填 | 页面/来源 | 状态 |
|-----------|------|-----------|------|
| `carNo` | 是 | 车牌号 | OK |
| `ownerName` | 是 | 运输人 | **歧义**：运输人 ≠ 车主？ |
| `ownerPhone` | 是 | 电话 | OK |
| `companyName` | 是 | — | **GAP** |
| `approvedLoad` | 是 | — | **GAP**（额定载重 ≠ 皮重） |
| `vehicleModel` | 是 | — | **GAP**（0/1） |
| 皮重 | — | 皮重(吨) | **本地专用**，不映射 §2.6 |

**推理完善**：

- **方案 A（推荐）**：§2.6 另扩表字段或录入项：所属公司、额定载重、车辆类型；皮重仍只服务净重。  
- **方案 B**：`companyName` / `vehicleModel` / `approvedLoad` 用厂级配置默认；仅车牌+人+电话来自页面（弱合规，须业务点头）。  
- **方案 C**：暂不报 §2.6，只保证池内皮重供 §2.2；市平台若强制车辆先建档则不可行。

## §2.2 成品销售车次 — 判定：结构对齐，出厂最小集 PARTIAL

工控已确认提供：车牌、毛重、现场照片 → 平台算净重。页面展示/补全：合同、产品、净重、出货/收货时间与凭证。

### 出厂首次上报（必填）

| V1.0 字段 | 必填 | 来源 | 状态 |
|-----------|------|------|------|
| `dataNo` | 是 | 平台生成并固化 | CFG |
| `pointNumber` | 是 | 配置 | CFG |
| `carNo` | 是 | 工控 / 清单车牌 | OK |
| `productName` | 是 | 清单「产品」（Web 补全） | OK 若补全；空则 **GAP** |
| `netWeight` | 是 | 平台毛−皮 | OK（链路已确认）；**单位吨/kg 未证实** |
| `outTime` | 是 | 出货时间 | OK（工控时间落清单） |
| `outPhotos` | 是 | 出货凭证 ← 工控照片 | **GAP**：现 mock 仅文件名；须 Base64 或先 §2.7 再填路径（文档写 Base64） |

### 出厂可选（宜带）

| V1.0 字段 | 来源 | 状态 |
|-----------|------|------|
| `tareWeight` / `grossWeight` | 池内皮重 / 工控毛重 | DERIVE（清单可不展示毛/皮列，库内要有） |
| `saleContractNo` | 清单合同编号 | OK 若已补 |
| `unitPrice` / `payAmount` | 合同明细按产品匹配 | DERIVE |
| `carrierCompanyName` | 合同运输方或车辆所属公司 | DERIVE / GAP |

### 收货二次上报（文档：收货后再次调用时必传）

| V1.0 字段 | 页面 | 状态 |
|-----------|------|------|
| `receivingTime` | 收货时间 | OK |
| `receivingProof` | 收货凭证 | **GAP**：真图/Base64，非「查看」占位 |
| `consignee` | **无独立「收货方」列** | **GAP**（可 DERIVE 合同购买方，须确认） |
| `consigneeAddress` | 卸点仅为摘要 | **GAP**；完整地址宜 DERIVE 合同 `shipAddress` |

### 清单页对第二跳的隐含要求（完善逻辑）

1. 库表除净重外 **持久化毛重、皮重**（页面可不显毛）。  
2. 出货/收货凭证存 **可还原的二进制或市平台 filePath**，不能只存展示名。  
3. 上报门闩：出厂最小集（车牌+产品+净重+出货时间+出货照+厂标识+dataNo）齐才能 Worker 推 §2.2。  
4. 收货补传：同一 `dataNo` 再调；缺 `consignee` 时默认策略（购买方 / 手填）须定。  
5. 「起点」不上报；「卸点」不替代 `consigneeAddress`。

## 按章节：能否用「当前页面数据」报满

| 章节 | 仅靠当前页面字段？ | 补齐后能否第二跳？ |
|------|-------------------|-------------------|
| §2.4 | 业务字段基本能 | 是（+CFG `pointNumber` + 真 §2.7） |
| §2.5 | 基本能 | 是（+CFG + 单位/取整规则） |
| §2.6 | **不能** | 须扩字段或配置默认 |
| §2.2 出厂 | **不能仅靠列表展示** | 须：库内毛皮净、真出货照、产品已补、CFG |
| §2.2 收货 | **不能** | 须：收货方、完整地址、真收货照 |
| §2.1/2.3/2.8/2.9 | 无页面 | Out-of-Scope |

**一句话**：页面信息架构支持「成品销售」故事，但 **现有字段与 mock 深度不足以原样喂满 V1.0 Worker**；合同/日产量最接近，车辆 §2.6 与车次照片/收货方是硬缺口。

## 建议的第二跳完善清单（非 OpenSpec tasks）

1. **配置**：`pointNumber` / HMAC / 厂级默认 `companyName`·`vehicleModel`（若选方案 B）。  
2. **车辆池**：明确是否报 §2.6；若报则加额定载重、所属公司、车辆类型；皮重保持本地。  
3. **合同**：保存时校验明细；PDF 走 §2.7 再写 `attachments`。  
4. **运输清单实体**：毛/皮/净、出货照二进制或路径、`dataNo`、补全态、上报态；编辑补产品/合同/收货方。  
5. **Worker**：出厂最小集校验 → §2.2；收货事件 → 同 `dataNo` 补传。  
6. **单位**：与市平台确认 §2.2 `netWeight` 等为吨还是 kg（文档写吨、示例像 kg）。
