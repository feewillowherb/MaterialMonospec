## 已确认决策（2026-11-16）

| 层 | 决定 |
|----|------|
| 对外中文 | 继续「资源化利用 / 萧山资源化利用网页端」；Recycle **不是**中文产品名 |
| 英文工程与类型 | **统一为 Recycle** |
| 桌面 | 保持 `MaterialClient.Recycle` / `MaterialClient.Common.Recycle` / `ProductCode.Recycle` |
| Web | 现状 `XiaoShanResource` 视为待收敛名；后续 OpenSpec 改为 Recycle 系标识（目标名示例：`UrbanManagement.XiaoShanRecycle`，Cookie / compose 同步，最终名以 change 为准） |
| 产品码数字 | 桌面 **5020**、Web **5041** 先不改 |

策略对照中的 **A 的「桌面坚持 Recycle」已升级为「全系统英文统一 Recycle」**：桌面不动；Web 从 Resource 迁到 Recycle。原建议的 B/C（迁到 Resource）**作废**。

## 决策维度（仍适用）

改名时只动需要动的一层：

1. **对外中文**：资源化利用 — 已与产品名一致，不因英文改 Recycle 而改中文。
2. **英文类型与工程名**：长期一律 `Recycle`。
3. **ProductCode 数字**：5020 / 5041 已与授权、SSO、现场配置绑定；无充分理由不要改数字。
4. **SQLite / 表名**：桌面 `RecycleWaybillExtensions` 已符合目标，不必为对齐再 rename。

## Web 收敛范围（另开 change）

至少涉及（实现前再扫一遍）：

- 工程 / 程序集：`UrbanManagement.XiaoShanResource` → Recycle 系名称
- Cookie：`XiaoShanResource.Session`
- compose 服务名 / 镜像名：`um-xiaoshanresource`、`urbanmanagement-xiaoshanresource`
- 文档与 OpenSpec：`add-xiaoshan-resource-web`、萧山资源化 Topic 中的英文工程名
- 环境变量与 DataProtection 应用名中带 Resource 的字符串

未批准的 rename change 之前，仓库里仍会暂时看到 Resource 标识；沟通时说明「英文目标是 Recycle，Web 尚未改完」。

## 与 Urban 命名的关系

`MaterialClient.Urban` 是城管采集端。Recycle 工控端对齐的是 Urban 的**职责**（采集重量/车牌并上传），名称仍是 Recycle，不改成 Urban。
