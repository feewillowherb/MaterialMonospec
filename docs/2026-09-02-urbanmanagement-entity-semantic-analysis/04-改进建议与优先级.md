# 04 · 改进建议与优先级

## 1. 原则（与仓库 trait 对齐）

1. **枚举优先**：领域状态用命名 enum，禁止 Service 层 `0/1/2` 魔法值
2. **Nullable 有意义**：仅对「未知 / 未发生 / 可选扩展」开放；创建时即确定的字段 non-nullable
3. **类型归属行为**：状态迁移（如 `ResetGovSync`）写在 Entity 方法内，使用 enum 非 int
4. **命名一致**：接入码统一 `AccessCode`；`ProId` 统一 `Guid`（在线态表需迁移策略）
5. **遗留隔离**：`GovSyncData` 不继续扩展；新功能只写 `UrbanWeighingRecord` / `UrbanPassageRecord`
6. **分 change 落地**：遵循 OpenSpec + `openspec-git-workflow`；不做大爆炸式 refactor

## 2. 分阶段建议

### P0 — 低风险、高收益（建议优先 OpenSpec）

| 项 | 动作 | 涉及文件 |
|----|------|----------|
| 统一 `SyncStatus` | `UrbanPassageRecord.SyncType`: `int?` → `SyncStatus`（non-nullable，默认 Pending） | Entity, DTO, `Gov*SyncManager`, AppService, EF migration |
| 去除魔法值 | 所有 `SyncType = 1/2`、`!= 1`、`is not (1 or 2)` → `SyncStatus.Success/Failed/Pending` | 见 [02-枚举与int魔法值问题.md](./02-枚举与int魔法值问题.md) |
| 收紧 RetryCount | `int?` → `int`，默认 0 | 通行 + 称重实体 |
| 修正 Entity 方法 | `ResetGovSync` / `FromReceive` 使用 `SyncStatus.Pending` | `UrbanPassageRecord.cs` |

**预期**：单仓、多文件但路径清晰；约 **M 档（~15万–40万 token）**。

**注意**：SQLite 已有数据需 migration 将 NULL `SyncType` 映射为 `0`（Pending）；EF enum 底层仍为 INTEGER，列类型不变。

### P1 — 称重实体与通行对齐

| 项 | 动作 |
|----|------|
| `SiteType` → `UrbanSiteType` | `UrbanWeighingRecord`；迁移 string → int enum；与萧山映射在 Service/上报层 |
| `SyncType` / `ClientSyncType` non-nullable | 创建时必须 Pending |
| `BuildLicenseNo` → `AccessCode` | 列重命名或 DB 列映射 `HasColumnName` 保持兼容 |
| 车辆属性 enum 化 | 评估 `VehicleType`、`PlateColor` 是否引入 enum 或共享 MaterialClient 枚举 |

**预期**：涉及 API 契约与 MaterialClient 对齐；约 **M–L 档**。

### P2 — 在线态与设备

| 项 | 动作 |
|----|------|
| `DeviceType` / `Status` enum | `ClientDeviceOnlineStatus`, `DeviceStatusLog` |
| `ProId` 统一 Guid | `ClientOnlineStatus` / `ClientDeviceOnlineStatus` string → Guid migration（需评估历史数据） |
| `EnableSync bool?` → `bool` | `GovProject`，默认 false |

**预期**：**M 档**；ProId 类型变更需单独评估。

### P3 — 遗留收敛（可选、独立 change）

| 项 | 动作 |
|----|------|
| 冻结 `GovSyncData` | 标记 obsolete；Legacy 路径只写 `UrbanWeighingRecord` |
| 历史数据 | 只读保留或 ETL 归档；不强制删除表 |
| `SnapTime`/`GoodsWeight` string | 若仍需表，逐步改为强类型或废弃 |

**预期**：**S–M 档**（若仅冻结不写）；全量迁移 **L 档**。

## 3. 建议 OpenSpec change 切分

| Change 名称（示例） | 范围 | 档位 |
|---------------------|------|------|
| `refactor-urban-passage-sync-status-enum` | P0 通行 SyncStatus | M |
| `update-urban-weighing-record-site-type-enum` | P1 SiteType + nullable 收紧 | M |
| `refactor-urban-online-status-proid-guid` | P2 ProId 统一 | M–L |
| `remove-gov-sync-data-dual-write` | P3 Legacy 双写移除 | M |

**禁止**塞进功能 change：除非 proposal 明确列出 tech debt 项（见根 `AGENTS.md` OpenSpec 与技术债务）。

## 4. 实施检查清单（Apply 阶段）

- [ ] Entity 无新增 `int` 表示 enum 语义字段
- [ ] Service 无 `SyncType` 字面量 `0/1/2`
- [ ] 新建/变更 API DTO 与 Entity enum 一致
- [ ] EF migration 处理 NULL → 默认值
- [ ] `type-owned-methods`：状态重置在 Entity 方法内
- [ ] 未使用 tuple（record 替代）
- [ ] 未新增 DB 外键 / 导航属性

## 5. 不建议的做法

| 做法 | 原因 |
|------|------|
| 一次性重写全部 Entity | 风险高、难 review |
| 仅加注释不改类型 | 不解决编译期安全 |
| 在 `GovSyncData` 上继续堆字段 | 强化反模式 |
| AutoMapper 映射 enum↔int | 违反 UrbanManagement AGENTS DTO 约定 |
| 用 `ExtraProperties` 替代正规字段 | 长期损害语义化 |

## 6. 参考范例（本仓内）

以 **`UrbanPassageRecord`** 的 `PassageSource` / `UrbanInOutType` / `UrbanSiteType` 与 **`AttachmentFile.AttachType`** 为目标风格：

```csharp
// 目标形态（示意）
public SyncStatus SyncType { get; private set; } = SyncStatus.Pending;
public int RetryCount { get; private set; }

public void MarkSyncSuccess(DateTime at) { SyncType = SyncStatus.Success; SyncTime = at; }
public void MarkSyncFailed(DateTime at) { SyncType = SyncStatus.Failed; LastErrorTime = at; RetryCount++; }
```
