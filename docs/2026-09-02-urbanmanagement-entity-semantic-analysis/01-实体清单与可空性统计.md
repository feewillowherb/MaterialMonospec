## 3. Nullable 分类：合理 vs 可疑

### 3.1 合理可空（状态机 / 可选业务数据）

| 字段模式 | 典型 Entity | 理由 |
|----------|-------------|------|
| 同步结果时间戳 | `SyncTime`, `ClientSyncTime`, `LastErrorTime` | 未同步前无值 |
| 错误/异常说明 | `AnomalyReason` | 仅 `IsAnomaly=true` 时有意义 |
| 连接生命周期 | `ConnectedAt`, `DisconnectedAt`, `LastSeenAt` | 离线态无连接时间 |
| 授权截止 | `AuthEndTime`, `AuthToken` | 项目可能未配置 |
| 软删除 | `DeletionTime` | 未删除时为 null |
| 预留扩展 | `Slot`（ClientOnlineStatus） | 注释标明 V2 预留 |

### 3.2 可疑可空（应收紧或改用默认值 / 枚举）

| 字段 | Entity | 问题 |
|------|--------|------|
| `SyncType`, `ClientSyncType` | `UrbanWeighingRecord` | 已有 `SyncStatus` 枚举，但仍 `SyncStatus?`；创建时通常应为 `Pending` |
| `SyncType`, `RetryCount` | `UrbanPassageRecord` | `int?` + 业务上创建即赋 `0`，应为非空 `SyncStatus` + `int` |
| `PlateNumber` | 称重/通行 | 业务上常必填；nullable 允许「无车牌」但未用 Value Object 表达 |
| `ProId`, `ProName` | 称重/通行 | 接入后应有项目上下文；nullable 使查询与同步条件复杂化 |
| `EnableSync` | `GovProject` | `bool?` 语义不清；更应为 `bool` + 明确默认 |
| `GovSyncData.*` 几乎全部 | 遗留表 | 字符串化 + 全 nullable，无法表达必填约束 |

### 3.3 类型不一致导致的「伪 nullable」

| 概念 | 类型 A | 类型 B | 位置 |
|------|--------|--------|------|
| 项目 ID | `Guid?` | `string?` | `UrbanWeighingRecord` vs `GovSyncData` |
| 项目 ID | `Guid?` | `string`（非空默认 `""`） | `UrbanPassageRecord` vs `ClientOnlineStatus.ProId` |
| 接入码 | `BuildLicenseNo` | `AccessCode` | 称重/通行 vs `GovProject` |
| 站点类型 | `string? SiteType` | `UrbanSiteType` enum | `UrbanWeighingRecord` vs `UrbanPassageRecord` |

## 5. 关联实体（低 nullable，结构清晰）

`AttachmentFile`、`UrbanWeighingRecordAttachment`、`UrbanPassageRecordAttachment` 结构简单、约束明确，可作为 **目标建模风格** 参照：

- 必填字段使用 non-nullable + `IsRequired()` / `default!`
- 枚举字段 `AttachType` 已正确映射为 `short`
- 关联仅保留逻辑 `{Related}Id`，无导航属性（符合 monospec `no-database-fk` trait）
