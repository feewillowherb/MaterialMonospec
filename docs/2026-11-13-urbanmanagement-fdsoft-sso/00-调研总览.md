## 接入含义与候选方向

知识状态：INFERRED / PENDING_VALIDATION，以下是后续设计输入，不是已批准的实现方案。

- 当前已找到的是自定义 JSON 登录、JWT 与 Redis 会话机制；未在所读入口中发现 OIDC 授权码、Discovery、标准回调流程，不能直接按标准 OIDC 提供方接入。
- 若沿用现有协议，可评估由 Admin 登录页面通过服务端请求 SSO，验证返回身份后建立 Admin 自有 Web 会话。是否采用此方向，取决于 JWT 验证契约、账号权限模型和会话撤销约定；不预设跨域共享 Cookie。
- Web 会话保护应覆盖管理页面、Blazor Hub 和实际支撑页面操作的管理接口。仅隐藏菜单或替换 RouteView 不足以定义服务端访问边界。
- 共享 Hosting 与 Gateway 还承载其他服务；后续必须逐路由区分管理页面所用接口、客户端接口与健康检查，不能给全部服务统一追加 Web 登录跳转。
- SSO 登录结果涉及 UserId、ProductId、CoId、RootCoId、ProIds、RoleList、PowerItemList 等上下文（见 RealLogin）。这些字段与 UrbanManagement 的项目数据访问范围如何对应仍为 UNKNOWN，不能把登录成功直接解释为所有管理功能可访问，也不能假定 SSO 企业就是 ABP Tenant。
- 退出管理页面至少需要清除本地 Web 会话；是否同时退出 SSO、撤销 JWT，以及已有 Blazor 连接何时失效，需要明确约定并验证。

### 可继续执行的接入路线

候选路线为「Admin 登录表单 → Admin 服务端调用 SSO GetToken → 验证身份与 Web 产品权限 → 建立 Admin 本地 Cookie 会话 → 保护页面、Blazor Hub 与管理操作」。这条路线使用 SSO 账号认证，不要求它必须提供标准 OIDC，也不代表已经具备跨站免密跳转登录。

实现前需要先做一次成功登录的最小联调：

1. 确认线上真实 API 基址或反向代理前缀、POST `/GetToken` 的契约，并确认与当前源码版本的关系。
2. 准备授权用于联调的 Web 账号、明确 Web 产品标识与允许的企业/项目范围；普通登录固定为登录分支，不透传身份切换参数。
3. 补齐 FdSoft.Common 契约，确定令牌签名验证、有效期、可信声明和 Redis 会话检查策略。读取 JWT 内容本身不构成身份验证。
4. 在隔离验证环境完成一次有效登录、一次无效登录、一次无产品权限验证，并确认本地会话到期、退出行为。实际样本和环境信息仅存 `.local`。
5. 据联调证据决定是否进入 OpenSpec；实施时在 Admin 边界建立认证，按客户端路由清单做回归，保持 MaterialClient.Urban 不受影响。
