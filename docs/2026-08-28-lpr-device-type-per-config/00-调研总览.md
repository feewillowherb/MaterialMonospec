# 00 · 调研总览：LPR 设备类型从全局下沉到添加时确定

**日期**：2026-08-28  
**类型**：代码考古 + 落地规模 / 破坏性评估  
**状态**：建议；**尚未**开 OpenSpec  
**子仓**：`repos/MaterialClient`（UrbanManagement / BasePlatform 不在本期）

## 一句话

设置页「车牌识别设备类型」今天是 `SystemSettings.LprDeviceType` **全站一份**；`AddLprDialog` 只是把这个值当构造参数。要改成**添加/编辑每台 LPR 时选定厂商**，必须给每条 `LicensePlateRecognitionConfig` 持久化 `DeviceType`，并改掉运行时「只启动一种厂商 SDK」的假设。

## 落地规模（effort-token-estimate）

| 范围 | 档位 | token 量级 | 说明 |
|------|------|------------|------|
| **本期（厂商下沉）** | **M** | 约 15万–40万 | 单仓、多模块（配置 JSON + 设置 UI + DeviceManager/抓拍/在线/道闸）；偏 M 上沿 |
| 仅挪 Combo、仍只存全局 | S | 约 5万–15万 | **达不到**产品意图 |
| 草稿里的地磅/卡口/成品独立 entity + 上报 | L～XL | 40万+ | **不要**捆进本期 |

开 change 后 effort **只**写 `.openspec.yaml`，勿写入 `proposal.md`。
