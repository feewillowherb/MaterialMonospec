# 2026-11-20 抓拍机图片与净重正负

## 问题

测试称重要使用入口抓拍机 `camera_1`（`192.168.3.245:8000`，通道 1）当时拍到的图片。车牌由测试 API 注入。`浙A35586D` 的净重为负，`浙A33606D` 的净重为正。

## 实验

称重抓拍列表原来是空的，这台设备只在车牌识别配置里。已把它写入称重抓拍。地磅保持测试模式。两次抓拍期间关闭了主动车牌抓拍，避免设备自己读到的车牌覆盖测试 API；抓拍结束后已改回开启。

| 步骤 | 浙A35586D | 浙A33606D |
|------|-----------|-----------|
| 车牌 | `POST /api/lpr/test-plate` | 同左 |
| 毛重 | `POST /api/scale/weight` 10 吨 | 20 吨 |
| 车辆皮重 | 13.50 吨 | 13.42 吨 |

稳定后客户端保存称重，并保存 `camera_1` 的 JPEG。这两条新建记录没有自动进入待上报，测试里补上待上报后，由已启动的客户端送到 138。

## 证据

| 观察 | 结果 |
|------|------|
| 本地记录 69 | 车牌 `浙A35586D`，毛重 10 吨，图片为 JPEG，约 192 KB |
| 本地记录 70 | 车牌 `浙A33606D`，毛重 20 吨，图片为 JPEG，约 189 KB |
| 图片内容 | 两张都是这台抓拍机当时的实景，不是程序生成的占位图 |
| 138 来源记录 69 | 皮重已写入，毛重 10000 kg，净重为负 |
| 138 来源记录 70 | 皮重已写入，毛重 20000 kg，净重为正 |
| 本地上报状态 | 两条都是 `Accepted` |

## Verdict

`FEASIBLE`。测试 API 的车牌、抓拍机实拍图片，以及一负一正的净重，都能在这一轮里同时出现。图片留在客户端，138 只保存称重。这不是 Capability 交付。
