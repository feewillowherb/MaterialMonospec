## 问题

MaterialClient.Recycle 的地磅测试重量，能否进入 138 上已发布的 Recycle Web？

## 实验

- 客户端：地磅测试接口只把吨位放进本机测试预处理器。称重保存后发布 `RecycleWeighingUploadRequestedEventData`。
- 处理程序：`RecycleWeighingUploadRequestedEventHandler` 写一条日志后返回，不发 HTTP。
- 138：Recycle Web 为 Production。匿名 POST 客户端形状的接收体，以及页面用的模拟称重体。
- 库：`GovProjects` 中产品码 5020 且未删除的行数。

发布健康检查见 Run `deploy-urban-lab-138` / `2026-11-19T164403`。该 Run 只说明站点进程在，不说明称重已写入。

## 证据

| 观察 | 结果 |
|------|------|
| 地磅测试设置重量 | 只调用本机 `IScaleTestWeightPreprocessorService.Enqueue` |
| 称重保存后的上传 | 发布本地事件；处理程序不调用 Recycle Web |
| `POST /api/transports/receive`，匿名，毛重 2500 kg | HTTP 401 |
| `POST /api/loop/simulate-weigh`，匿名，毛重 2.5 t | HTTP 401 |
| 产品码 5020 的 `GovProjects` 行 | 0 |

401 在进入接收逻辑之前返回。这次没有写入运输记录，也没有把同步标成成功。

## Verdict

`FEASIBLE`。接收门闩补上工作单元后，激活客户端的称重已写入 138 的 Recycle Web。首次实验的 401 与当时的空项目表保留在上面的证据表，不作为这次的结果。
