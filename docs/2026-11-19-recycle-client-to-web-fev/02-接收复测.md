# 2026-11-20 客户端到 Recycle Web 复测

## 问题

当前检出的 MaterialClient.Recycle，能否把地磅测试重量送进 138 上刚发布的 Recycle Web？

## 实验

- 发布：`deploy-urban-lab-138` run `2026-11-20T104544`，结果 `pass`。该次发布包含 `POST /api/transports/receive` 的设备令牌门闩。
- 138：`GET /health/live`，以及两次 `POST /api/transports/receive`，正文只含 `grossWeightKg` 2500。一次不带 `Authorization`，一次带无法通过校验的 Bearer。
- 客户端：查看当前 `main` 检出里的 Recycle 上报入口。没有调用激活接口，没有写入运输台账。

## 证据

| 观察 | 结果 |
|------|------|
| `GET http://192.168.3.138:5334/health/live` | HTTP 200 |
| 匿名 `POST /api/transports/receive` | HTTP 401，响应体长度 0 |
| Bearer 无法校验的 `POST /api/transports/receive` | HTTP 401，响应体长度 0 |
| 当前客户端上报入口 | `IRecycleDataApi` 指向市平台 `/dataCenter/resourcePlace/.../addBatch`，源码中没有 `/api/transports/receive` |

401 发生在入库之前。这次没有运输记录写入，也没有把同步标成成功。

## Verdict

`INFEASIBLE`。当前检出的客户端不向 Recycle Web 发送称重。138 的接收口对没有有效设备令牌的请求返回 401，有效令牌下的入库仍未执行。
