# 01 · 现状与耦合

路径均相对 MaterialMonospec：`repos/MaterialClient/...`。

## 宿主与安装包

| 产物 | 项目 | 安装脚本 AppName |
|------|------|------------------|
| 标准 + 固废（同一安装） | `src/MaterialClient` | `MaterialClient.iss` → `MaterialClient` |
| 城管地磅 | `src/MaterialClient.Urban` | `MaterialClient.Urban.iss` → 凡东城管地磅系统 |
| 资源化 | `src/MaterialClient.Recycle` | `MaterialClient.Recycle.iss` → 凡东资源化利用厂系统 |

固废 **没有** 对等的 `MaterialClient.SolidWaste` 项目。授权切到 `ProductCode.SolidWaste` 后，仍是标准 exe 里 `DefaultWeighingMode = SolidWaste`。

## 内核已有、应保留的列

`AddSolidWasteMode` 给 `WeighingRecords` / `Waybills` 加了 `WeighingMode` 与 `ExtraProperties`。这是 **内核判别列 + 扩展袋**，不是「固废专用表」。方案 B 下：

- **留下内核**：`WeighingMode`（含 `Standard` / `SolidWaste` 枚举值）、通用 `ExtraProperties`。
- **不要**为固废往 `WeighingRecord` 加业务列；固废字段继续走 ExtraProperties 键，或将来进 `Common.SolidWaste` 扩展表（与 Urban 扩展表同套路）。

固废业务键今日在 `SolidWasteInfoExtensions`：`SolidWasteInfo.SolidWasteType` / `Street` / `SolidWasteOrderNumber` / `Shipper`。

## 固废仍堆在 Common / AttendedWeighing

**Common（领域 + 服务）**

- `Services/SolidWasteService.cs`、`ExcelExportService` 固废导出
- `Models/SolidWasteExportRow.cs`、`SolidWasteExportFilter.cs`、`PagedSolidWasteResult.cs`
- `Configuration/SolidWasteTypeConfig.cs`
- `Entities/ISolidWasteInfo.cs`、`SolidWasteInfoExtensions.cs`
- `WeighingMatchingService` 内 `CopySolidWasteInfoToWaybill` 等

**AttendedWeighing（UI，标准与固废共用）**

- `SolidWasteWeighingDetailViewModel`、`SolidWasteModeFormView`
- `DataManagementDialogViewModel`（固废台账）vs `StandardDataManagementDialogViewModel` / `StandardWeighingDetailViewModel`
- `AttendedWeighingViewModel` 按 `WeighingMode` 分支：净重/偏差、导出文件名「固废运单」、详情 VM 解析

`MaterialClientAttendedWeighingModule` 被 **标准宿主和 Recycle 宿主** 同时 `DependsOn`。Recycle 详情走 `RecycleWeighingDetailViewModel`，但列表/打印等多处把 **SolidWaste 与 Recycle 绑在同一分支**（`is WeighingMode.SolidWaste or WeighingMode.Recycle`）。拆固废客户端时必须 **显式切开 Recycle**，不能把 Recycle 一起搬进 `Common.SolidWaste`。

## 标准物料验收仍与「内核」重叠

标准模式的匹配、物料、磅差、标准详情 VM 都在 Common + AttendedWeighing + `MaterialClient` 宿主。  
对方案 B 而言：**内核 = 称重/运单/附件/认证/内核设置**；「凡东智能物料验收」= **使用内核的那个产品宿主**，不是再造一套内核表。

分离标准客户端的含义是：

- `MaterialClient.exe` **只**注册 Standard 默认模式、只带标准 UI 切片；  
- **不再**内置固废详情/台账/导出；  
- 安装显示名可与 Description「凡东智能物料验收系统V2.0」对齐（今日 iss 未对齐）。

不要把 `WeighingMatchingService` 整类搬进 `Common.Standard`，除非证明某段逻辑 **仅**标准模式需要；Recycle/固废匹配仍走内核 Service + 产品钩子（已有 Recycle Store 模式）。

## 和已拆产品的边界

| 已拆 | 与本次关系 |
|------|------------|
| `Common.Urban` | 另一产品（地磅 5001）。固废 5010 不要 DependsOn Urban。 |
| `Common.Recycle` | 共享 AttendedWeighing 与部分「固废或 Recycle」UI 条件。拆固废时 Recycle 宿主继续引用 AttendedWeighing（或抽出更小的共享称重壳），但 **去掉 SolidWaste 专用 VM/导出**。 |

## 小结

最大耦合不是缺一张固废表，而是：**一个 WinExe + 一个 AttendedWeighing 用 `WeighingMode` 开关两套产品 UI**，且 Recycle 复用了固废分支。后续分离必须按产品切程序集与宿主，而不是只改枚举 Description。
