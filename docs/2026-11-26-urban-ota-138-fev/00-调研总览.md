### E2 / E4：Gateway 有根目录、有文件，仍 404

| 请求 | 状态 |
|------|------|
| `GET /health/gateway` | 200 `Healthy` |
| `GET /updates/urban/releases.win.json` | **404** |
| `GET /updates/urban/*-full.nupkg` | **404** |
| `GET /updates/urban/RELEASES` | **404** |
| `GET /updates/urban/missing.nupkg` | 404（且非 HTML） |

启动日志确认 `OtaFeed` 根路径存在。Debug：

```text
Request starting GET /updates/urban/releases.win.json
1 candidate(s) found for the request path '/updates/urban/releases.win.json'
Endpoint 'fallback' with route pattern '/{**rest}' is valid for the request path '/updates/urban/releases.win.json'
Static files was skipped as the request already matched an endpoint.
Request finished ... 404
```

根因：YARP `fallback` 路由 `/{**rest}`（`UrbanManagement.Gateway/appsettings.json`）先匹配为 endpoint；`StaticFileMiddleware` 见已匹配 endpoint 后**跳过**，请求落到后面的 `/updates` 强制 404 中间件。

### E3：去掉 YARP 后同款静态挂载可行

最小宿主（仅 `UseStaticFiles` + `/updates` 404 中间件，无 YARP）对同一夹具：

| 请求 | 状态 |
|------|------|
| `GET /updates/urban/releases.win.json` | **200**，`Cache-Control: no-cache, no-store, must-revalidate` |
| `GET /updates/urban/missing.nupkg` | **404** |

说明夹具与 `PhysicalFileProvider` 无误；问题在 Gateway 与 YARP endpoint 的共存方式。
