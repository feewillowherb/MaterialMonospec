# 01 · FEV：Urban Velopack 发布与更新能力

- **日期**：2026-11-26
- **生命周期**：`ACTIVE`
- **知识状态**：`CONFIRMED`（本机实验）
- **FEV Verdict**：`FEASIBLE`（本地包源上的发布 → 安装 → 检查/下载 → 应用）

本篇回答用户澄清后的目标：**发布与更新能力**，不是仅探测 Gateway 静态目录。  
Aggregate 仍受 [`00-调研总览.md`](00-调研总览.md) 中 Gateway HTTP `/updates` 阻断约束：138 HTTP 包源未通前，现场不能宣称「经 um-gateway 远程更新」可行。

## 可行性问题

能否用现行 `MaterialClient.Urban` + Velopack CLI：

1. **发布**：`dotnet publish` + `vpk pack` 产出 `releases.win.json` / `*-full.nupkg` / Setup；
2. **安装**：Silent Setup 落到 Velopack 布局（`current\` + `Update.exe`）；
3. **更新**：已安装实例从包源检查到更高版本、下载校验、应用后 `current\` 变为新版本？

## Experiment

工作区：`_tmp/fev-urban-ota-publish-update/`（本地目录作 Feed，对应设计允许的 `Ota:FeedUrl` 文件夹路径）。

| 步骤 | 操作 | 观察标准 |
|------|------|----------|
| P1 | `dotnet publish` Urban `2.0.100` → `vpk pack` | 出现 `releases.win.json`、`MaterialClient.Urban-2.0.100-full.nupkg`、`*-Setup.exe` |
| P2 | Setup `--silent --installto <install>` | `install\current\`、`install\Update.exe`；`sq.version` = 2.0.100 |
| P3 | publish + `vpk pack` `2.0.101` 写入同一 `releases\` | 清单含 2.0.101；夹具 `FEV_MARKER_101.txt` |
| P4 | 在 `install\current\` 运行探针：`UpdateManager` Check + Download | `IsInstalled=True`，Current=2.0.100，Target=2.0.101，`RESULT=READY_TO_APPLY` |
| P5 | 探针 `--apply`（`ApplyUpdatesAndExit`） | `sq.version`=2.0.101；`FEV_MARKER_101.txt` 存在；exe `FileVersion=2.0.101.0` |

探针仅为 FEV 观测器（`VelopackApp.Build().Run()` + `UpdateManager`），不替代 `UrbanUpdateService`；称重空闲门禁仍以既有单元测试为准。

## Evidence

### 发布（P1 / P3）

| 产物 | 结果 |
|------|------|
| `vpk pack` 2.0.100 | exit 0；`MaterialClient.Urban-2.0.100-full.nupkg` ≈ 143.7 MB；`releases.win.json` |
| `vpk pack` 2.0.101 | exit 0；`MaterialClient.Urban-2.0.101-full.nupkg` ≈ 144.1 MB；清单 Assets 含 2.0.100 与 2.0.101 |
| Pre-process | 日志：`Verified VelopackApp.Run() in MaterialClient.Urban.Program::Main` |

### 安装（P2）

| 观察 | 结果 |
|------|------|
| Silent Setup | `Installation completed successfully!` |
| 布局 | `current\`、`packages\`、`Update.exe`、stub exe |
| `sq.version` | `<version>2.0.100</version>` |
| 安装钩子 | `--veloapp-install 2.0.100` 成功（约 840 ms） |

### 更新检查/下载（P4）

```text
IsInstalled=True
CurrentVersion=2.0.100
UpdateAvailable Target=2.0.101
Download+verify complete
RESULT=READY_TO_APPLY
```

`install\packages\` 出现 `MaterialClient.Urban-2.0.101-full.nupkg`。

### 应用（P5）

| 观察 | 结果 |
|------|------|
| `sq.version` | `<version>2.0.101</version>`，`rid=win-x64` |
| 标记文件 | `FEV_MARKER_101.txt` = `fev-update-target-2.0.101` |
| 主程序版本 | `FileVersion=2.0.101.0`，`ProductVersion=2.0.101-fev+…` |
| 副作用 | 出现同级 `install\data\`（与 Velopack `DataRoot` 外置一致） |

## Verdict

| 子问题 | Verdict |
|--------|---------|
| 发布（publish + vpk pack） | `FEASIBLE` |
| 安装（Silent Setup → Velopack 布局） | `FEASIBLE` |
| 更新（检查 / 下载 / 应用） | `FEASIBLE`（本地目录 Feed） |
| 经 138 Gateway HTTP `/updates/urban` 远程更新 | 仍为 `INFEASIBLE`（见 00：YARP fallback 抢匹配） |

**本篇 Aggregate：`FEASIBLE`。** Urban 客户端侧「打包装包 → 安装 → 升版应用」闭环在本机本地包源上成立。

未覆盖：经修好的 Gateway HTTP 拉包；真实称重空闲门禁联调；Admin 灰度控制面；回滚/闪退保护。

## 与 00 的关系

- **00**：问的是 138 Gateway 静态源可达性 → HTTP 路径 `INFEASIBLE`。
- **01**：问的是发布与更新能力本身 → 本地 Feed `FEASIBLE`。

要在 138 上宣称远程 OTA，须先修 Gateway（`Map("/updates")` 或收窄 fallback），同步宿主机 compose 的 Updates 卷，再把本篇同一套 P4/P5 指向 `http://192.168.3.138:5333/updates/urban` 复测。
