# 01 · 设计稿：Intake Parking

## 1. 目标与范围

### 1.1 目标

把「碎片需求堆积 → 挂起 → 按主题消化成 Epic → OpenSpec」标准化；采用 **`docs/intake/` + `INT-`** 命名，与 OpenSpec `proposal.md` 及 Scrum Product Backlog 区分。

### 1.2 范围内

- `docs/intake/` 的定位、字段、状态机、索引规则
- **标准 topic**：`intake-parking`（机制名）+ `theme`（条目业务主题）
- 与 BMAD / OpenSpec / GitHub Issue / `docs/YYYY-MM-DD-*` 的单向交接

### 1.3 范围外

- 本夹不创建真实 `docs/intake/` 运行时文件（落地另一步，见 §10）
- 不新建 BMAD 模块 / 不写完整 PRD
- 不做 Issue ↔ INT 全文双向自动同步

---

## 2. 问题与定位

### 2.1 为何不用 proposal / PBL

| 旧名 | 问题 |
|------|------|
| `proposal-backlog` | 易与 OpenSpec 正式 `proposal.md` 混淆 |
| `PBL` | 易与 Scrum **Product Backlog** 混淆 |
| 「提案」语义 | 实际层级在 BMAD/OpenSpec **之前**，只是种子收件 |

### 2.2 新定位（两类入口，同一收件池）

```text
A. OpenSpec / 调研衍生（技术债、一致性、安全…）
B. 挂起项目 / 日常产品碎片（先记下，消化窗口再做）
                │
                ▼
        docs/intake/          ← topic: intake-parking
        INT-001-<slug>.md
                │
        ┌───────┴────────┐
        ▼                ▼
  同 theme 收 Epic    单条够清楚
  (BMAD)              直接 /opsx:propose
        │
        ▼
  openspec/changes/
```

**原则**：Intake 只存种子；权威规划在 BMAD；权威实现在 OpenSpec；证据在 `docs/` / `SyncDoc/`。

## 3. 标准 Topic 与命名

### 3.1 机制 Topic（固定）

| 项 | 值 |
|----|-----|
| **slug** | `intake-parking` |
| **中文** | 需求收件（Intake）/ 需求堆积（Parking） |
| **目录** | `docs/intake/` |
| **条目前缀** | `INT-001` … |
| **调研夹** | `docs/2026-08-27-intake-parking/`（本夹） |
| **可选薄 skill** | `intake-register` 等；**不得**做成 BMAD 级规划流 |

### 3.2 条目 `theme`（业务主题，强制）

用途：下月 `按 theme 分组 → 一个 Epic`。

**格式**：英文 kebab-case，字母开头，≤ 48 字符。模式：`<domain>[-<facet>]`

| 示例 theme | 含义 | 消化时可能的 Epic slug |
|------------|------|------------------------|
| `xiaoshan-upload` | 萧山监管上报 | `xiaoshan-platform-upload-epic` |
| `urban-weighing` | Urban 称重桌面/链路 | `materialclient-urban-epic` |
| `gov-sync` | 政务同步 | `gov-sync-*-epic` |
| `observability` | 可观测性债 | 分散或合成 refactor epic |
| `security` | 安全债 | 通常单条或小 epic |

**规则**：同一挂起项目尽量共用 theme；细分用条目 `slug`；theme ≠ OpenSpec change 名。

### 3.3 可选挂起桶 `park`（项目级）

README 顶部登记 `park/<project-slug>`（例 `park/xiaoshan-serve`）。条目仍填业务 `theme`；`parked_until` 建议 `YYYY-MM`。

## 4. 目录与文件

```text
docs/intake/
├── README.md
├── _template.md
├── _draft-template.md
└── YYYY-MM/
    ├── README.md
    ├── drafts/
    │   ├── YYYY-MM-DD-<slug>.md
    │   └── archive/
    └── INT-001-<slug>.md
```

- **按月聚合**：路径 `docs/intake/<YYYY-MM>/INT-xxx.md`；详见 [07-按月聚合](./07-按月聚合.md)。  
- **Draft**：活跃在 `…/drafts/`；晋升后 **archive**（`drafts/archive/`）或 **delete**；详见 [08-draft](./08-draft.md)。  
- 序号全局升序；**Next ID** 写在根 `README.md`。

---

## 5. 条目字段（种子粒度）

必填：`id`（INT-00N）、`slug`、`title`、`status`、`kind`、`theme`、`intake_month`（`YYYY-MM`）、`summary`、`source`、`created`

强烈建议：`parked_until`、`repos`、`evidence`、`priority`、`depends_on`、`github`（Issue `#n`）

消化后：`absorbed_into`、`change`、`incubation`

**禁止**：完整 PRD、tasks、密钥、大段接口原文。正式 effort 只进 OpenSpec `.openspec.yaml`。

---

## 6. 状态机

```text
open → triaged → absorbed → proposed → closed
```

- **挂起月**：仅 `open` / `triaged`；禁止为记账而 propose / 空占 Epic  
- **消化窗口**：同 theme → BMAD → `absorbed` → slice propose → `proposed` / `closed`

---

## 7. 与 BMAD / OpenSpec / docs 交接

```text
证据 ──► docs/YYYY-MM-DD-* / SyncDoc/
           │ 链接
           ▼
      INT 种子（docs/intake/）
           │ 消化
           ▼
   _bmad-output/.../<epic>/
           ▼
   openspec/changes/<id>/
```

OpenSpec 衍生新债：登记 INT，不扩大当前 change。源 change 的 proposal/design 可一句回溯链接。

---

## 8. GitHub Issue 衔接（指针协作）

| 层 | 权威 |
|----|------|
| 种子摘要 + theme | **INT 文件** |
| 讨论 / 指派 / 通知 | **Issue** |

- Issue 标题：`[INT-001] 一句标题`  
- Issue body 一行：`Intake: docs/intake/<YYYY-MM>/INT-001-<slug>.md`  
- INT 字段 `github: #123`  
- Label 与 theme 对齐：`theme:xiaoshan-upload`；挂起桶 `park:xiaoshan-serve`  
- 状态仅在 `absorbed` / `proposed` / `closed` 节点对齐；PR 用 `Fixes #n` 关闭 Issue  

---

## 9. Agent 行为

**Draft**（不占 INT）：「先记一下 / 还没想清楚」→ `drafts/<YYYY-MM-DD>-<slug>.md`。

**登记 INT**：够种子或「收件」→ 写 INT；若来自 draft → 源文件 **archive** 或 **delete**（未指定默认 archive）。

步骤（INT）：读 Next ID → 复制 `_template.md` → 更新 README → 可选开 Issue。

**消化**：仅用户明确要求时升 `absorbed` / `proposed`。

**禁止**：半截聊天占用 `INT-00N`；`promoted` 草稿留在 `drafts/` 根下不处理。
