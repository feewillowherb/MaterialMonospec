# 05 · 消化手册

将挂起 INT 收成 BMAD Epic 并切入 OpenSpec 的操作清单。

## 前置

- 消化窗口已到（`parked_until` 月或用户明确要求）  
- `docs/intake/README.md` 中目标 theme 的 `open`/`triaged` 已列出（theme 定义见 `docs/intake/themes.md`）
- 可选：`gh issue list --label "theme:xiaoshan-upload" --state open`

## 步骤

### 1. 选定范围

- 按 `park/*`（整项目）或单个 `theme`  
- 导出 INT 列表：扫描 `docs/intake/YYYY-MM/` 各月文件夹，按 theme 过滤

### 2. 合并与去重

- 同义 INT → 保留一条，`closed(duplicate-of: INT-xxx)`  
- 强依赖：在 Epic slice 顺序中体现（如 INT-003 依赖 INT-002）

### 3. 开 BMAD Epic

- 走 `bmad-prd`（必要时先 brief）  
- 落点：`_bmad-output/planning-artifacts/<epic-slug>/`  
- **追溯表**（参考 `materialclient-urban-epic/epic-traceability.md`）必须列：

  | INT id | PRD 需求摘要 | OpenSpec slice（规划） |
  |--------|--------------|------------------------|
  | INT-001 | … | `add-...` |

- 相关 INT → `absorbed`，填 `absorbed_into`

### 4. 切 OpenSpec

- 每个 slice → `/opsx:propose` → `openspec/changes/<name>/`  
- INT → `proposed`，填 `change`  
- 证据链：INT → Epic PRD → change proposal（只链，不复制全文）

### 5. 收尾

- archive change 后 INT → `closed(completed)`  
- 更新 `docs/intake/README.md`  
- GitHub Issue：`Fixes #n` 关闭；label 去掉 `status:parked`

## kind 分流（粗则）

| kind | 默认路径 |
|------|----------|
| `product` | theme → Epic → 多 slice |
| `tech-debt` / `security` | 单条够清楚时可直 propose，否则进 Epic |
| `ops` / `docs` | 常单条 propose 或单独小 change |

## closed 原因

| 原因 | 说明 |
|------|------|
| `completed` | 对应 change 已 archive |
| `duplicate-of: INT-xxx` | 合并进另一条 |
| `wontfix` | 否决，孵化记录写理由 |
| `merged-into: INT-xxx` | 内容并入其他 INT 后关闭 |
