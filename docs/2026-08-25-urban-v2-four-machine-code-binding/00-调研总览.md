# Urban V2 四机器码绑定 — 调研总览

**日期**: 2026-08-25  
**范围**: 新增城管地磅授权 **V2**（新 `ProductCode`）：「1 项目 ↔ 最多 **4** 台机器码 / 最多 **4** 个场地」；**5001（V1）保持单机覆盖语义不变**  
**继承**: 沿用 [2026-08-06 双机绑定调研](./archive/2026-08-06-urban-dual-machine-code-binding/00-调研总览.md) 的槽位 / 发码选槽 / 成员校验 / 无解绑设计，将上限由 2 升为 4，并以**新产品码**落地，避免改写存量 5001 客户行为  
**结论摘要**: **可落地，跨仓主路径**；必须联动 BasePlatform（含 PublicApi）+ UrbanManagement + MaterialClient。落地规模 **XL**（约 100万+ token 量级；鉴权 + 新产品码 + 四槽 + 联调，建议按仓分会话）。

## 相对 2026-08-06 的增量

| 项 | 双机调研（已归档） | 本期 V2 |
|----|-------------------|--------|
| 产品入口 | 扩展现有 **5001** | **新增 ProductCode（Urban V2）**；5001 不改行为 |

## 已确认产品决策

| 项 | 结论 |
|----|------|
| 目标场景 | **最多 4 台同时在线称重**（非主备切换）；场地与机器码槽 **1:1** |
| 产品形态 | **新增城管授权 V2**（新 `ProductCode`）；V1（5001）仍「1 项目 ↔ 1 机器码、后激活覆盖」 |
| 槽位模型 | 项目级 **设备1…设备4**；验签由「严格相等」改为「∈ {槽1…槽4 非空集合}」；每台 JWT 仍只含本机 `machineCode` |
| 写入/换机 | **生成激活码时选择设备槽 1–4**；激活写入对应槽；槽已占用则 **覆盖该槽**；其它槽不动 |
| AccessCode / AuthEndTime | **四槽共享**同一套项目 `AccessCode` 与 `AuthEndTime` |
| 解绑 / 清空 | **不做**；换机仅通过「发对应槽位激活码 → 覆盖」 |
| 不采纳 | 改写 5001 全局行为；仅改客户端；逗号拼接塞单字段；独立解绑/清空；维持 V2 单权威全局覆盖 |

## 一句话现状（V1 / 5001）

激活时把本机机器码写入 `JC_ProductAuthority.MachineCode` 与 `GovProject.MachineCode`（覆盖写）；JWT 内嵌单一 `machineCode` claim；服务端 F4 与客户端 `StaticLicenseChecker` 均按**严格相等**校验。第二台机激活 = 第一台机被吊销。V2 用**新产品码 + 四槽成员校验**解决多场地并存，而不动 5001。
