# 01 触点清单与 UI 代价

> 知识状态：`INFERRED`（源码检索 2026-11-04；未穷尽测试与 Demo 全量）  
> 读法：先看「三层精度」，再看方案对照。

## 1. 三层精度（必须拆开）

```text
设备读数
  → [L1 采集舍入] MaterialMath.Convert*ToTon / Ton 直通
  → 入库 TotalWeight / Waybill 毛皮净（decimal，可多于 2 位）
  → [L2 领域计算] CalculatePlanWeight Round(2)、件数 Round(4)、偏差率 Round(4)
  → [L3 显示/打印] :F2 字符串、ConvertDisplayedTonToKg（先 Round 到显示位再×1000）
```

| 层 | 当前行为 | 改成「3 位」意味 |
|----|----------|------------------|
| L1 采集 | Kg/十克/百克/克 → 吨时 **`Round(..., 2)`**；`ScaleUnit.Ton` **不舍入** | Round→3 ≈ 1 kg 步长；Ton 秤 UI 才能稳定看到第 3 位 |
| L2 计算 | 计划重 **2 位**；实际件数 4 位；差值用「未同等舍入的净重 − 已 Round(2) 的计划重」 | 与显示位数对齐，或比较前统一精度；可消样例假偏差 |
| L3 显示 | 大量 `:F2` / `ToString("F2")` / `FormatString="F2"` | 机械改为 F3；**不改 L1/L2 则只改观感** |

样例假偏差链路（L2）：

1. 固废匹配兜底：`waybillQuantity ??= OrderGoodsWeight` → `6.995`  
2. `OrderPlanOnPcs = 6.995`，`MaterialUnitRate = 1`  
3. `PlanWeight = Round(6.995 × 1, 2) = 7.00`  
4. `Difference = 6.995 − 7.00 = −0.005` → `OffsetRate = −0.0714`，`OffsetResult = 超负差`  
5. 同时 `OffsetCount = 0`（件数未 Round 到与计划重同一尺度）

权威代码：

- `repos/MaterialClient/src/MaterialClient.Common/Utils/MaterialMath.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Models/MaterialCalculation.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Services/WeighingMatchingService.cs`（`TryCalculateMaterialAsync`、固废 `OrderPlanOnPcs = OrderGoodsWeight`）

## 2. L3 显示触点（MaterialClient）

### 2.1 主称重 / 进出场（用户最敏感）

| 位置 | 用法 |
|------|------|
| `AttendedWeighingViewModel` | `JoinWeightInfo` / `OutWeightInfo` / 固废 `OffsetBlockValue` 净重 → `$"{…:F2}"` |
| `AttendedWeighingMainView.axaml` | 绑定上述字符串（进场/出场块） |
| `AttendedWeighingDetailView.axaml` | `AllWeight` / `TruckWeight` / `GoodsWeight` → `StringFormat F2` |
| `AttendedWeighingWindow.axaml` / `UrbanAttendedWeighingWindow.axaml` | `CurrentWeight` → F2 |
| `UrbanAttendedListRow` | `WeightText = $"{TotalWeight:F2} 吨"` |

收料时 Join/Out 预计算：`WeighingMatchingService` 填 `JoinWeight`/`OutWeight`（来自 `OrderTotalWeight`/`OrderTruckWeight`），**不再二次 Round**；显示层 F2 负责观感。

### 2.2 表单 / 弹窗 / 列表

| 位置 | 用法 |
|------|------|
| `ManualMatchWindow` / `ManualMatchEditWindow` | 毛/皮/净、换算率、运单重 F2 |
| `ManualMatchEditWindowViewModel` | `NetWeight.ToString("F2")` 写入数量 |
| `MaterialItemRow` | 计划/实际/差值/偏差率等多处 `ToString("F2")` |
| `StandardModeFormView` / `RecycleModeFormView` | Numeric 类 `FormatString="F2"` |
| `WeighingListItemDto` | `OffsetInfo` 的 `OffsetRate:F2`；单位 `Rate:F2`（**单位换算率是否跟重量位数走要单独产品决定**） |
| `MaterialUnitDto.DisplayName` | `Rate:F2` |

### 2.3 打印 / 上传（与「显示位数」耦合）

| 位置 | 行为 |
|------|------|
| `ConvertDisplayedTonToKg` | **先 `Round(ton, 2)` 再 ×1000**；注释：与面板 F2 一致 |
| `WeighingMatchingService` 组票 | `gross/tare/net` 走 `ConvertDisplayedTonToKg` |
| `TicketPrintingService` | 票面整数 kg；依赖上一层显示对齐 |
| Urban 上传 | `ConvertTonToKg`（吨→kg **直接 Round 到整数 kg**，不先 F2）；与「显示 3 位」无自动对齐 |

改 L3→F3 而不改 `ConvertDisplayedTonToKg` → **屏显 3 位、票面仍按 2 位收 kg**，验收必踩坑。

## 3. L1 采集与「假精度」

| ScaleUnit | 入库 | UI 改 F3 的观感 |
|-----------|------|-----------------|
| Kg | `Round(kg/1000, 2)` → 步长 **0.01 t = 10 kg** | 多半 `x.xx0`，第 3 位无信息 |
| Ton | 设备值原样 | 设备给 3+ 位时 F3 有意义（样例皮重 6.045 符合此路径推断） |
| 十克/百克/克 | 各自 `/…` 后 **Round 2** | 同 Kg，F3 多为尾零 |

**UI 代价要点：** 工控员会相信屏上每一位。若 L1 仍是 2 位，强行 F3 属于产品风险，不是纯美工问题。

## 4. UI 版面与交互代价

| 项 | 评估 | 备注 |
|----|------|------|
| 大字实时重量 | 低～中 | 多 1 字符；Urban/Attended 大号 `CurrentWeight` 需目视一次防溢出 |
| 进出场信息行 | 低 | `"13.040 吨 HH:mm:ss"` 略长，现有居中块通常够 |
| 详情三列毛/皮/净 | 低 | AXAML `F2`→`F3` |
| DataGrid / 列表 | 低～中 | 列宽若写死可能挤；优先抽公共格式 |
| NumericUpDown | 中 | `FormatString` + 步进：若 Increment 仍 0.01，显示 3 位易别扭 |
| 单位 Rate 显示 | 产品决策 | 重量 3 位 ≠ 换算率必须 3 位；建议重量与 Rate **分常量** |
| 导出 Excel | 待核 | 固废导出行当前直接带 `decimal?`；Excel 客户端显示位数可能另有格式，需在 change 内点名验收 |

**缺少单一 `WeightDisplayFormat` / `WeightDecimalPlaces` 配置** → 全站改位数只能散落替换，回归面大；若做 B/C，OpenSpec 宜顺带引入**一处权威位数**（显示与 `ConvertDisplayedTonToKg` 共用），避免下次再扫全仓。此属实现建议，**未**记入「必须做技术债务」——仅当 change 明确要求时写入 proposal。

## 5. 方案对照（成本 × UI）

| | A 仅 F3 显示 | B + 计算一致 | C 端到端 0.001 t |
|--|--------------|--------------|------------------|
| 实现量 | 多文件替换 + 冒烟 | A + `MaterialMath` 策略 + 单测 | B + L1 + 小票/上传对齐 + 回归矩阵 |
| effort | **M** | **M～L** | **L** |
| UI 版面 | 小 | 小 | 小 |
| UI/业务风险 | 假精度（Kg）；假偏差仍在 | 假偏差可消；Kg 仍可能假精度 | 口径变化大；历史单不升准 |
| 推荐场景 | 仅 Ton 秤且只要「看见库里的第 3 位」 | **修样例类问题的默认首选** | 监管/结算明确要求 1 kg 吨显示 |

### 若目标只是「不要再显示成 7.00 / 不要假超负差」

不必先上全站 F3。优先选项（产品二选一即可进 OpenSpec）：

1. **比较前统一精度**：计划重与净重都 Round 到同一位数再算差；或计划重与件数精度对齐。  
2. **固废短路**：`OrderPlanOnPcs` 由净重兜底且 Rate=1 时，偏差置 0 / 不跑超差判定。  

显示仍可保持 F2，或仅对毛/皮/净用 F3（混合策略，验收要写清）。

## 6. 验收时建议覆盖的路径

- 固废收料：净重含 3 位（如 6.995）→ 屏显、列表、偏差、Waybill 入库  
- 标准模式：计划件数 × Rate → 计划重与偏差  
- Kg 秤 vs Ton 秤各一组  
- 小票 kg 与屏显一致（若动 L3/C）  
- Urban 上传后再在管理端核对（若动上传或管理端展示）
