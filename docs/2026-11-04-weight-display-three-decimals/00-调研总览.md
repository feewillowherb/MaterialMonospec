# 00 调研总览 — 重量显示 2 位 → 3 位小数：成本与 UI 代价

> 生命周期：`ACTIVE` · 知识状态：`INFERRED`（对照 2026-11-04 MaterialClient 源码与会话内 Waybill 样例；未做全仓自动化枚举回归）  
> 范围：主要 `repos/MaterialClient`；Urban 上传 / 小票 / 导出连带触及  
> **不是** OpenSpec change；本夹只做成本与 UI 代价评估。改产品行为须另开 change 并 Human `APPROVED`。

## 1. 一句话

「界面全部改成 3 位小数」**不等于**「整条重量链路变成 0.001 吨精度」。UI 文案层改动是 **M** 档可扫完的机械活；若要把采集舍入、计划重、小票 kg、与界面一致的 `ConvertDisplayedTonToKg` 一并改到 3 位，上升到 **L**，且 UI 上多出的第 3 位在 **Kg 秤** 场景常常是假精度。

## 2. 触发证据（样例）

Waybill `866676267929669`（固废收料）：

| 含义 | 库值 | 主界面 `:F2` |
|------|------|--------------|
| 进场 / 毛重 | 13.04 | 13.04 |
| 出场 / 皮重 | 6.045 | **6.05**（非 6.06） |
| 净重 | 6.995 | **7.00** |

另：`MaterialMath.CalculatePlanWeight` 对计划重 `Round(..., 2)`，在固废「计划件数=净重、Rate=1」时把 `6.995` 收成 `7.00`，制造假偏差 `-0.0714%` / 超负差。详见同夹 [`01-触点清单与UI代价.md`](01-触点清单与UI代价.md)。

## 3. 方案分层（先定范围再估成本）

| 方案 | 改什么 | 不改什么 | 能否消掉样例「假 7.00 / 假偏差」 |
|------|--------|----------|----------------------------------|
| **A. 仅显示** | AXAML / ViewModel 字符串 `:F2`→`:F3`、`FormatString` | 采集 `Round(2)`、计划重 `Round(2)`、小票按 F2 对齐的 kg | 库里本有 3 位时 UI 能看见；**Kg 秤入库已是 2 位**时 F3 只多尾零；**假偏差仍在** |
| **B. 显示 + 领域计算一致** | A + `CalculatePlanWeight`（及与净重比较的舍入策略） | 采集 / 小票 / 上传 kg 语义可不动 | 可消假偏差；显示与库更一致 |
| **C. 端到端 0.001 t** | B + `Convert*ToTon` / `ConvertDisplayedTonToKg` / 小票 / 上传与打印对齐 | 历史已入库的 2 位数据无法「补」出真实第 3 位 | 新单可达约 **1 kg** 分辨率；需产品确认 Kg↔吨与监管口径 |

**建议决策顺序：** 先确认要不要修「假偏差」（偏 B），再确认是否真要全链路 3 位（C）。不要默认「全软件 F3」= C。

## 4. 落地规模（effort-token-estimate）

| 方案 | 档位 | 约略 token | 驱动因素 |
|------|------|------------|----------|
| A 仅显示 | **M** | ~15万–40万 | 多文件 AXAML/VM 机械替换 + 主路径目视回归（Urban / Attended / Recycle） |
| B 显示+计算 | **M～L** | ~25万–50万 | A + `MaterialMath` / `MaterialCalculation` 单测 + 固废/标准偏差回归 |
| C 端到端 | **L** | ~40万–100万 | B + 采集舍入、小票 kg、Urban 上传 `ConvertTonToKg`、导出一致性；可能跨 `UrbanManagement` 展示口径 |

主仓：`MaterialClient`。C 若动服务端展示/报表，再加 `UrbanManagement` 分会话。

## 5. UI 代价（摘要）

| 维度 | 代价 | 说明 |
|------|------|------|
| 改点面 | 中 | 称重主屏、详情毛/皮/净、列表、手动匹配、NumericUpDown `FormatString`、Urban 当前重量等；字符串散落，缺统一 `WeightFormat` 常量 |
| 版面宽度 | 低～中 | 大字 `CurrentWeight`、进出场信息块多 1 位；工控屏一般可容，需防换行 / 截断 |
| 认知与假精度 | **高（若只做 A 或 Kg 秤做 C）** | Kg 秤当前 `ConvertKgToTon`→2 位 ≈ **10 kg** 步长；UI 写到 0.001 t 易让人以为有 1 kg 精度 |
| 小票 / 打印 | 中（做 C 时） | 注释写明小票 kg **对齐 UI F2**；改 F3 必须同步 `ConvertDisplayedTonToKg`，否则「屏显 ≠ 票面」 |
| 历史单 | — | 已存 2 位的记录不会因改格式变准；仅新采集/新计算受益 |

## 6. 结论表

| # | 结论 | 状态 |
|---|------|------|
| C1 | 主列表进出场/固废净重由 `:F2` 格式化，直接造成样例净重显示 7.00 | `CONFIRMED` |
| C2 | 假偏差主因是 `CalculatePlanWeight` 的 `Round(2)`，不是单纯 UI | `CONFIRMED` |
| C3 | 「只改 UI 到 F3」成本约 **M**，UI 版面代价可控，但 **不解决假偏差**，Kg 场景价值有限 | `INFERRED` |
| C4 | 端到端 3 位约 **L**，且须显式处理小票/上传 kg 与历史数据 | `INFERRED` |
| C5 | 更划算的最小修复常常是：**B 的计算舍入策略**（或固废 plan=actual 跳过偏差），不必先上全站 F3 | `INFERRED` |
