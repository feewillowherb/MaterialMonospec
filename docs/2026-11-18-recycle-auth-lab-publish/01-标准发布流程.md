## 2. PublicApi（135）

1. 用 `Publish-PublicApi.ps1` 发布。默认保留目标已有的 `appsettings*.json`。实验口这份文件是 135 的 Redis / SQL，整文件覆盖会把连接打回仓库里的其他地址。
2. 发布后确认目标 `appsettings.json` 仍有 `PublicApiServiceAuth`，且 `Enabled=true`、`ApiKey` 非空。没有就只补这一节，不要替换整份文件。密钥与 UrbanManagement 出站配置使用同一把。
3. 改配置后让站点重新加载。`IOptions` 在中间件构造时取值，只改文件不够；改动 `web.config` 触发回收。
4. 验收见第 6 节第 1 条。无密钥必须是 401。

## 3. UrbanManagement Ingest（138）

镜像和数据库是两步。

1. 有新的 EF 迁移时，用同一镜像标签构建并执行 `um-migrator`，再重建 Ingest。只 `docker compose up` Ingest 不会改表。2026-11-18 的库停在 `20261102165325_InitialSqlServer`，实体已经要 `GovProjects.ProductCode` 与 `SourceProId`（迁移 `20261117163000_AddGovProjectProductCode`）。
2. 若迁移器当次不能跑、只能手工补列：一条 `ALTER` 与后续 `UPDATE` 分成独立批次（`GO`）。同一批编译时列还不存在，会报 `Invalid column name`。补完后写入 `__EFMigrationsHistory`，避免迁移器以后再加一次。
3. 在挂载的 `appsettings.Production.json` 写入：

```json
"PublicApiServiceAuth": {
  "BaseUrl": "http://192.168.3.135:8551",
  "ApiKey": "<与 135 站点同一把>"
}
```

镜像构建会删掉 `appsettings.secret.json`。镜像内 `appsettings.json` 的 `BaseUrl` 为空时，`UrbanManagementHostingModule` 使用 `http://localhost`。`BasePlatformSync__Enabled` 只控制 GovSync，不设置这个地址。环境变量 `PublicApiServiceAuth__BaseUrl` 与 `PublicApiServiceAuth__ApiKey` 同样有效。
4. 两个 Ingest 容器都挂这份文件。改完后重启 `um-ingest` 与 `um-ingest-2`。确认容器内该文件的 BaseUrl 是 `http://192.168.3.135:8551`。

## 4. Recycle 客户端

1. `UrbanManagement:BaseUrl` = `http://192.168.3.138:5333`。指到 `http://192.168.3.135:8551` 时，`/api/urban/auth/activate` 在 PublicApi 上是 404。
2. `Jwt:PublicKey` 与 `repos/MaterialClient/src/MaterialClient.Urban/appsettings.json` 的 `Jwt:PublicKey` 相同。签发方 `iss=BasePlatform`，`aud=MaterialClient.Urban`（5020 也是这一对）。
3. 启动目录是 `.build-verify\MaterialClient.Recycle` 时，改源码旁的 `appsettings.json` 后还要同步到该输出目录。`StaticLicenseChecker` 在进程启动时读公钥，正在运行的进程要退出后重开。

## 5. 发布顺序

```
135 PublicApi 配置仍含 PublicApiServiceAuth
    → 138 迁移（um-migrator 或分批 SQL）
    → 138 Production 配置写上 BaseUrl 与 ApiKey
    → 重启两个 Ingest
    → 假码验收
    → 客户端 BaseUrl 与公钥对齐到启动目录
    → 重启客户端
    → 人用一枚未使用的 5020 码激活
```

## 6. 验收（假码）

假码示例：`{"ProductCode":5020,"Code":"probe-not-a-code","MachineCode":"PROBE"}`。

| # | 请求 | 通过时 |
|---|------|--------|
| 1 | `POST http://192.168.3.135:8551/Api/Auth/ActivateUrban`，带头 `X-Api-Key` | HTTP 200，`msg` 为「授权码无效或已使用」 |
| 2 | 同一 URL，不带头 | HTTP 401 |
| 3 | `POST http://192.168.3.138:5333/api/urban/auth/activate` | HTTP 200，同一句业务错误 |

第 3 步若是「无法连接授权服务，请稍后重试」，出站 BaseUrl 或密钥仍不对。若是「该产品请使用 GetAuthClientLicense」，Ingest 仍是只放行 5001 的旧程序。若是 HTTP 500，先看 Ingest 日志里的 SQL，不要再换真实授权码重试。

真实码只在第 6 节通过之后，由操作者在客户端输入。客户端最终应验签通过并进入称重窗。这一步截至 2026-11-18 尚未在重启后的进程上复核（`PENDING_VALIDATION`）。
