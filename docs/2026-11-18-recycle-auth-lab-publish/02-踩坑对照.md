# 02 踩坑对照 — 2026-11-18

证据：客户端 `MaterialClient.Recycle-20261118.log`，PublicApi `fdsoftlogs/all.txt`，Ingest 容器日志。日志里的密钥和 JWT 不抄进本文。

## 文案分别从哪来

| 界面或响应 | 实际含义 |
|------------|----------|
| 客户端「无法连接到授权服务器，请检查网络连接」 | `LicenseService.VerifyAuthorizationCodeAsync` 捕获异常。这是旧的 `GetAuthClientLicense` 路径 |
| 客户端「无法连接到授权服务」 | `LicenseService.ActivateOnlineAsync` 捕获异常。Recycle 激活窗走的是这条 |
| 客户端「授权公钥未配置，无法验证」 | HTTP 已成功，`StaticLicenseChecker` 没有 `Jwt:PublicKey` |
| Ingest「无法连接授权服务，请稍后重试」 | Ingest 调用 PublicApi 抛错（连不上、401、反序列化失败都会进这个 `catch`） |
| 「该产品请使用 GetAuthClientLicense」 | 产品码不是 5001 或 5020。旧 Ingest 只放行 5001 时，5020 也会得到这一句，而且请求还没到 135 |
| HTTP 200「授权码无效或已使用」 | 链路通，码不存在或已被删 |
| HTTP 500，PublicApi 日志已有「JWT 令牌已生成」 | 签发成功，Ingest 本地回写失败。码已经作废 |

## 配置落点

| 现象 | 原因 |
|------|------|
| 客户端请求打到 `http://192.168.3.135:8551/api/urban/auth/activate` 并得到 404 | `UrbanManagement:BaseUrl` 指到了 PublicApi。该路由只在 Ingest |
| Ingest 日志是 `Connection refused (localhost:80)` | 容器内 `PublicApiServiceAuth:BaseUrl` 为空。138 到 135 的 TCP 是通的 |
| 仓库里的 ApiKey 调 8551 得到 401，部署文件里密钥长度为 0 | 站点 `appsettings.json` 没有 `PublicApiServiceAuth` 节。`Enabled` 默认 true，空密钥比较失败 |
| 只改 135 的 json，中间件仍用旧密钥 | 回收应用程序池或改 `web.config` 让进程重启 |
| 假码已经 200，真实码 500，`Invalid column name 'ProductCode'` | 新 Ingest 对旧库。`GetAsync` 查询 `GovProjects` 失败。缺的还有 `SourceProId` |
| 同一条 SQL 脚本里 `ALTER` 后立刻 `UPDATE` 新列 | SQL Server 整批编译，列尚未提交。用 `GO` 拆开 |
| 源码 `appsettings.json` 已有公钥，运行中的程序仍报未配置 | 启动目录是 `.build-verify`，且公钥只在构造函数读一次 |

## 一次性授权码

`AuthController.ActivateUrban` 在回写数据库和签发 JWT 之前执行 `RedisHelper.Del`。Ingest 随后在 `TrySyncGovProjectAsync` 失败时，异常在 `catch` 之外，控制器变成 HTTP 500。客户端拿不到 JWT，码也不能再用。

因此：探测只用假码；看到 PublicApi 已签发之后，换一枚新的 5020 码，不要对同一枚码反复提交。
