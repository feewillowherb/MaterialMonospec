## G. 完成语义抽检

| 检查 | 期望 |
|------|------|
| tasks 全勾 | 只说明变更文件做完，不足以宣称 Capability 交付 |
| Pipeline PASS | 不足以改产品行为（须 Human `APPROVED` + OpenSpec） |
| 日常 OpenSpec propose | 不先等 Pipeline `APPROVED` |
| FEV `FEASIBLE` | 不等于 ICD `PASS`；也不取消 Promotion 人闸 |
| 会话快照写入 DOCS | 不等于 `CONFIRMED` |
| Pipeline P0–P3 | cook 刻度。不得自评为产品通过，不得换算成 ICD 等级 |
| ICD L1–L4 | 仅在有对应 Evidence 时按定义声称。L3 = 声明的能力已完整可用 |
| `guess-governance` L1–L3 | 需求风险刻度。L3 = 计费 / 合规 / 不可逆，禁止凭猜测实现 |
| Agent 自评 cook 为产品通过 | 禁止 |

## H. 禁拷 / 禁写

| 项 | 原因 |
|----|------|
| 目标业务模块方案、业务 Graph 业务逻辑、现场配置 | 超出元系统设计范围 |
| 改写本仓技术栈（产品语言与框架、Node.js cook 实现、子仓架构） | 本次只升级 Monospec |
| BlenderTools 技术栈：Python cook、DCC / 游戏引擎 / 专用脚本宿主、并行 lease、DCC Context / Socket 必填 | 属于来源仓技术栈，不是要升级进来的 Monospec 设计 |
| 把 CED / DOCS 标成 Established | 来源仍为 PENDING，本仓不得升格 |
| 整份 CED Default Continue | 与显式 commit、挂起、高风险停止冲突 |
| 自动 commit MUST 政策 | 与本仓协作习惯冲突 |
| 第二份 Blocker Local Policy | 外壳权威已是 `strategic-fallback` |
| 在 CLI 没有 `openspec create` 时仍把该命令写成唯一入口 | 本机 CLI 1.3.1 的创建命令是 `openspec new change` |
| 未决议即替换 `strategic-fallback` 防守语义 | 可能丢失显式挂起约定 |
| 真实 secrets / `.local` 凭证内容 | 敏感 |
