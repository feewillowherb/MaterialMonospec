# 01 — 先进设计对照

> 对照来源是 **BlenderTools-MonoSpecs** 的 Monospec。本仓技术栈不改。不迁入 BlenderTools 的 Python cook、DCC / 引擎域约定。  
> 2026-11-02 审查：按来源成熟度裁剪引入范围。来源状态不得在本仓升格。

## 1. 已对齐的基础（不要回退）

| 能力 | 说明 |
|------|------|
| Monospec 宿主模型 | OpenSpec / docs / pipelines 在主仓；业务代码在 `repos/` |
| `AGENTS.md` 为约定入口 | 专业目录用 `AGENTS.md`，不用 README 当契约（`agents-md-only`） |
| OpenSpec 工作流 | `openspec new change` → `openspec/changes/<name>/` → apply → archive。本机 CLI 1.3.1 没有 `openspec create` |
| Pipeline 哲学 | 先落工件再 cook；密钥不进仓；`runs/` 不覆盖；cook 结果不得自评为产品通过 |
| Graph 布局与选型 | `pipelines/graphs/<domain>/<slug>/`；family 为 `observe \| ingest \| probe \| reconcile \| transform`；`config.yaml` 的 `graph.*`；同一 `goal` 互斥 |
| 日期调研夹 | `docs/<YYYY-MM-DD>-<topic>/` + `00-调研总览.md` |
| BMAD 存在 | `_bmad/`、`_bmad-output/`；`docs/AGENTS.md` 场景路由 |
| 根上的硬约束摘要 | 禁止 tuple、禁止数据库外键、界面层不碰 Repository、effort 只进 `.openspec.yaml`。瘦身时保留 |

## 2. 本仓技术栈与编排优势（内容不变）

产品语言、框架、Node.js cook、子仓架构保持现状。下表是升级 BlenderTools Monospec 时继续沿用的本仓编排能力。

| 能力 | 落点 |
|------|------|
| Intake Parking | `traits/intake-parking-trait.md`、`docs/intake/` |
| Effort 按 token 档 | `traits/effort-token-estimate-trait.md` |
| OpenSpec Git 工作流 | `traits/openspec-git-workflow.md` |
| 既有编码 / UI 类 traits | 保持现状，不因本次升级替换 |
| 猜测治理 | `traits/guess-governance-trait.md`。管需求假设、Guess Risk、一 change 一交付档 |
| 策略性挂起 | `traits/strategic-fallback-trait.md`。管禁止伪实现与三选一防守外壳 |
| 提案表达指南 | `PROPOSAL_DESIGN_GUIDELINES.md` |
| Node.js cook | 本仓 cook runtime 保持 **Node.js**（`pipelines/AGENTS.md` §4：复杂 cook 用 TypeScript / `pnpm exec tsx`，短探针可用 `.mjs`）。这是技术栈，不随 Monospec 升级改写 |

## 3. 应对齐的模式（按优先级与成熟度）

成熟度取自 BlenderTools-MonoSpecs 对应 trait 在审查日的状态。本仓落地文件单独标状态，不得把 PENDING 写成 Established。

### P0 — 可以引入的判别

| 模式 | 来源状态 | 本仓引入切片 |
|------|----------|----------------|
| **ICD** | Established 1.0.0 | Capability 是交付单位；**Task 勾完 ≠ Capability 交付**；验收先于「写完了」 |
| **FEV** | Proposed 1.2.0 | Unknown → Experiment → Evidence → Verdict。「看起来能做」与「证据上可行」分离。不引入并行 Sub-FEV、resource lease、并行协调器 |
| **`openspec/AGENTS.md`** | 本仓缺失 | 归档不可变；Pipeline / DOCS 结论进入产品行为前须 Human `APPROVED`。日常 propose 不先等这道人闸。CLI 写法与本仓根约定一致 |
| **Trait discovery map** | 可直接采用 | Trigger → MUST 读全文；Local Policy 只能加强/收窄 |

### P0 — 只引入收窄版

| 模式 | 来源状态 | 本仓引入切片 |
|------|----------|----------------|
| **CED** | PENDING 0.9.0 | 显式 STOP / Defer。仅在用户已授权的 Epic 内，继续下一步独立且可逆的工作。不授权 commit、push、生产变更，也不覆盖 `strategic-fallback` 或 `guess-governance` 的高风险停止 |
| **完成语义接线** | 本仓根约定仍写「任务勾完即可归档」 | 勾选只说明变更文件做完；Capability 交付另要 Acceptance 证据。改根 `AGENTS.md` 的归档句，避免子树契约被根规则盖住 |

### P0 — Pipeline 机器可读契约（语义层，不换模型）

| 模式 | 本仓引入切片 |
|------|----------------|
| **`pipelines-trait.md`** | Contract、Run identity、Evidence、Acceptance 的解释层。Local Policy 对齐本仓 family、`config.yaml` 与 Node.js cook |
| **`contract.yaml`** | 把 `pipeline.md` / `config.yaml` 里已经写明的输入、输出、不变量写成可机读形式 |
| **稳定 Run identity** | DOCS / OpenSpec 引用 Run 用稳定身份 |
| **cook 前读契约** | 去重 + 读 contract / pipeline / config |
| **刻度隔离** | Pipeline Acceptance 用 **P0–P3**。ICD 用 **L1–L4**。`guess-governance` 用自己的 **L1–L3**（L3 = 计费 / 合规 / 不可逆，禁止凭猜测实现）。三套刻度不互相推导 |

现有「Agent 不得宣布 L3 通过」在刻度拆开之前，只表示 cook 结果不得自评为产品通过。它不禁止在已有 Evidence 时按 ICD 定义声称 L3。

### P1 — DOCS 卫生

来源 DOCS trait 为 PENDING 0.10.0。放在 Phase 2。`docs/AGENTS.md` 是 Local Policy，持有 BMAD 路由表。

| 模式 | 是什么 |
|------|--------|
| **`topic.yaml`** | 每 Topic：`topic` / `created` / `updated` |
| **Topic read contract** | 先读唯一 `00-*.md`；会话快照 ≠ `CONFIRMED` |
| **knowledge state** | `CONFIRMED` / `INFERRED` / `UNKNOWN` / `PENDING_VALIDATION` |
| **lifecycle** | `ACTIVE` / `STALE` / `SUPERSEDED` / `HISTORICAL` |
| **可选 CI 校验** | 新 Topic 结构与链接；legacy 用 baseline 豁免 |
| **`scripts/AGENTS.md`** | 根 scripts 边界 vs Graph 内 cook 脚本 |

### P1 — 仓库人体工程学

| 模式 | 是什么 |
|------|--------|
| 根 `AGENTS.md` 「Where things are」 | 跨树薄入口；重复的流程长文下沉子树。硬约束摘要留在根上 |
| **`openspec/project.md`** | 本仓产品锚点：子仓与用途、权威边界。无密钥。不把本仓产品身份抹成空锚点 |
| **可选 `repos-meta/`** | 不依赖 `repos/` 检出即可读子仓 Agent 摘要 |
| **可选 `bootstrap/`** | 可移植模板；导入时手工 merge |

### P2 — 辅助

| 模式 | 说明 |
|------|------|
| `technology-first-trait` | 多方案默认选型；未证明回 FEV。不得重开已写定的 Node.js cook |
| `bmad-trait` | 可晚做。不替代 `docs/AGENTS.md` 的场景路由，也不另立一套流程替代 OpenSpec |
| 技术文风 trait | 骨架自然语言 + 标识符/域词保留原文 |
| Domain 级 `graphs/<domain>/AGENTS.md` | 索引补齐（只列编排元数据，不写业务方案） |

## 4. 缺口映射

| 模式 | 现状 | 严重度 |
|------|------|--------|
| ICD：Task ≠ Capability | 根 `AGENTS.md` 仍写任务勾完即可归档 | Critical |
| 三套 L 命名空间 | Pipeline / ICD / `guess-governance` 未拆 | Critical |
| `openspec/AGENTS.md` | 缺失 | Critical |
| FEV 核心环 | 缺失。并行 lease 不在缺口内 | High |
| CED 收窄版 | 缺失。整份 Default Continue 与本仓停止条件冲突 | High |
| IWE skill | 缺失。本仓 FEV/ICD/CED 可读后再装 | High |
| Human Promotion `APPROVED` | 未成文。范围只限 Pipeline / DOCS → 产品行为 | High |
| OpenSpec CLI | 已安装 CLI 1.3.1 的命令是 `openspec new change` | 已对齐 |
| `contract.yaml` + Run identity | 无契约文件。family 与 `graph.*` 已存在 | High |
| DOCS knowledge state / `topic.yaml` | 未全面强制（本夹已示范 `topic.yaml`） | Medium |
| docs 校验自动化 | 缺失 | Medium |
| 根 AGENTS 过长 | 可下沉重复流程；硬约束摘要保留 | Medium |
| `repos-meta` / `bootstrap` | 缺失 | Low |
| Agent 自动 commit | 本仓为显式 commit | **不引入** |

## 5. 刻意排除

- 改写本仓技术栈（产品语言与框架、Node.js cook 实现、子仓架构）
- 任何目标业务模块、业务 Graph 实例、业务协议与现场配置
- BlenderTools 的技术栈：Python cook、DCC / 游戏引擎 / 三维宿主 / 专用脚本运行时
- 并行 Sub-FEV、resource lease、并行协调器
- 以 Socket / Wire / Context 作为现有 Graph 的必填模型
- 把来源 CED / DOCS 的 PENDING 标成 Established
- 再抄一份 Blocker Local Policy（外壳以 `strategic-fallback` 为准）
- 在 CLI 仍提供 `openspec create` 时改用另一套不存在的命令。当前 CLI 没有该命令，故使用 `openspec new change`
- 密钥、token、密码、连接串、个人联系方式、本机私有路径
- 用 BlenderTools 的域实践覆盖本仓 Intake / openspec-git / 既有编码 traits / Node.js cook / 根硬约束摘要
