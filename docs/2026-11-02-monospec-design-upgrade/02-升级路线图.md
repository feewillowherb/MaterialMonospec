# 02 — 升级路线图

> 主要变更：本仓 Monospec 升级为 **BlenderTools-MonoSpecs** 的 Monospec。本仓技术栈内容不变。  
> 不迁入 BlenderTools 的 Python cook、DCC / 引擎域约定，不改业务 Graph 实现。  
> 2026-11-02 审查：Phase 0 补齐冲突决议；Phase 1 / 3 改为裁剪引入。档位按裁剪改写估算，不按整文件复制估算。

## Phase 依赖

```text
Phase 0 政策决议（含归档 / 刻度 / CED / CLI）
    │
    ▼
Phase 1 裁剪后的权威栈 + openspec/AGENTS
    │     契约可读后再装 IWE
    ├──────────────┐
    ▼              ▼
Phase 2 DOCS     Phase 3 Pipeline Contract
 topic/CI          acceptance/evidence
    │              │
    └──────┬───────┘
           ▼
     Phase 4 可移植与抛光
```

Effort 参考（见 `traits/effort-token-estimate-trait.md`）：

| Phase | 档位 | 说明 |
|-------|------|------|
| 0 | S | 决议与根 AGENTS 短补丁 |
| 1 | L | 裁剪后的 traits + openspec 子树 + IWE |
| 2 | M | docs 语义 + topic.yaml + 可选 CI |
| 3 | L | 契约/证据/验收语义、试点 contract、evidence 辅助 |
| 4 | M | 可选 repos-meta / bootstrap / 辅助 traits |

整文件复制会把 Phase 1 / 3 的名义工作量看小，后续冲突成本看大。上表按裁剪改写计。

## Phase 0 — 政策决议

**落点**：本夹 + 根 `AGENTS.md` 短声明（可选 change：`add-monospec-authority-stack`）

| # | 决议 | 默认建议 |
|---|------|----------|
| 0 | 变更性质 | **只升级 Monospec**，对齐 BlenderTools-MonoSpecs。本仓技术栈内容不变：产品语言与框架、Node.js cook、子仓架构 |
| 1 | `strategic-fallback` 与 FEV / CED | **保留** `strategic-fallback` 作为禁止伪实现与三选一外壳的权威。FEV 管可行性结论。CED 只管已授权 Epic 内的显式 STOP / Defer。不把 BlenderTools 的 Blocker Local Policy 再抄一份 |
| 2 | Agent 自动 commit | **不导入** BlenderTools 的自动 commit。仅用户明确要求时 commit。`APPROVED` 不授权 commit 或 push |
| 3 | cook runtime | **保持 Node.js**（`pipelines/AGENTS.md` §4）。Monospec 只增加契约 / 证据 / 验收语义，不改 cook 实现，也不改成 BlenderTools 的 Python cook |
| 4 | BMAD | **保留** `docs/AGENTS.md` 为场景路由。`bmad-trait` 放到 Phase 4，且不替代该路由，也不替代 OpenSpec |
| 5 | 归档门槛 | 任务勾选只说明变更文件做完。Capability 交付另要 Acceptance 证据。改根 `AGENTS.md`「归档前确认所有任务已完成」。`commit_when_archive` 仍只提交 specs，不把勾选变成交付声明 |
| 6 | 三套刻度 | Pipeline Acceptance = **P0–P3**。ICD = **L1–L4**。`guess-governance` = 需求风险 **L1–L3**。三者不互推。现有「不得宣布 L3」在改名完成前只约束 cook 结果不得自评为产品通过 |
| 7 | CED 继续边界 | 仅在用户已授权的 Epic 内继续下一步独立、可逆的工作。不授权 commit、push、生产变更。`strategic-fallback` 已触发或 `guess-governance` 判定高风险时停止 |
| 8 | OpenSpec CLI | 本机 CLI 1.3.1 没有 `openspec create`。Agent 命令使用实际存在的 `openspec new change`。这是本仓 CLI，不是另换一套工具 |
| 9 | 根 `AGENTS.md` 瘦身 | 增加「Where things are」，下沉重复流程长文。**保留**硬约束摘要：禁止 tuple、禁止数据库外键、界面层不碰 Repository、effort 只进 `.openspec.yaml` |

Human `APPROVED` 只挡 Pipeline / DOCS 结论进入产品行为。日常 OpenSpec propose 不先等这道人闸。FEV 对可行性实验「取消默认人工批阅」不得写成 Promotion 也可以免人闸。

## Phase 1 — 权威栈与 OpenSpec 子树

完成标准是本仓裁剪版契约可读，不是来源文件原样落盘。

| 动作 | 落点 |
|------|------|
| 引入 FEV 核心环 | `traits/fev-trait.md`。只写 Unknown → Experiment → Evidence → Verdict。不写并行 Sub-FEV、resource lease、并行协调器。状态不得高于实际采用的切片 |
| 引入 ICD | `traits/icd-trait.md`。Task 完成 ≠ Capability 交付 |
| 引入 CED 收窄版 | `traits/ced-trait.md`。状态保持 PENDING，直到继续边界在本仓验证。不写 Default Continue 为总原则 |
| 更新 discovery | `traits/AGENTS.md`。不弱化既有编码 traits、`guess-governance`、`strategic-fallback` |
| 创建 `openspec/AGENTS.md` | 归档不可变；Promotion 范围见 Phase 0；链到 `openspec-git-workflow`；命令用 `openspec new change`。外壳仍指向 `strategic-fallback`，不另写一套 Pattern A/B/C |
| 增加 `openspec/project.md` | 本仓子仓、用途与权威边界。无密钥。保留本仓产品身份 |
| 根 `AGENTS.md` | 「Where things are」+ 调查/验收 Required traits + 修订后的归档句。硬约束摘要保留 |
| 安装 IWE | 上列 FEV/ICD/CED 可读之后，再装 `.agents/skills/investigate-with-evidence/`。契约缺失时不得发明 Verdict，也不得自动安装整套框架 |
| 成文 Promotion | `openspec/AGENTS.md` + `docs/AGENTS.md` handoff：Pipeline PASS 不足以改产品行为 |

建议 change 名：`add-monospec-feicd-authority`。

DOCS trait 不放在本阶段标成 Established。知识层语义见 Phase 2。

## Phase 3 — Pipeline 契约与证据

| 动作 | 落点 |
|------|------|
| `traits/pipelines-trait.md` | Contract、Run identity、Evidence、Acceptance。写明 P0–P3 与 ICD L1–L4、`guess-governance` L1–L3 不互推。Local Policy 对齐本仓 family、`graph.*` 与 Node.js cook。不把 Socket / Wire / Context 写成现有 Graph 必填 |
| 试点 `contract.yaml` | 两条已有 Graph：一条 `observe`，一条 `probe` 或 `reconcile`。接口已经写在 `pipeline.md` / `config.yaml`。不新增密钥字段，不改变 cook 行为。只把已写明的不变量与接口形状机器化 |
| 补齐 `acceptance.md` | 试点 Graph 的可执行验收项，使用 P0–P3 |
| 共享 evidence 辅助 | `pipelines/_shared/` 最小 manifest 约定 |
| cook 前读契约 | 命令或 skill 文档 |
| Domain `AGENTS.md` | 仅索引与编排约定 |
| `scripts/AGENTS.md` | 根脚本 vs Graph 脚本边界 |
| `pipelines/AGENTS.md` | 增加 handoff / Run identity 段，不删现有选型表与 family 词表 |

**不要导入**：BlenderTools 技术栈及其域专用机制（Python cook、会话隔离、资产 capture、并行租约、DCC Context 必填）。本仓 Node.js cook 与 Graph 实现保持原样（除非本仓已出现对应编排冲突）。

## 升级后推荐衔接

```text
不确定 / 需证据
  → 本仓 FEV / ICD / CED 已可读后，IWE 组织执行
  → FEV 出 Verdict（核心环）
  → DOCS 落可复用结论（带 knowledge state）
  →（可选）Pipeline cook → Run（P0–P3）
  → 仅当结论要进入产品行为：Human APPROVED
  → OpenSpec propose / apply（ICD 判 Capability）
  → 已授权 Epic 内：CED 只决定显式 STOP / Defer
```

遇阻且触发防守条件时，走 `strategic-fallback`，不把挂起改写成继续。

Intake 仍位于 OpenSpec / BMAD **之前**；不因 FEV 取消 `docs/intake/`。
