# 00 — 调研总览：ITruckScaleWeightService × TransmissionFormatType 重构

日期：2026-09-15  
仓：MaterialClient（initiative 基线 `dev-truck-scale-weight`）  
状态：讨论稿（未 propose）

## 一句话

把地磅串口解析从「巨型 `TruckScaleWeightService` 内 if/switch」改为 **`ScaleType × TransmissionFormatType` 隔离**；新增 `TransmissionFormatType`（tf0 / tf1）；**仅耀华实现 tf1**，其余设备在 tf1 路径明确返回不支持。

## 背景与现状缺陷

| 现象 | 证据 |
|------|------|
| 无协议隔离 | `TruckScaleWeightService.cs`（~1300 行）内混合 Yaohua / DingSong / DingSongAddr4 / PortableXPSY / TestMode |
| 配置未真正驱动协议 | `ScaleSettings.CommunicationMethod` 默认 `"TF0"`，设置页可改；服务层几乎不按该字段分支，只按 `ScaleType` + 内部 `ReceType` |
| tf0 / tf1 语义散落在 Demo | Demo 有 `YaohuaTf0WeightWindow` / `YaohuaTf1WeightWindow`；生产服务未正式建模 tF |
| 扩展成本高 | 新仪表或新通讯方式继续堆进同一类，易互相踩帧缓冲 / 锁 / 解析 |

参考：

- `repos/MaterialClient/src/MaterialClient.Common/Services/Hardware/TruckScaleWeightService.cs`
- `repos/MaterialClient/src/MaterialClient.Common/Configuration/ScaleSettings.cs`
- `docs/Device/耀华地磅仪表_tF模式与全功能重量获取分析报告.md`
- OpenSpec Demo：`openspec/changes/add-demo-yaohua-tf0-weight-display/`（只 Demo，不改生产服务）

## 用户目标（本讨论范围）

1. **重构** `ITruckScaleWeightService`：代码隔离（按设备类型 × 传输格式）。
2. **新增枚举** `TransmissionFormatType`（`TransmissionFormat` + `Type` 后缀）：
   - `TransmissionFormatType0 = 0`，`[Description("(tF0)")]`（连续发送 / 现网主流）
   - `TransmissionFormatType1 = 1`，`[Description("(tF1)")]`（生产耀华：**连续查询听流，不向设备发查询命令**；非 Demo 指令轮询）
3. **所有 `ScaleType` 都具备 tf0 / tf1 对应入口**（编译期隔离，禁止「隐式共用解析」）。
4. **仅 `ScaleType.Yaohua` 实现 tf1**（连续查询）；其它设备（**含 `TestMode`**）选 tf1：**UI 不让选** + 协议 **抛不支持异常**。
5. 保持 `ITruckScaleWeightService` 对外契约对称重业务尽量稳定（`WeightUpdates` / `InitializeAsync` 等），内部可替换。
