# 03 — 旧通讯方式停用，改用 TransmissionFormatType

本文约定：**停用** `ScaleSettings.CommunicationMethod`，**只使用**新枚举字段 `TransmissionFormatType`；默认值为 **tf0**（`TransmissionFormatType0`）。**不**再读取、映射或依赖旧字段里的字符串值。

## 1. 决策（已拍板）

| 项 | 结论 |
|----|------|
| 权威字段 | 仅 `TransmissionFormatType` |
| 默认值 | `TransmissionFormatType.TransmissionFormatType0`（Description `(tF0)`） |
| 旧字段 `CommunicationMethod` | **停用**：从模型 / **UI** / 业务分支移除 |
| 设置页「通讯方式」 | **选择项**，绑定 `TransmissionFormatType`；**禁止**再绑 `CommunicationMethod` 文本框 |
| 是否用旧 JSON 里的 `TF0`/`TF1` 赋值 | **否**；忽略旧属性，一律走枚举默认或用户新选的值 |
| 升级后未改设置的机器 | 反序列化后得到 **tf0**（缺省或忽略旧键），与现网主流一致 |

## 2. 模型目标形态

```csharp
public class ScaleSettings
{
    public string SerialPort { get; set; } = "COM3";
    public string BaudRate { get; set; } = "9600";

    /// <summary>通讯格式。默认 tf0。</summary>
    public TransmissionFormatType TransmissionFormatType { get; set; }
        = TransmissionFormatType.TransmissionFormatType0;

    public ScaleUnit ScaleUnit { get; set; } = ScaleUnit.Kg;
    public ScaleType ScaleType { get; set; } = ScaleType.Yaohua;

    public bool IsValid() =>
        !string.IsNullOrWhiteSpace(SerialPort) &&
        !string.IsNullOrWhiteSpace(BaudRate);
}
```

- **删除**（或不再序列化）`CommunicationMethod`。
- **不需要** `TransmissionFormatTypeWire.FromLegacy` 读旧串；业务只认枚举。

## 3. 与旧盘 JSON 的关系

现网 `ScaleSettingsJson` 里可能仍带：

```json
{
  "SerialPort": "COM3",
  "BaudRate": "9600",
  "CommunicationMethod": "TF0",
  "ScaleUnit": 0,
  "ScaleType": 0
}
```

`System.Text.Json` 默认会**忽略未知属性**。属性从类型上删除后：

1. 反序列化时 `CommunicationMethod` 键被忽略。
2. JSON 中若无 `TransmissionFormatType`，属性保持 CLR 默认 → **`TransmissionFormatType0`**。
3. 不解析、不拷贝旧字符串，也**不做** `"TF1" → TransmissionFormatType1` 映射。

因此：即使用户以前把通讯方式写成非 `TF0`，升级后也会回到 **默认 tf0**，不再沿用旧旁路语义。

### 刻意不做的事

| 不做 | 原因 |
|------|------|
| 双写 `CommunicationMethod` | 已决定停用旧字段 |
| 读旧值填充枚举 | 明确「不需要使用旧字段值」 |
| 为旧 `"TF1"` 自动切真 tf1 | 旧 TF1 本就不是指令模式；避免静默改行为 |

若现场曾依赖「非 TF0 ⇒ String/`=`」旁路：升级后应靠正确的 `ScaleType`（如 PortableXPSY）或显式在设置页选择格式，而不是旧字符串。

## 4. 首次保存后的盘形态

用户打开设置并保存一次后，JSON 应为：

```json
{
  "SerialPort": "COM3",
  "BaudRate": "9600",
  "TransmissionFormatType": 0,
  "ScaleUnit": 0,
  "ScaleType": 0
}
```

（枚举也可序列化为名字，以项目现有 `JsonSerializer` 选项为准；数值 `0`/`1` 即可。）

旧键 `CommunicationMethod` 会在重写整段 `ScaleSettingsJson` 时自然消失。

## 5. UI：通讯方式改为 TransmissionFormatType 选择项

### 5.1 已拍板

| 项 | 结论 |
|----|------|
| UI 是否再绑定 `CommunicationMethod` | **否**；控件、ViewModel、文案均不再出现该字段 |
| 通讯方式控件 | **选择项**（`ComboBox` / 等价下拉），绑定 **`TransmissionFormatType`** |
| 选项展示 | 枚举 `[Description]`：`(tF0)`、`(tF1)` |
| 默认选中 | `TransmissionFormatType0` |
| 选项范围 | **仅耀华**列出/启用 `(tF1)`；其它 `ScaleType`（**含 TestMode**）不出现或禁用 Format1 |
| 绕过 UI | 非耀华 × tf1 → 协议 **抛不支持异常**（见 [01 §4.3](01-修改方案讨论.md)） |

### 5.2 现状 → 目标

| 现状 | 目标 |
|------|------|
| `SettingsWindow.axaml`：`TextBox` + `ScaleCommunicationMethod`，Watermark=`TF0` | `ComboBox`（或项目内统一选择控件），`Items` = `TransmissionFormatType` 枚举项 |
| `SettingsWindowViewModel`：`string _scaleCommunicationMethod` | `TransmissionFormatType ScaleTransmissionFormatType`（或同名属性），Load/Save 读写 `ScaleSettings.TransmissionFormatType` |
| 保存：`CommunicationMethod = ScaleCommunicationMethod` | `TransmissionFormatType = ScaleTransmissionFormatType`；**无**字符串赋值 |

### 5.3 绑定示意（非定稿 AXAML）

```xml
<!-- 通讯方式：选择 TransmissionFormatType，禁止自由文本 -->
<ComboBox ItemsSource="{Binding TransmissionFormatTypeOptions}"
          SelectedItem="{Binding ScaleTransmissionFormatType}"
          ... />
```

ViewModel 侧选项可来自：

```csharp
public IReadOnlyList<TransmissionFormatType> TransmissionFormatTypeOptions { get; } =
[
    TransmissionFormatType.TransmissionFormatType0,
    TransmissionFormatType.TransmissionFormatType1
];
```

显示文本用现有 Description 转换器（与 `ScaleType` 下拉同一套），保证界面看到 `(tF0)` / `(tF1)`。

### 5.4 其它调用点

| 位置 | 处理 |
|------|------|
| `TruckScaleWeightService` | 删除 `== "TF0"`；改为比较 `TransmissionFormatType` |
| 配置相等判断 | 用 `TransmissionFormatType`，不再比 `CommunicationMethod` |
| 测试 | 构造 `ScaleSettings` 时设枚举；UI 测试断言为选择项而非 TextBox |

## 6. 行为对照（升级瞬间）

| 升级前旧盘 | 升级后内存 | Initialize 期望 |
|------------|------------|-----------------|
| 无 ScaleSettings / 空 JSON | Format0 | 与默认 TF0 Hex 主流路径一致 |
| 仅有 `"CommunicationMethod":"TF0"` | Format0（忽略旧键） | 同 tf0 |
| 仅有 `"CommunicationMethod":"TF1"` 或其它 | Format0（**不**沿用旧值） | tf0；不再走旧 String 旁路 |
| 已有 `"TransmissionFormatType":1`（新版本写过）且 ScaleType=Yaohua | Format1 | 耀华 tf1 |
| 已有 Format1 但 ScaleType≠Yaohua（含 TestMode） | 仍可读出 Format1 | **UI 不应让选**；Initialize/协议 **抛不支持** |

## 7. 测试要点

| # | 输入 | 期望 |
|---|------|------|
| T1 | 旧 JSON 仅 `CommunicationMethod` | `TransmissionFormatType == TransmissionFormatType0` |
| T2 | 无通讯相关字段 | 默认 Format0 |
| T3 | `"TransmissionFormatType": 1` | Format1 |
| T4 | 保存往返 | JSON **无** `CommunicationMethod`，有 `TransmissionFormatType` |
| T5 | 业务 / UI 代码 | **无** `CommunicationMethod` / `ScaleCommunicationMethod` 引用 |
| T6 | 设置页通讯方式 | 选择项；默认 `(tF0)`；**非耀华/TestMode 不可选 `(tF1)`** |
| T7 | 非耀华 + Format1 调协议 | **抛不支持异常** |

## 8. 小结

- **停用旧字段，只用新枚举。**
- **默认 tf0，不读旧字段值。**
- **UI 通讯方式 = `TransmissionFormatType` 选择项**；**仅耀华可选 `(tF1)`**，TestMode 及其它非耀华不可选。
- 非耀华 × tf1：协议入口存在，**抛不支持异常**。
- 旧盘靠「忽略未知属性 + CLR 默认」落到 tf0；真 tf1 仅耀华用户显式选择。
