# Recycle Web 持久化 FEV

知识状态：`PENDING_VALIDATION`。Verdict 只判断这条接入是否可行，不是 Capability 交付。

## 问题

`UrbanManagement.Recycle` 去掉内存 mock 后，车辆、称重和合同能否写入 `Recycle*` 表，并在进程重启后仍能读回？请求体里的项目标识能否被忽略？

## 实验

- 环境：`ASPNETCORE_ENVIRONMENT=Testing`，本机 LocalDB `UrbanManagement`。`Testing` 跳过 5041 SSO，用来打业务接口。
- 绑定：`RecyclePersistence:BoundSourceProId=50200000-0000-4000-8000-000000000020`，对应 `GovProjects` 中产品码 5020 的 `SourceProId`。
- 请求体另带了一个不同的 `sourceProId`。

## 证据

| 操作 | 观察 |
|------|------|
| `POST /api/vehicles`，皮重 1234.5 kg | 返回 `tareWeightKg=1234.5`，`tareWeight=1.2345` |
| 重启进程后再 `GET /api/vehicles` | 同一 Guid `742bc2bd-8707-44ab-831d-7ce20445c96f` 仍在 |
| 库中 `RecycleVehicles.ProId` | `50200000-0000-4000-8000-000000000020`，不是请求体里的另一个 Guid |
| `POST /api/loop/simulate-weigh`，毛重 2.5 t | 毛重 2500 kg，皮重 1234.5 kg，净重 1265.5 kg（1.2655 t），`SyncStatus=0`（None） |
| 重启后再 `GET /api/transports` | 同一称重行仍在，`reportStatus=None` |
| `POST /api/vehicles/batch-report` | HTTP 400，正文为没有外部平台响应、不能标为同步成功 |
| `POST /api/contracts`，数量 1.5 t、单价 2 | 明细 `QuantityKg=1500`，`Amount=3000`，列表数量仍显示 1.5 |

## Verdict

`FEASIBLE`。本机 Recycle Web 可以经 AppService 把车辆、一次称重和合同写入 Recycle 表，重启后数据还在，项目归属取服务端绑定，上报接口不会把同步标成成功。

后续实验见 `01-四页与拒绝规则.md`。四页刷新、匿名 401、跨项目拒绝、小数拒绝和皮重快照已有观察。真实 5041 登录和 138 上的库仍没有证据。
