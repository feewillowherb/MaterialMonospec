# 04 · 开源方案对照（Windows 10+ / Avalonia）

> **日期**：2026-09-14  
> **读者**：选型，不是实现手册  
> **约束**：Windows 10+、Avalonia 桌面 WinExe、self-contained 单文件约 330MB、安装目录任意且通常不在 `C:\Program Files`、强制更新、更新后最多约 30 分钟不在跑。

## 结论

**有现成的「检查版本 + 下载 + 换文件/重启」库，没有现成方案覆盖本需求全集。**

最接近的是 Velopack（差分、重启）和 NetSparkle（Avalonia UI、签名清单）。两者都不提供「30 分钟后必须已在跑」的看守租约。现场更新单位就是单文件主 exe 加要覆盖的 `appsettings`（依赖已打进 exe），不是「保住配置、只换程序」。整目录替换库仍不合适：它们会连数据库一起换掉。Onova / GeneralUpdate 更接近「就地覆盖」，但单文件锁定、强制、保活仍要自己做。

**第一版仍按 [02-推荐方案.md](02-推荐方案.md) 自建清单 + 同目录看守。** 开源库可当对照和以后差分的备选，不替换第一版主路径。这不改变 [03](03-落地影响与effort.md) 的 L 档判断。

## 对照（对本需求）

| 方案 | 平台 / UI | 能直接用的 | 对本现场不够的 | 建议 |
|------|-----------|------------|----------------|------|
| [Velopack](https://github.com/velopack/velopack) 1.2.0 | Windows / macOS / Linux；与 UI 无关（Avalonia 可用） | 清单、差分、下载失败回退全量、`ApplyUpdatesAndRestart`；`setup.exe --installto` 可指定目录 | Windows 更新会整目录替换 `current`。覆盖 `appsettings` 符合现场习惯，但同目录的数据库、租约文件也会被清掉。自有安装布局，和现有 Inno 现场包不好混。无 30 分钟租约 | 不作为第一版。若以后只要差分，须先把数据库挪出将被替换的目录 |
| [NetSparkle](https://github.com/NetSparkleUpdater/NetSparkle) `UI.Avalonia` 3.1.0 | Win / WPF / Avalonia（包依赖 Avalonia ≥ 11.3.9，与现栈同代） | Appcast 清单、Ed25519 签名、可无内置 UI、`--critical-versions` 仅提示「关键更新」 | 「关键」不是硬强制：窗口默认可关、可稍后（[issue #552](https://github.com/NetSparkleUpdater/NetSparkle/issues/552)）。设计是拉起安装包（Inno / NSIS / WiX），不是换正在运行的单文件 exe。无看守租约 | 可借鉴清单签名；不要用它的对话框当强制更新，也不要回到 Inno 静默当更新器 |
| [Onova](https://github.com/Tyrrrz/Onova) | **仅 Windows**；UI 无关 | 面向便携 zip 就地覆盖；外部 updater 退出后覆盖再拉起；自定义 resolver | 不拥有「任意盘符」以外的安装器，但历史问题是 **PublishSingleFile 覆盖会死锁/找错路径**（[issue #28](https://github.com/Tyrrrz/Onova/issues/28)）。无强制、无 30 分钟租约、无差分 | 模型最近「旁路下载 + 进程外替换」，不建议直接接入单文件现场包 |
| [GeneralUpdate](https://github.com/GeneralLibrary/GeneralUpdate)（Apache-2.0；2026-06 仍在更新） | Win / Linux / macOS；核心不绑 UI。另有 Avalonia 示例 | 版本检查、断点、差分 zip、SHA 校验、可换下载实现 | 名为 Avalonia 的独立仓当前是 **Android**（`GeneralUpdate.Avalonia.Android`），不是 Windows 桌面方案。无「必须已在跑」租约。差分工具链要另接发布 | 不作为第一版依赖。若以后要 BSDiff，再单独看其 Tools，不要和 Android 包混用 |
| AutoUpdater.NET 及非官方 Avalonia fork | 原版 WinForms/WPF；fork 质量不一 | XML 清单；zip 可解到指定 `InstallationPath` | 不是 Avalonia 一等公民；仍是「下载后启动安装器或解压器」，无租约、无单文件换包约定 | 不采用 |
| Squirrel.Windows | 旧 Windows 安装器 | — | 维护态，官方迁到 Velopack | 不新引入 |
| MSIX / App Installer | Windows 10+ 平台能力，不是开源更新库 | 企业分发、商店 | 签名、安装身份、目录策略都和「任意盘、非 C、只覆盖主 exe 与 appsettings」冲突 | 不采用 |

## 和已定方案逐条对

| 本需求 | 开源库典型做法 | 缺口 |
|--------|----------------|------|
| 安装路径不统一、通常不在 C 盘、目录须可写 | Velopack 默认 `%LocalAppData%\{id}\current`；`--installto` 能改根目录，但更新仍替换整棵 `current` | 现场要覆盖的是主 exe + `appsettings*`。数据库留在 exe 旁。整目录替换会把库一起换掉。自建方案只换这两类文件 |
| 运行中的单文件 exe 被锁定 | 都是退出后再换。Onova 对单文件有已知覆盖问题 | 必须旁路下载；替换发生在进程外。这与 02 一致，库没有省掉看守 |
| 强制、无跳过 | NetSparkle 的 critical 只是 UI 标记，用户仍可关窗 | 强制要自己做：无跳过、空闲硬截止、清单为权威 |
| 退出后最多约 30 分钟必须已在跑 | `ApplyUpdatesAndRestart` / `LaunchUpdater` 只保证「这次重启命令发出去」 | 重启失败、换文件失败、进程被结束，没有租约到期拉起或 `.bak` 回滚。这是自建看守的理由，不是库的缺陷能打补丁补上的 |
| 包约 330MB、地磅机网络不稳 | Velopack / GeneralUpdate 有差分或断点，有价值 | 差分要求换打包布局。第一版用 HTTP Range 即可；差分单独立项 |
| 清单防篡改 | NetSparkle Ed25519、各家 sha256 | 可借鉴签名；局域网 HTTP 只靠 sha256 仍只防损坏。见 03 开放问题，不必为此换库 |
| Avalonia 界面 | NetSparkle 有 Avalonia 对话框；其余不依赖 UI | 本需求不需要更新对话框（无跳过）。UI 包不是选型理由 |

## 不建议做的「半采用」

- 用 Velopack 只做更新、安装目录仍是现在的 Inno 目录：它换的是整棵 `current`，不是「主 exe + appsettings」。现场数据库会一起丢。
- 用 NetSparkle 弹窗 + 静默 Inno：回到 02 已否定的路径（要管理员、无 `AppMutex`、点不了 UAC）。
- 把 Onova 直接套在 `PublishSingleFile` 上：已知和单文件覆盖冲突，等于把失败模式交给第三方 updater。

## 若以后重开「用开源安装器」

只在下面都成立时再评估 **Velopack**（不要同时评估三家）：

1. 数据库已迁出将被替换的目录（`appsettings` 可以随包覆盖，这和现场习惯一致）。
2. 接受一次安装器切换（不再用 Inno 当后续更新通道）。
3. 330MB 全量下载已证明是现场瓶颈（差分才有理由）。
4. 看守租约仍自建：Velopack 的重启不能代替「到期必须在跑」。

在此之前，开源方案的可复用点只有：**清单版本比较、下载校验、签名思路**。换包与保活继续自建。
