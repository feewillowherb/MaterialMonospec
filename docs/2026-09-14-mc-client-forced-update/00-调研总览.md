# MC 客户端强制更新与保活 — 总览

> **日期**：2026-09-14  
> **类型**：代码考古 + 方案选型（仓库知识）  
> **范围**：`MaterialClient` 三个现场 WinExe / `UrbanManagement` 宿主边界  
> **不做**：本夹不开 OpenSpec、不改产品代码。正式拆分可再走 BMAD architecture 或 `/opsx:propose`。

## 一句话

今天没有更新通道，保活也只是「登录时可选自启」。`MaterialClient.Urban` 是工控软件，必须开机自动运行且主窗口始终处于前台。要同时满足「UM 下独立服务器推送、强制更新、安装路径不统一且通常不在 C 盘、更新窗口最多约 30 分钟且结束后必须已回前台」，应新增 **UM 旁路更新宿主（清单）+ 与主程序同目录的看守进程（替换、拉起、置前）**，并配置 Windows 开机自动登录。不要用现有 Inno Setup 静默重装当更新器。

## 结论（先读）

| 要求 | 今天 | 建议 |
|------|------|------|
| 所有现场客户端可更新 | 无 Velopack / Squirrel / 版本检查；版本只写在 `.iss` | 按产品通道发版：`MaterialClient` / `MaterialClient.Urban` / `MaterialClient.Recycle` |
| UM 下独立服务器推送 | UM 只有 `UrbanManagement.App` 一个宿主 | 旁路宿主只发清单与下载地址，不塞进称重 API |
| 安装包放 OSS 或静态目录 | UM 无 OSS SDK；`UseStaticFiles` 只服务业务静态资源 / `ClientLogs` | 字节在 OSS 或更新宿主静态目录；客户端不持有长期 OSS 密钥 |
| 强制更新 | 无自动通道；现场手工覆盖 `appsettings` + 主 exe（依赖已打进单文件） | 同一替换范围做成可重复通道：覆盖主 exe 与 `appsettings*`，不碰数据库。下载在进程仍运行时完成 |
| MaterialClient.Urban 是工控软件：开机自动运行，且主窗口始终处于前台 | 仅 HKCU `Run`，默认关；崩溃不拉起；Urban 未接线；不保证前台 | 开机自动登录到交互会话 + 同目录看守拉起并置前台；更新租约最多约 30 分钟不在前台，到期必须重新置前 |
| 目标机不统一、通常不在 C 盘 | Inno 默认 `{autopf}`（多在 `C:\Program Files`），且要管理员 | 用自身 exe 目录定位；目录须对运行用户可写。不要假设盘符或 Program Files |

## 非目标

- 不把 `MaterialClient.Demo` / `MaterialClient.Toolkit` 算进现场更新通道（除非另要求）
- `MaterialClient.AttendedWeighing` 是主程序里的窗口，不是单独安装包
- 不把 Avalonia 界面做成 Windows Service（Session 0 没有交互桌面）
- 不把长期 OSS AccessKey 写进客户端（与 [客户端 OSS 直传调研](../2026-09-11-client-aliyun-oss-direct-upload/00-调研总览.md) 一致）
