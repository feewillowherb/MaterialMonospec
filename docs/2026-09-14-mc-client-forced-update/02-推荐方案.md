# 推荐方案

## 角色

```text
运维发布
  │  登记版本 + sha256 + 包 URL（OSS 或本机静态目录）
  ▼
UrbanManagement.UpdateHost          ← UM 解决方案里的旁路宿主，不是称重 API
  │  GET 清单（按产品通道）
  │  可选：静态目录直接发字节
  ▼
地磅机（路径任意，通常非 C 盘）
  MaterialClient*.exe               ← 称重 UI，负责发现新版本、空闲策略、下载
  MaterialClient.Watchdog.exe       ← 同目录小进程，负责换文件、租约、拉起
```

「独立服务器」指独立进程/站点，仍放在 UrbanManagement 解决方案里，由 UM 侧部署。不要做成 `UrbanManagement.App` 里的一个 Controller：业务宿主发布时更新通道会一起停；330MB 包也不该进业务 wwwroot。

## 更新宿主只做三件事

1. **清单**（权威）。按通道一份当前版本，例如 `MaterialClient`、`MaterialClient.Urban`、`MaterialClient.Recycle`。字段至少：`product`、`version`、`sha256`、`packageUrl`、`releasedAt`、`force`（本需求恒为 true，字段仍保留，避免以后只能改代码）。
2. **包地址**。`packageUrl` 指向：
   - 更新宿主自己的静态目录（`PhysicalFileProvider`，目录与业务 `wwwroot` 分开），或
   - OSS 对象。客户端只拿 URL 下载。公开读或由更新宿主签发短期 URL。**不**把 Bucket 长期密钥放进地磅机。
3. **回报**（建议同期做，否则无法知道谁还停在旧版）。客户端用已有 `MachineCodeService` 回报 `product + version + machineCode`。更新通道不要依赖业务登录 JWT：坏版本若把登录打坏，仍须能拉到下一版。

轮询间隔由客户端配置（建议数分钟）。离线期间不更新；连上后若清单版本更高则强制进入更新。不做「用户稍后」。

## 看守进程与 30 分钟租约

看守 exe 与主程序放在同一目录，用自身路径找主 exe。不读 Program Files，不读盘符。

启动方式（两层，缺一不可）：

- 用户登录时拉起看守（计划任务「登录时」或 HKCU `Run`，**值名用 exe 名**，禁止再写死 `MaterialClient`）
- 主程序启动时若发现看守不在，再拉一次

工作目录必须设为 exe 目录（现有 `Program.cs` 已为此注释过）。

状态机：

| 状态 | 看守行为 |
|------|----------|
| 主进程在跑 | 不动 |
| 主进程不在，且没有未过期租约 | 立即启动主 exe |
| 租约有效（更新中，最长约 30 分钟） | 不把「不在跑」当故障。等待换包完成或自己执行换包 |
| 租约过期仍不在跑 | 启动盘上的主 exe。若新 exe 校验失败且存在 `.bak`，先回滚再启动 |

租约是一个同目录文件（开始时间、截止时间、目标版本、已校验的暂存包路径）。只在暂存包 sha256 通过之后才写租约并退出主进程。下载失败不退出、不写租约。

换包步骤（主进程已退出、Mutex 已释放）：

1. 主 exe 改名为 `.bak`（若改名失败，租约内重试；到期仍失败则尝试启动原 exe，并回报失败）
2. 暂存文件移到正式 exe 名
3. 启动新进程；确认 Mutex/进程出现后清租约
4. 启动失败：用 `.bak` 盖回，再启动，并回报

不要覆盖 `appsettings.json`、`appsettings.secret.json`、数据库文件。这与现有 Inno `onlyifdoesntexist` 一致。

三个产品各有自己的 Mutex（`MaterialClient_SingleInstance_Mutex`、`MaterialClient_Urban_SingleInstance_Mutex`、`MaterialClient_Recycle_SingleInstance_Mutex`）。换包前必须等旧进程退出，否则新进程会因 Mutex 直接 return。Urban 已有 `RequestProcessRestart`，可作「退出后由别人拉起」的先例，但看守仍要在进程外，不能只靠进程内重启。

## 为何不用 Inno 静默重装，也不把 Velopack 当第一版

| 做法 | 不作为第一版主路径的原因 |
|------|--------------------------|
| Inno `/VERYSILENT /DIR=...` | 要管理员；脚本默认 `{autopf}`；无 `AppMutex`；版本不在程序集里；现场路径不统一。无人值守点不了 UAC |
| Velopack / Squirrel | 差分对 330MB 有价值，但自有安装布局，和现有 Inno 现场包不好混；也不提供「30 分钟后必须已在跑」的租约。带宽真成为问题再单开差分 |

第一版用 HTTP Range 断点续传。地磅机网络上一次下 330MB 失败是预期情况，不能因此退出主进程。

## 强制更新与称重中

清单版本更高则必须更新，没有跳过按钮。

下载放在仍在称重的时段（旁路文件，不替换正在运行的 exe）。真正退出前：若有未完成称重，先等到空闲，并设硬截止（建议远小于 30 分钟租约，例如数分钟），避免一车卡死整个更新。硬截止后仍强制退出——否则「强制」不成立。称重中被切断会丢当前票，这是取舍，见开放问题。

30 分钟租约覆盖的是「已经退出、正在换文件/拉起失败重试」，不是「先退出再下 330MB」。

## 版本从哪里来

每个 WinExe csproj 增加 `<Version>`（或等价的 informational version），与将要发的清单版本一致。Inno 的 `MyAppVersion` 改成同一来源，避免脚本和运行时各写各的。

客户端比较用这个版本，不用文件时间，不用 Inno 卸载注册表。

## 安装目录可写

换 exe 的用户必须能写安装目录。这与「通常不在 C 盘、机器不统一」相符：自定义目录、同一用户运行即可，不需要管理员。

若某台仍在 Program Files：第一版应迁到可写目录，而不是在更新时弹 UAC。迁目录是一次性的，不在每次更新里做。

## 诚实边界：无法在无人登录时显示界面

Avalonia WinExe 需要交互会话。重启后、登录前，界面起不来。Windows Service 也不能在 Session 0 里撑起这个 UI。

本方案保证的是：**已有用户会话时，除更新租约窗口外，主程序应在跑；租约结束后不允许停在未运行。** 若还要求「拔电重启、无人登录也要在跑」，做不到界面程序，只能另议开机自动登录 + 登录任务。
