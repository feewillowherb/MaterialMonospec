# 01 · 快速查询

给不熟悉 EF / 多 Context 的同事：先扫这张表，再看下面 FAQ。

## 30 秒对照

| 问题 | 答案 |
|------|------|
| 数据库文件变几个了？ | **还是一个**：`MaterialClient.db`（连接串 `Default`）。 |
| 为什么要两个 Context？ | 内核模型 **冻结**；Urban/Recycle 表 **不要**再进内核 snapshot，否则标准安装也会 `CREATE` 产品表。 |
| `DbSet<UrbanWeighingExtension>` 会改旧库吗？ | **声明模型而已**。真正改库的是 **Migrate**。Urban 表名未改，旧行还在。 |
| 标准客户端会建 Urban 表吗？ | **新库不会**（不引用 `Common.Urban`）。**旧库**可能已有孤儿表，**不 DROP**。 |
| 设置 `UrbanSettingsJson` 呢？ | 内核 **不再映射**该列。Urban 启动时拷到表 `UrbanSettingsRows`。 |

## 三种宿主

| 宿主 WinExe | 引用 | 启动时 Migrate |
|-------------|------|----------------|
| `MaterialClient`（标准） | Common + `Common.EntityFrameworkCore` | **只**内核 |
| `MaterialClient.Urban` | 上者 + `Common.Urban` | 内核 → **再** `UrbanDbContext` |
| `MaterialClient.Recycle` | Common + 内核 EF + `Common.Recycle`（**禁止** `Common.Urban`） | 内核 → **再** `RecycleDbContext` |

`MaterialClient.UI` **只**引用 Common，不引用产品 Common。

## FAQ

### 1. 「双 Context」是两套程序还是两套表定义？

运行时还是 **一个进程、一个 SQLite 文件**。  
`MaterialClientDbContext` 管称重/运单/附件/内核设置等；`UrbanDbContext` 只管 Urban 扩展表 + Urban 设置行。ABP 各注册一次 `AddAbpDbContext`，**禁止** `ReplaceDbContext` 把产品模型并回内核（并回去就等于没拆）。

### 2. 旧 Urban 客户端升级后，称重扩展数据还在吗？

在。表名仍是 `UrbanWeighingExtensions`。产品 migration 使用 `CREATE TABLE IF NOT EXISTS`，**已有表不重建**。仓储从内核 Context 改到 `UrbanDbContext`，读的是同一张表。

### 3. 加 `DbSet<UrbanSettingsRows>` 会怎样？

会多一张 **新产品表**。首次 Urban Migrate：建表，并从 `Settings.UrbanSettingsJson` **INSERT 拷贝**一行。之后 Urban 读写走 `IUrbanSettingsJsonStore`，不再把该 JSON 当内核必填列。

### 4. 标准端打开旧库，里面还有 Urban 表，会不会报错？

一般 **不会**：标准端模型里没有这些实体，EF **不理**孤儿表。不要为此写内核 `DROP TABLE`。

### 5. 内核 history 表名变了会怎样？

旧库默认是 `__EFMigrationsHistory`。启动内核 Migrate 前会尝试 **rename** 到 `__EFMigrationsHistory_Kernel`（若目标表还不存在）。产品另用 `__EFMigrationsHistory_Urban` / `_Recycle`。

### 6. Common 里为什么还有 `IUrbanWeighingRecordSideEffects`？

标准宿主 **不能**引用 `Common.Urban`。称重写入仍在 Common；Urban 用 **ReplaceServices** 接上真正写扩展表的实现，标准端是 **空操作**。Recycle 对运单扩展同理：`IRecycleWaybillExtensionStore`。

### 7. 能不能 LINQ join 内核表和 Urban 表？

**不要**跨两个 `DbContext` 做 EF join。分别查询，在 **Service** 里用逻辑 Id（`WeighingRecordId` 等）组合。禁止数据库 FK / EF `HasOne`/`HasMany`（见 `traits/no-database-fk-trait.md`）。

### 8. `dotnet ef` 怎么用？

必须带 `--context` 和对应 `--project`（内核 EF 项目 vs `Common.Urban` vs `Common.Recycle`）。不要对着内核项目 `add` 出产品表的 DROP。

### 9. 设置保存没反应、日志里 `database is locked`？

同库双 Context **不能**在内核写事务未提交时再开 Urban 写事务。证据与不变量见 [03-同库双Context设置保存锁.md](./03-同库双Context设置保存锁.md)。同一日志里的 **502** 是远端 Hub/API，不要当成保存失败原因。
