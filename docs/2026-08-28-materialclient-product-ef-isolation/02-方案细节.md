# 02 · 方案细节

选型背景与否决项见 BMAD 报告（方案 **B**：同库多 Context）。这里只写 **已落地形状**，便于对照代码。

## 目标 / 非目标

**目标**

- Common 领域基线 + 内核 EF 项目；产品表不进内核 snapshot。  
- `Common.{Product}` 承载产品实体、产品 DbContext、产品 migration、产品 Service。  
- 标准宿主不引用产品程序集。  
- Urban 设置离开内核 `Settings` 映射列。  
- 启动顺序：内核 Migrate → 产品 Migrate。

**非目标**

- 不改 UrbanManagement / BasePlatform。  
- 不拆成多个 SQLite 文件。  
- 不用 ABP `ReplaceDbContext` 合成单一模型。  
- 不强制 DROP 旧库产品表。  
- 不把 Avalonia 视图塞进 `Common.*`。

## 程序集分层

```text
MaterialClient.Common          领域、Service 接口、钩子（无产品实体映射）
        ▲
        │
MaterialClient.Common.EntityFrameworkCore     MaterialClientDbContext + 内核 Migrations
        ▲
        ├── MaterialClient.Common.Urban      UrbanDbContext + Urban 实体/服务
        └── MaterialClient.Common.Recycle    RecycleDbContext + Recycle 实体/Store

WinExe：标准只引用 Common + 内核 EF
        Urban 再引用 Common.Urban
        Recycle 再引用 Common.Recycle（不得引用 Common.Urban）
UI：只引用 Common
```

内核 EF **不得** ProjectReference 产品 Common。产品 Common 可引用 Common + 内核 EF（注册 SQLite 与 history 表名）。

## DbContext 与 history

| Context | History 表 | 典型表 |
|---------|------------|--------|
| `MaterialClientDbContext` | `__EFMigrationsHistory_Kernel` | WeighingRecords、Waybills、Settings（无 Urban JSON 映射）、认证… |
| `UrbanDbContext` | `__EFMigrationsHistory_Urban` | `UrbanWeighingExtensions`、`UrbanSettingsRows` |
| `RecycleDbContext` | `__EFMigrationsHistory_Recycle` | `RecycleWaybillExtensions` |

`DbSet<>` = 该 Context 的模型成员。**不会**单独改磁盘；改磁盘的是各 Context 的 `Database.MigrateAsync()`。

Urban 的 `DbSet<UrbanWeighingExtension>` / `DbSet<UrbanSettingsRow>`：前者对齐 **已有** 表名；后者为 **新** 持久化。产品 Up 脚本对扩展表 `IF NOT EXISTS`，对设置表创建并 `INSERT…SELECT` 自 `Settings.UrbanSettingsJson`。

内核有一条 **空 Up** 的 migration（`DetachProductTablesFromKernel`）：只同步 snapshot（去掉产品实体），**禁止**在此 DROP 产品表。

旧 `__EFMigrationsHistory` → 启动时 rename 到 `_Kernel`（见 `SqliteMigrationHistoryMigrator`）。

## 跨层调用（避免循环引用）

| 场景 | 做法 |
|------|------|
| Common 称重写入要带 Urban 扩展 | `IUrbanWeighingRecordSideEffects`；Urban 模块 `ReplaceServices` |
| Common 匹配/收货要写 Recycle 扩展 | `IRecycleWaybillExtensionStore`；Recycle 模块替换实现 |
| 设置里的 Urban JSON | `IUrbanSettingsJsonStore`；内核 `SettingsEntity` **Ignore** `UrbanSettingsJson`；Get/Save 时 Urban 实现读写 `UrbanSettingsRows`。**必须先结束内核 UoW 再写产品表**，否则 SQLITE_BUSY（见 [03](./03-同库双Context设置保存锁.md)） |
| 列表（异常 Tab） | 内核查 `WeighingRecord`，Urban 查扩展，**内存组合**（禁止跨 Context EF join） |

Xiaoshan 表单转化：现网为 Common 上静态 From/To；UI 不引用 `Common.Urban`。

## 旧库 vs 新库

| 情况 | 行为 |
|------|------|
| Urban 升级旧库 | 扩展表保留；设置拷到 `UrbanSettingsRows`；内核列可仍物理存在但不再映射 |
| 标准端 **新**安装 | 内核 migration **不再**创建 Urban/Recycle 表 |
| 标准端 **旧**库 | 可能残留产品表 → 孤儿，忽略 |
| 极旧 Urban 表缺列 | `IF NOT EXISTS` 不会 ALTER；缺列会在运行时报错（需单独补列 change） |

## 开发约束（摘）

- ViewModel → Service → Repository；产品仓储来自产品 Context。  
- 无 tuple API；转化用静态 From/To。  
- 无 DB FK、无 EF 关系导航为关联服务。  
- `dotnet build MaterialClient.sln -o .build-verify`（避开文件锁）。
