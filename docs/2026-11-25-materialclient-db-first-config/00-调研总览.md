# MaterialClient 放弃 appsettings、全面收敛为「代码内置默认值 + SQLite DB」

创建日期：2026-11-25。生命周期：`ACTIVE`。知识状态：现状核对为 `CONFIRMED`；目标方向已由用户确认（仅记录现状、决策与 Goal，**暂不进 `docs/intake/` 与 `openspec/`**，不修改业务代码）。

---

## 1. 背景与适用范围

当前 `repos/MaterialClient/src/` 下全部 **4 个桌面宿主**均同时维护 `appsettings.json` + `appsettings.secret.json` 与 SQLite `Settings` 表：

- `MaterialClient`（Standard）
- `MaterialClient.SolidWaste`（固废）
- `MaterialClient.Urban`（城管 5001）
- `MaterialClient.Recycle`（资源化 5020）

在无人值守工控机与 2.0 远程推送更新（Velopack OTA）场景下，依赖外部 `appsettings.json` 存在三大顽疾：
1. 断电写半截、人工编辑漏逗号或编码错误会直接导致 `ConfigurationBuilder` 在启动最早期崩溃，软件起不来、运维与更新通道全部失联；
2. 覆盖安装或版本目录切换时极易发生现场配置丢失或字段漂移；
3. 大量本应内嵌代码常量的内容（如公钥、静态字典、重连参数、默认路径）暴露在外部 JSON 中，既无必要又放大故障面。

---

## 2. 核心决策（Goal）

- **对全部 4 个 MaterialClient 桌面软件统一生效**（不限于 Urban 与 Recycle）。
- **彻底放弃外部 `appsettings.json` / `appsettings.secret.json` 作为运行时强依赖**，全面收敛为 **「代码内置默认值 + SQLite DB」**（外加仅限开发/测试的命令行/环境变量覆写）。
- 保证**即使裸机空目录或单条配置异常，客户端也能以内置默认值正常启动**，从根源消除“配置文件无法解析导致程序无法启动”的故障，为 2.0 推送更新与无人值守常驻提供底层保障。
