# 当前测试全流程 — 缺陷分析

> **日期**：2026-09-11  
> **范围**：手册宣称的「人测 → Graph 选型/生成 → cook → runs 证据 → 人闸 → OpenSpec 衔接」全流程，对照 [`pipelines/AGENTS.md`](../../pipelines/AGENTS.md) 与仓库实态。  
> **约束**：本文**只记缺陷**；不展开改进方案（改进另开讨论 / change）。

## 1. 流程断层：三层测试互不咬合

- 手册声明「不替代单元测试 / CI」，但仓内**没有** CI workflow，也没有「unit → pipeline → 现场」的强制衔接。
- OpenSpec 活跃 change 的 `tasks.md` **均未链接**任何 Graph / `/run-pipeline`；手册 §4「tasks 应指向 Graph」在实践上基本落空。
- 现场/真机门（地磅、海康）被划为「仍要人」，但**没有**可登记的现场闸工件类型；tasks 勾选完成 ≠ 现场门关闭（例：Hikvision soft-reset 任务写明硬件 smoke 延后现场，仍可整表 `[x]`）。

---

## 2. 覆盖空洞：手册承诺的替代面远大于现图

- MaterialClient 人测替代在手册速查里几乎只落到**登录 observe**；对应图本地 **0 次** `runs/`。
- **称重主路径、抓拍、Hikvision soft-reset、weighing-list UI** 均无对应 Graph；相关 OpenSpec 只能靠单测 / 手测收口。
- AGENTS domain 词表含 `baseplatform` / `platform`，目录下**零图**；词表示例 `attended-list-observe`、`weighing-list-observe`、`login-smoke`、`sqlite-reconcile` **路径不存在**（幽灵目标）。

---

## 3. 「绿」不可核验：证据与验收状态机残缺

- `runs/` **gitignore**，手册却把「绿证据包」当作 Archive / PR 门槛 → **远程审查看不到**人闸证据。
- Agent 禁宣布 L3，但人闸允许写在「会话 / 工单 / PR」任一处 → **无统一验收落点**；多份 cook 缺 `acceptance.md` / `report.md`，甚至有空跑目录。
- 存在把 Graph 根 `acceptance.md` 写成「已 L3」与 run 内 pending 并存的矛盾记录；L0「可达」与业务绿可同时成立（例：xiaoshan-weighbridge HTTP 502 仍可 L0 pass）→ **人闸语义不清**。

---

## 4. 选型与权威双轨：跟手册会选错 / 选不全

- `02-场景对照与选型.md` 自建「现行 Graph 速查」相对 AGENTS §6.1 **子集且易过期**；与总览「本夹不复制词表」自相矛盾。
- 无工具扫描 `graph.*`；选型靠人 / Agent 读表 → 易漏 active、易撞同 goal。
- 手册把 `urban-passage-probe` 写成 UrbanManagement 通行证探测，图自身实际是 **MaterialClient.Urban 本地注入** → 场景标签错误。
- AGENTS「现行路径禁止日期段」与 active slug `sand-addbatch-2026-0N` **规则自撞**。

---

## 5. Cook 可靠性与副作用未纳入「可替代人测」前提

- 大量 active 图本地 **0 runs**；有 runs 的也可见红灯 / 空状态（如 xiaoshan-weighbridge 502）。
- Observe 依赖可选 MCP（FlaUI / Avalonia DevTools），手册检查清单**不要求**适配器预检。
- 部分 probe **破坏性**（如 passage-probe 整表覆盖 LPR 设置）未在「适合替代人测」表中标为环境污染。
- 重试产生大量半残 `runs/`，无清理 / 作废契约 → 证据库噪声。

---

## 6. 手册自身的流程表述缺陷

- `01-使用手册.md` OpenSpec 对照表写：`/run-pipeline` cook「**默认真改产品**」——与「采证、默认不改 `repos/`」的全仓约束**语义相反**（表述缺陷，会误导执行方）。
- gen 侧模板路径在命令 / 哲学文档与仓库实际（仅 `_template/`）不一致，生成入口易踩空。
- Goal 互斥 / 同 goal 退役 Ask 仅在 AGENTS；手册决策树未写 → 仅跟手册易重复 active goal。
- 退役图若仍留 `design-brief.md` `status: active`，与 `config.yaml` 冲突时可能误选。

---

## 一句话

当前缺陷不是「缺几句文档」，而是 **自动化覆盖窄、OpenSpec 不强制挂图、绿证据无法共享核验、验收状态机分裂、选型权威漂移**——人测替代在规程上写成闭环，在仓库实态上仍是断链。
