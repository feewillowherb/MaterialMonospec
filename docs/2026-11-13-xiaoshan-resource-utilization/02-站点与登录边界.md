# 站点与登录边界

创建日期：2026-11-13。生命周期：ACTIVE。知识状态：CONFIRMED（现有宿主）/ INFERRED（新站点做法）。

## 现有宿主

以下事实限于当前工作区源码。

| 事实 | 证据 |
|------|------|
| 对外入口是 `um-gateway`，默认把宿主机端口 5333 转到网关 8080 | `repos/UrbanManagement/deploy/docker/compose.yaml` 的 `um-gateway.ports` |
| `/_blazor/**`、`/api/**` 和其余路径兜底都到 `um-admin`。客户端认证、上传、称重接收、实时通道有更优先的独立路由 | `repos/UrbanManagement/src/UrbanManagement.Gateway/appsettings.json` |
| 管理界面是 Blazor Server。登录页是 Razor Page `/login`，登录后的页面走 `/_Host` | `repos/UrbanManagement/src/UrbanManagement.Admin/Sso/AdminSsoAuthentication.cs`、`Pages/Login.cshtml` |
| Cookie 名是 `UrbanAdmin.Session`，方案名是 `UrbanAdmin`。退出是整页 `POST /logout` | 同上，`MapPost("/logout")` |
| 登录调用 SSO `POST /GetToken`。请求固定 `switchType=0`、`productType=2`，`toProductIds` 只有配置里的 `WebProductCode` | `repos/UrbanManagement/src/UrbanManagement.Admin/Sso/SsoWebLoginClient.cs` |
| 接受登录的条件是业务码 200，且响应 `productId` 等于这个 `WebProductCode`。令牌不进入登录结果，也不写入 Cookie | `repos/UrbanManagement/src/UrbanManagement.Admin/Sso/SsoWebLoginResult.cs` |
| 仓库内示例配置把 `AdminSso:WebProductCode` 留为 0。运行中的城管管理端产品在既有 Topic 里是 5040 | `repos/UrbanManagement/src/UrbanManagement.Hosting/appsettings.json`；[`docs/2026-11-13-urbanmanagement-fdsoft-sso/00-调研总览.md`](../2026-11-13-urbanmanagement-fdsoft-sso/00-调研总览.md) |
| 每个服务是独立 Web 项目和镜像，服务项目之间不互相引用 | `repos/UrbanManagement/AGENTS.md`「Microservices」 |

城管管理端页眉是「萧山城管对接平台」，菜单是项目管理、称重记录、卡口进出、成品进出、异常审批、客户端日志。那些页面调用 Core 的 AppService。本站不进入这些页面，也不调用这些服务。

## 独立站点

新站点是 UrbanManagement 解决方案里的另一个 Web 项目，仍在这个 Git 仓库中。它不引用 `UrbanManagement.Admin`，也不把页面加进现有 `AdminLayout`。

2026-11-16 用户确认：三张业务页使用 **Vue 3 + Element Plus**。筛选、表格、分页、标签、按钮、对话框和上传使用 Element Plus 组件，顶栏改成图上的紫色。登录页是本站的 Razor Page，不放进 Vue。Vue 构建结果由这个 ASP.NET 进程在登录成功后提供。Vue 从本站 API 获取车辆和合同 mock，不调用 SSO，也不调用城管管理端或 Core 的业务 API。

2026-11-16 用户确认工程名为 **`UrbanManagement.XiaoShanResource`**。标识符用英文。用户可见中文写在登录页和 Vue 模板里。

本单的宿主选择：

- 单独监听一个端口。该进程提供登录页，并托管 Vue 3 页面。
- 不把本站接进现有网关的 `/{**rest}` 兜底，也不占用 `/_blazor`、`/api`、上传和称重路由。
- Cookie 名为 `XiaoShanResource.Session`。浏览器按主机名保存 Cookie，不按端口区分。与城管管理端同机部署时，沿用 `UrbanAdmin.Session` 会把两个站点的登录状态混在一起。
- `WebProductCode` 固定为 5041。配置节可以继续叫 `AdminSso`，数值不读取城管管理端的 `UM_ADMIN_SSO_WEB_PRODUCT_CODE`。
- 2026-11-16 确定与 138 现有栈同一次 compose 发布。服务名 `um-xiaoshanresource`，宿主端口默认 5334，不进入 `um-gateway`。SSO 地址复用 `UM_ADMIN_SSO_BASE_URL`，产品编码固定 5041。现有服务的端口、路由和数据库依赖不改。

登录页标题使用产品名称「萧山资源化利用网页端」。账号和密码的提交方式与现有 `/login` 相同：浏览器只把表单交给本站，本站服务端再请求 SSO。请求体保持 `switchType=0`、`productType=2`、`toProductIds=[5041]`。响应里的 `productId` 必须是 5041 才写入本站 Cookie。失败时停留在登录页，页面只显示登录失败。

2026-11-16 对 135 的 `POST /GetToken` 做过一次 FEV：错误口令被拒绝；已核对匹配的口令返回业务码 200，产品是 5041「萧山资源化利用网页端」，响应里有令牌。这次没有经过本站登录页。证据和 Verdict 在 [`00-调研总览.md`](00-调研总览.md)。

登录成功后进入外壳，并打开车辆管理。侧栏只有车辆管理和合同管理。页签栏此时只有「车辆管理」；合同管理的标签在该页被打开后才出现。新建合同是合同页上的对话框，没有自己的菜单项或页签。这三块画面通过本站 API 读写进程内 mock。

退出沿用整页提交：`POST /logout` 删除本站 Cookie 并回到本站登录页。本单不调用 SSO 的 `logout`，也不删除 SSO 的 Redis 会话。这一点与现有城管管理端一致。

## 登录仍然依赖的外部条件

真实 SSO 能签发 5041 令牌，前提是 FD_Base 里已有产品 5041、名称「萧山资源化利用网页端」，以及对该账号有效的产品授权。5040 的写入和缓存刷新记录在既有 SSO Topic 中。5041 是否已经存在，本次没有查库，状态是 UNKNOWN。

本单不设计、不修改 FD_Base 的表，也不写产品、菜单、角色和授权。若登录联调时 SSO 拒绝 5041，处理方式是另案补产品数据，而不是在本站加业务表。

本站登录不携带图形验证码。验证码计划写在 [`docs/2026-11-13-urbanmanagement-fdsoft-sso/01-管理端登录页计划.md`](../2026-11-13-urbanmanagement-fdsoft-sso/01-管理端登录页计划.md)，对象是城管管理端，本单不提前做。

## 本单不做的事

- 不设计车辆、合同、产品明细、附件的表、实体、DbContext 或 migration。
- 不把 mock 列表放进 `UrbanManagement.Core`，也不为它们注册 AppService。
- 不把 PDF 送到 `UrbanManagement.Attachment`，不把合同上报送到 Ingest 或外部平台。
- 不修改城管管理端的菜单、Cookie、`WebProductCode` 和网关路由。
- 不修改 MaterialClient，也不修改 FdSoft.SSO 的代码。
- 不在本 Topic 里宣布 5041 登录已经成功。5040 的登录结论不能挪到 5041。
- 不实现仪表盘、消纳场地、生产管理、运输清单、系统管理，也不为这些未打开页面预留菜单或页签。
- 不把这三张业务页做成 Blazor 页面，也不把城管管理端改成 Vue。
