## 本单范围

用户于 2026-11-13 指定：在 UrbanManagement 中做独立站点，按 `_tmp/萧山资源化利用/` 的三张图做页面。ProductCode 为 **5041**。2026-11-16 确定该 Web 的产品名称为 **萧山资源化利用网页端**。

本单同时限定：

- 只实现三张图里的画面：车辆管理、合同管理、新建合同对话框。图上其余菜单和页签（仪表盘、消纳场地、生产管理、运输清单、系统管理）不实现，也不在侧栏或页签栏留标签。
- 页签只在对应页面被打开后出现。未打开的页面不预留标签位置。
- 不做数据库设计。不建表、实体、migration，也不做车辆、合同、附件的持久化。
- 登录之后的车辆和合同仍是 mock，不落库。2026-11-16 确定这些数据由 `UrbanManagement.XiaoShanResource` 自己的 API 提供，Vue 从该 API 获取，不在页面里内置种子。
- 只有登录调用真实 SSO。登录形态沿用现有 Admin 的 `POST /GetToken`。
- 2026-11-16 确定三张业务页的技术选型为 **Vue 3 + Element Plus**。登录页仍由本站 ASP.NET 渲染，服务端调用 SSO。城管管理端继续使用 Blazor，本站不改那套界面。
- 2026-11-16 确定工程名为 **`UrbanManagement.XiaoShanResource`**。会话 Cookie 名为 `XiaoShanResource.Session`。

## 结论

本单可以做成 UrbanManagement 仓库内的另一个 Web 项目 `UrbanManagement.XiaoShanResource`：自己的端口、Cookie `XiaoShanResource.Session`、`WebProductCode = 5041`。车辆管理、合同管理和新建合同对话框用 Vue 3 + Element Plus 还原布局和样式。车辆和合同 mock 由该项目的 API 放在进程内存里，Vue 从 API 获取。登录页把账号和密码交给本站服务端，服务端按现有约定调用 SSO `GetToken`，`toProductIds` 只含 5041。

现有 `um-admin`、网关兜底路由、客户端上传和称重通道保持原样。2026-11-16 确定本站进入同一套 compose，服务名 `um-xiaoshanresource`，宿主端口默认 5334，不由网关转发。5041 的产品、菜单、角色和一条项目授权已在 2026-11-16 的 FEV 中写入 135 的 FD_Base。那次写入不是本站的车辆或合同库，本 Topic 仍不规划这些业务表。

界面技术选型和工程名已由用户确认。站点端口仍是 INFERRED。进入代码前需要 Human `APPROVED`，并另开 OpenSpec change。

## 5041 SSO 初始化与登录 FEV（2026-11-16）

### 问题、实验与 Verdict

- 问题：135 的 FD_Base 能否为「萧山资源化利用网页端」落下可登录的产品、菜单、角色、用户角色和产品授权，并且 `POST /GetToken` 能用账号 `13758155135` 对 ProductCode 5041 签发令牌？
- 实验：写入前只读确认 5041 和产品名称都未占用，菜单编码未占用。该账号已存在、未删除、未锁定，库存密码与 2026-11-13 已核对的口令一致，因此不更新 `UserPwd`。授权只落到该用户当前项目上的一条记录；该项目当时仍有一条未过期且审核通过的 5001 授权。事务内新增产品、根菜单和「车辆管理」、一条普通角色、一条用户角色、一条 `AuthStatus=1` 且 `CheckStatus=2` 的产品授权，有效期自当日起两年。5040 未改。随后只删除 135 Development Redis 的 `AllTable` / `JCProduct`，返回 1。再向 `http://192.168.3.135:8500/GetToken` 发送两次请求，`switchType=0`、`productType=2`、`toProductIds=[5041]`。先用错误口令，再用已核对匹配的口令。响应只保留 HTTP、业务码、msg、产品标识，以及是否出现令牌。这次没有启动或停止本机 SSO，打的是 135 上已经在听的 SSO。
- **产品数据 Verdict：FEASIBLE。** 读回 ProductCode=5041，名称「萧山资源化利用网页端」，OrganizeType=2，ProductType=2，Status=1，DeleteStatus=0，Sort=5041；菜单 2、角色 1、该用户赋权 1、未过期授权 1。5040 仍在。
