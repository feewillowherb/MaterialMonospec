# 耀华（XK3190系列）地磅仪表串口通讯模式与重量数据提取分析报告

本报告针对 **上海耀华（Yaohua）XK3190系列称重显示控制器**（如 A9 / A9+ / DS3 / A12 等地磅仪表）的串口通讯模式进行深度分析，涵盖 **`tF=0`（连续发送模式）**、**`tF=1`（指令应答模式）** 机制，并专门针对如何从数据包中获取 **皮重 (Tare Weight / 英文: Tare Weight)**、**毛重 (Gross Weight / 英文: Gross Weight)** 与 **净重 (Net Weight / 英文: Net Weight)** 进行详细说明。

---

## 一、 参数背景与配置项说明

在耀华称重仪表的系统参数设置中，`tF` 参数代表 **通讯方式控制字 (Transmission Format / Trigger Format)**：

* **`tF = 0`**：**连续发送模式 (Continuous Transmission Mode)**
* **`tF = 1`**：**指令应答模式 (Command-Response / Polling Mode)**

配套参数：
* `bAud`：波特率（如 2400 / 4800 / 9600 bps 等）
* `Adr`：通讯地址（范围 01 ~ 26，在 `tF=1` 轮询模式下必须指定唯一地址）

---

## 二、 `tF=0` 模式深度分析（连续发送模式）

### 1. 工作原理与机制
在 `tF=0` 模式下，仪表作为**数据发送方**，不需要接收来自上位机的请求指令。只要仪表开机，就会按固定频率（通常 10~25 次/秒）**主动、单向**地向串口广播数据。

### 2. 数据帧结构解析
标准耀华 A9 / A9+ 连续模式下的每帧数据通常由 **12 个 ASCII 字符（字节）** 组成：

| 字节序号 | 内容说明 | ASCII码 / 十六进制示例 | 详细解析 |
| :---: | :---: | :---: | :--- |
| **第 1 字节** | 帧起始符 (**Head / STX**) | `02H` (`XON`) | 标识一帧数据的开始 |
| **第 2 字节** | 符号位 (**Sign**) | `+` (`2BH`) 或 `-` (`2DH`) | 重量正负号 |
| **第 3~8 字节** | 重量数据位 (**Data**) | `000000` ~ `999999` | 6位ASCII数字，从高位到低位表示数值 |
| **第 9 字节** | 小数位数 (**Decimal**) | `0` ~ `4` | 标识小数点后保留的位数 |
| **第 10 字节** | 状态位/校验位 (**Status**) | 校验和位 | 通常为 `第2字节 ⊕ 第3字节 ⊕ ... ⊕ 第9字节` |
| **第 11 字节** | 帧结束符 1 (**CR**) | `0DH` (`
`) | 回车符 |
| **第 12 字节** | 帧结束符 2 (**LF**) | `0AH` (`
`) | 换行符 |

### 3. 特性与优缺点
* **优点**：**实时性高 (High Real-time Performance)**，上位机逻辑简单（只需单向接收解析）。
* **缺点**：仅支持 **点对点 (Point-to-Point)** 连接，不能多台仪表挂载同一 RS485 总线。

---

## 三、 `tF=1` 模式深度分析（指令应答模式）

### 1. 工作原理与机制
在 `tF=1` 模式下，仪表作为 **从机 (Slave)** 运行。仪表**绝不主动发送数据**，只有在收到上位机（主机/Master）匹配地址的查询指令后才回复。

### 2. 指令与应答帧结构
* **主机发送指令格式**：`[地址码 Adr] + [命令码 Command] + [结束符 CR/LF]`
* **常见命令代码（历史摘录；现场无效，勿用）**：
  * **`R` (Read)**：~~读取当前称量数据~~ — **无效**
  * **`T` (Tare)**：~~去皮操作~~ — **无效**
  * **`Z` (Zero)**：~~置零操作~~ — **无效**

> **无效说明（2026-09-15）**：上表 `R` / `T` / `Z`（`Adr+Cmd+CR/LF`）经现场与 Demo 对照后判定为**无效命令**，不得用于 MaterialClient / Demo 生产或验收路径。  
> **有效 tF=1 命令**为 XOR 帧 `STX + Adr + Cmd + XOR + ETX` 下的 **`A`（握手）/ `B`（毛重）/ `C`（皮重）/ `D`（净重）/ `E`（车号）/ `F`（货号）**（见 MaterialClient.Demo `YaohuaTf1Protocol`）。

### 3. 特性与优缺点
* **优点**：支持 **RS485 多机总线组网 (Multi-drop RS485 Bus)**；支持上位机按需获取与双向控制。
* **缺点**：实时性依赖上位机轮询周期，软件开发需处理超时重发机制。
* **控制注意**：文档旧述「可发送去皮 `T`、清零 `Z`」属**无效表述**；去皮/置零请用仪表面板或其它已验证手段，勿发 `T`/`Z` 行命令。

## 四、 如何获取皮重、毛重与净重

在实际工程应用中，地磅显示的三个核心参数定义如下：
* **毛重 (Gross Weight)**：车辆/容器与货物相加的总重量。
* **皮重 (Tare Weight)**：空车/空容器的重量。
* **净重 (Net Weight)**：实际货物的纯重量，计算公式为：$$	ext{净重 (Net Weight)} = 	ext{毛重 (Gross Weight)} - 	ext{皮重 (Tare Weight)}$$

耀华地磅仪表提取这三个参数主要有两种途径：

---

### 途径一：通过仪表原生串口数据帧直接读取

在耀华标准数据格式中，`tF=0` 或 `tF=1` 返回的数据帧通常直接传输 **当前显示屏显示的重量值**（即**显示重量 Displayed Weight**），同时会在状态字节或专门的拓展扩展格式中提供皮重标志与毛/净重标志。

#### 1. 单重量传输模式（标准 12 字节帧）
在标准 12 字节帧中，数据字节传回的是当前显示值：
* **未去皮状态 (Gross Mode)**：此时传回的数据即为 **毛重 (Gross Weight)**，皮重为 `0`，**净重 = 毛重**。
* **已去皮状态 (Net Mode)**：仪表在执行“去皮”扣除皮重后，数据字节传回的数据即为 **净重 (Net Weight)**。
  * **状态标志识别 (Status Flag Identification)**：第 10 字节（状态位）的某些 Bit 位或状态字符标识了当前处于毛重模式还是净重模式：
    * **`NET` 标志位置位**：表示当前传输值为净重。
    * **`GROSS` 标志位置位**：表示当前传输值为毛重。

#### 2. 双重量/三重量拓展格式帧（如 A9/A9+ 拓展协议格式）
部分耀华仪表配置为全数据帧格式时，一帧完整数据中会显式包含毛重与皮重两个字段：

$$	ext{数据帧：} 	ext{[Header]} + 	ext{[毛重 Gross Weight (6位)]} + 	ext{[皮重 Tare Weight (6位)]} + 	ext{[状态位 Status]} + 	ext{[CR/LF]}$$

* **解析逻辑 (Parsing Logic)**：
  1. 提取 **毛重字段 (Gross Weight Field)**，带入小数点转换为数值；
  2. 提取 **皮重字段 (Tare Weight Field)**，带入小数点转换为数值；
  3. 通过计算式生成净重：`Net Weight = Gross Weight - Tare Weight`。

---

### 途径二：通过上位机称重业务逻辑计算获取（无人值守/二次过磅标准流程）

在绝大多数地磅应用场景（如汽车衡称重管理系统）中，单靠串口当前一帧数据无法完成完整称重业务。标准做法是**通过上位机软件数据库结合二次过磅流程计算获取**：

#### 业务流程说明：

```
[车辆第一次过磅] ──> 读取串口重量 ──> 存为 第一次重量 (如: 毛重 Gross Weight)
                                             │
                                             ▼
[车辆第二次过磅] ──> 读取串口重量 ──> 存为 第二次重量 (如: 皮重 Tare Weight)
                                             │
                                             ▼
                                 [上位机自动计算净重]
                           Net Weight = Gross Weight - Tare Weight
```

1. **重车进场（第一次过磅 / First Weighing）**：
   * 货车装满货物驶上地磅。
   * 上位机从串口读取当前稳定重量，记录为 **毛重 (Gross Weight)**（例如：`40,000 kg`）。
2. **空车出场（第二次过磅 / Second Weighing）**：
   * 货车卸货后空车再次驶上地磅。
   * 上位机从串口读取当前稳定重量，记录为 **皮重 (Tare Weight)**（例如：`15,000 kg`）。
3. **软件自动计算净重 (Net Weight Calculation)**：
   * 上位机称重软件根据绑定的车牌号（Vehicle Plate Number）检索两次记录，自动计算：
     $$	ext{净重 (Net Weight)} = 40,000 	ext{ kg} - 15,000 	ext{ kg} = 25,000 	ext{ kg}$$
4. **已知固定皮重模式 (Preset Tare Mode)**：
   * 如果车辆皮重已预先登记入库（Preset Tare），当重车驶上地磅时，上位机从串口读取当前数值作为 **毛重 (Gross Weight)**，直接调取数据库中的 **预置皮重 (Preset Tare Weight)** 计算得出 **净重 (Net Weight)**。

## 五、 `tF=0` 与 `tF=1` 模式对比总结

| 对比维度 | `tF = 0`（连续发送模式 / Continuous） | `tF = 1`（指令应答模式 / Command-Response） |
| :--- | :--- | :--- |
| **数据传输主控方** | **仪表主动发送 (Active Transmission)** | **上位机主动请求 (Master Polling)**，仪表被动响应 |
| **总线拓扑结构** | 仅支持 **点对点 (Point-to-Point)** | 支持 **多点总线 (Multi-drop RS485 Bus)** |
| **数据实时性** | **高 (High)**（10~25 Hz 无间断刷新） | **中/低 (Medium/Low)**（取决于轮询周期） |
| **上位机开发难度** | **简单 (Simple)**（仅单向接收解析） | **中等/复杂 (Moderate)**（需要超时重发与帧校验） |
| **控制交互能力** | **只读 (Read Only)** | **按需查询**（有效：`A/B/C/D/E/F` XOR 帧；~~`T`/`Z`/`R` 行命令~~ **无效**） |
| **重量提取机制** | 上位机实时解析广播帧中的当前重量及状态 | 上位机主动下发 **`B`/`C`/`D`**（XOR 帧）获取毛/皮/净，**`E`/`F`** 读车号/货号；~~`R`~~ **无效** |

---

## 六、 工程建议与选型指导

1. **单机标准称重管理**：
   若为“一机一磅”且仅需实时显示当前重量，推荐设置 **`tF=0`**。皮重、毛重、净重的逻辑在上位机过磅软件中进行保存和二次计算。
2. **多地磅/多模块组网及自动化控制**：
   若需接入 PLC 或多台地磅集中控制，必须设置 **`tF=1`**，并通过 **有效 XOR 帧命令 `B`/`C`/`D`/`E`/`F`**（及握手 `A`）取重与读号；**勿**使用手册行命令 `R`/`T`/`Z`（**无效**）。去皮/置零优先仪表面板。
