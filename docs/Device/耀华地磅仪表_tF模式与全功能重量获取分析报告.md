# 耀华（XK3190系列）地磅仪表串口通讯模式与全功能数据获取分析报告

本报告针对 **上海耀华（Yaohua）XK3190系列称重显示控制器**（如 A9 / A9+ / DS3 / A12 等地磅仪表）的串口通讯模式进行深度分析，重点梳理 **`tF=0`（连续发送模式 / Continuous Mode）** 与 **`tF=1`（指令应答模式 / Command-Response Mode）**，并解答在**无需修改仪表配置（No Configuration Change Required）** 的前提下，能否**同时获取实时数据流（Real-time Data Stream）以及皮重（Tare Weight）、毛重（Gross Weight）、净重（Net Weight）**。

---

## 一、 参数背景与配置项说明

在耀华称重仪表的系统参数设置中，`tF` 参数代表 **通讯方式控制字 (Transmission Format / Trigger Format)**：

* **`tF = 0`**：**连续发送模式 (Continuous Transmission Mode)**
* **`tF = 1`**：**指令应答模式 (Command-Response / Polling Mode)**

配套参数：
* `bAud`：波特率（Baud Rate，如 2400 / 4800 / 9600 bps 等）
* `Adr`：通讯地址（Address，范围 01 ~ 26，在 `tF=1` 轮询模式下必须指定唯一地址）

---

## 二、 核心疑问解答：无需修改配置，能否兼顾实时数据与皮重/毛重/净重？

**答案是：可以，完全可以通过 `tF=0`（连续发送模式）或特定配置直接实现。**

耀华仪表在设计上**并没有一个专门的“第三种混合模式”**，但**通过选用 `tF=0` 模式，结合上位机的软件解析/运算逻辑（或仪表内置的双串口输出/拓展数据帧），可以在不修改仪表配置的情况下同时满足这两个需求。**

下面针对两种最具可行性的方案进行详细拆解：

---

### 方案一：基于 `tF=0`（连续发送模式）+ 上位机业务逻辑控制【工程最推荐 / 成本最低】

在 `tF=0` 模式下，仪表以 10~25 次/秒 的频率持续向串口广播当前称重数值。

#### 1. 实时数据获取（Real-time Data Stream）
* **实现原理**：上位机串口后台线程直接读取广播帧，实时刷新界面上的重量显示。

#### 2. 毛重、皮重、净重获取（Tare / Gross / Net Calculation）
在不需要切换 `tF` 配置的前提下，上位机通过业务逻辑配合仪表物理按键（或上位机下发键盘指令）完成：
1. **未去皮状态（Gross Mode）**：
   * 串口传来的数据即为 **毛重 (Gross Weight)**。
   * 上位机判定当前 **皮重 (Tare Weight) = 0**，**净重 (Net Weight) = 毛重**。
2. **去皮状态（Net Mode）**：
   * 司磅员按下仪表上的 **[去皮/Tare]** 键（或由软件发送去皮指令），仪表将当前重量锁存为皮重，并扣除皮重。
   * 随后串口持续传来的数据变为 **净重 (Net Weight)**。
   * 数据帧的第 10 字节（状态位 / Status Bit）中的 `NET` 标志位置 1，上位机通过识别该标志位，即可实时区分出当前收到的是毛重还是净重。
3. **二次过磅计算法（地磅标准业务流程）**：
   * 重车过磅：读取串口数据，保存为 **毛重**。
   * 空车过磅：读取串口数据，保存为 **皮重**。
   * 上位机自动计算：$$	ext{净重 (Net Weight)} = 	ext{毛重 (Gross Weight)} - 	ext{皮重 (Tare Weight)}$$

---

### 方案二：采用“拓展数据帧格式”（在 `tF=0` 下一次性传回所有重量）

部分耀华仪表（如 XK3190-A9 / A9+ 等）支持设置输出数据格式为**扩展帧格式（Extended Frame Format）**。

#### 扩展帧结构示例：
在此格式下，`tF=0` 每次主动发送的一帧数据中，直接**同时打包**了毛重和皮重：

$$	ext{数据包格式：} 	ext{[STX (帧头)]} + 	ext{[毛重 Gross (6位)]} + 	ext{[皮重 Tare (6位)]} + 	ext{[状态位 Status]} + 	ext{[CR/LF (帧尾)]}$$

* **获取方式**：
  * **实时数据 (Real-time Data)**：连续接收该数据帧（10~25 Hz 刷新）。
  * **毛重 (Gross Weight)**：直接截取数据包中的毛重字段。
  * **皮重 (Tare Weight)**：直接截取数据包中的皮重字段。
  * **净重 (Net Weight)**：上位机解析后通过 `Net = Gross - Tare` 实时计算。
* **特点**：**无需修改 `tF` 模式配置**，保持 `tF=0` 即可在单帧数据中同时获取所有重量指标。

---

### 方案三：硬件双串口独立输出（双通道模式 / Dual Serial Port Mode）

部分高配耀华地磅仪表提供 **RS232** 与 **RS485** 两个独立的串口输出通道（或 2 个串口配置）：

* **串口 1（通道 A）**：配置为 `tF=0`，专门连接外接大屏或实时监视器，持续推送 **实时重量 (Real-time Weight)**。
* **串口 2（通道 B）**：配置为 `tF=1`，连接上位机/工控机；取重应使用 **有效 XOR 帧命令 `B`/`C`/`D`**（见 Demo），**勿**下发手册行命令 `R`（**无效**）。

* **特点**：两个串口物理隔离，无需频繁在软件中修改 `tF` 配置，硬件上直接同时具备两种模式的优势。

> **无效命令（2026-09-15）**：`R`（读）/ `T`（去皮）/ `Z`（置零）及 `Adr+Cmd+CR/LF` 行格式经现场判定为**无效**，不得用于实现或验收。有效路径：`STX+Adr+Cmd+XOR+ETX` 的 **A/B/C/D/E/F**（E=车号、F=货号）。

## 三、 `tF=0` 与 `tF=1` 深度对比

| 对比维度 | `tF = 0`（连续发送模式 / Continuous） | `tF = 1`（指令应答模式 / Command-Response） |
| :--- | :--- | :--- |
| **数据传输主控方** | **仪表主动发送 (Active Transmission)** | **上位机主动请求 (Master Polling)**，仪表被动响应 |
| **总线拓扑结构** | 仅支持 **点对点 (Point-to-Point)** | 支持 **多点总线 (Multi-drop RS485 Bus)** |
| **数据实时性** | **高 (High)**（10~25 Hz 无间断刷新） | **中/低 (Medium/Low)**（取决于轮询周期） |
| **上位机开发难度** | **简单 (Simple)**（仅单向接收解析） | **中等/复杂 (Moderate)**（需要超时重发与帧校验） |
| **控制交互能力** | **只读 (Read Only)** | **按需查询**（有效：`A/B/C/D/E/F` XOR 帧；~~`T`/`Z` 行命令~~ **无效**） |
| **实时性与三重重量获取** | 可通过 **扩展帧** 或 **上位机业务逻辑** 实现 | 必须通过上位机循环下发查询指令实现 |

---

## 四、 总结与工程选型建议

1. **能否兼顾？**
   **完全可以。** 耀华仪表不需要在 `tF=0` 和 `tF=1` 之间来回切换配置。
2. **推荐做法（`tF=0` + 上位机逻辑）**：
   维持仪表配置为 **`tF=0`（连续模式）**，上位机负责实时读取数据流展示实时重量；当车辆完成过磅时，由上位机保存当前稳定帧（作为毛重或皮重），并通过二次过磅逻辑或状态标志自动计算出净重。这是绝大多数地磅无人值守软件的标准做法。
