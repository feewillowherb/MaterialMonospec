# 03 · 萧山上报映射

协议细节以设计稿为准，此处只写 **UrbanManagement 出站** 怎么选 Client、怎么填字段。

## 通道选择

| 源 | HTTP | `buildLicenseNo` |
|----|------|------------------|
| `UrbanWeighingRecord` | `POST /sapi/v1/inoutRecord/lantu/saveRecord` | 原值 `L` |
| 进出 + `Checkpoint` | `POST /sapi/v1/inoutRecord/save` | 原值 `L` |
| 进出 + `FinishedProduct` | 同上 | `XiaoshanBuildLicenseNo.ForProduct(L)` |

`L` 来自项目/场地配置（现网称重行上的 `BuildLicenseNo`）。进出行若不存 `L`，从 **同一项目** 配置读取，变换只做一次。

建议两个 Refit Client（或两个 `[Post]` 路径），两个 payload `record`：地磅 builder **不得**写入卡口字段集，卡口 builder **不得**写 `dataSource`。

## `UrbanWeighingRecord` → 地磅（摘录）

权威：地磅 SyncDoc + 设计稿 §3。现网 `GovSyncWeightPayload` **混有** `inOutType` 与 `deviceID`/`siteType`/`areaCode`，且 `IGovSyncHttpClient` 为 `[Post("")]`（基址即完整 URL）。落地时地磅报文应对齐 `lantu/saveRecord`（`dataSource`、`inOutType` 0/1、`goodsWeight`），不要继续用卡口 schema 冒充地磅。

重量：本地吨 vs 上云千克见 `repos/MaterialClient/AGENTS.md`；服务端已按 kg 存的保持一致。

## `UrbanPassageRecord` → 卡口/成品（摘录）

权威：场地 SyncDoc + 设计稿 §4–5。进出实体无 `goodsWeight`：卡口/成品该字段可选，**缺省不传或省略**，不要填 0 假装过磅。

| 实体 | 萧山 |
|------|------|
| `PlateNumber` | `carNo` |
| `PlateColor` | `carNoColor` |
| `VehicleType` | `carType` |
| `CapturedAt` | `snapTime`（`yyyy-MM-dd HH:mm:ss`） |
| 附件大图、小图 | `snapImages` Base64 数组，约定 `[大图, 小图]`；有则编、无则不凑 |
| `UrbanInOutType` | `deviceID`：`Enter` → `01`，`Exit` → `02`（不要用 `DeviceCode` 表示进出） |
| `UrbanSiteType` | `siteType`：`Construction` → `1`，`Disposal` → `2` |
| 配置 | `areaCode`（如 `330109`）、`spaceName` 可选 |
| 仅成品 | `buildLicenseNo` 后缀 `-02` |

成功：`code == 200`。Worker 应对进出表单独出队/重试，**不要**让 `GovSyncManager.GetPendingRecordIdsAsync` 只扫称重表却用进出 payload。
