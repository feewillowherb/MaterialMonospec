# 04 · 现网差距与开放问题

## 现网事实

`GovSyncManager.ProcessRecordAsync` 只处理 `UrbanWeighingRecord`，调用 `IGovSyncHttpClient.PostWeightAsync`，payload 由 `GovSyncWeightPayload.FromRecord` 生成（同时带重量相关字段与 `deviceID`/`siteType`/`areaCode`）。这是历史「单一场地进出 save」形态，**不是**设计稿中的三通道拆分。

因此：即使客户端已有 `UrbanPassageRecord`，不改 UrbanManagement 则进出 **既不上云也不上报**。

## 相对客户端进出 change 的缺口

| 已有 | 缺失（本夹范围） |
|------|------------------|
| 客户端 `UrbanPassageRecord` + LPR 路由 | 服务端表与 Receive |
| 客户端混合列表 + 卡口/成品 tab | UM **新增卡口页、成品页**（与称重页并列；本期查看、不上审批） |
| 设计稿三通道 | 两个 HTTP Client + Worker 分流 |
| 称重 `ReceiveAsync` | 进出上云与附件绑定 |

## 开放问题（继承设计稿，服务端视角）

| ID | 问题 | 对 UM 的影响 |
|----|------|----------------|
| Q1 | 地磅 `dataSource`：`WEIGHBRIDGE_XIAOSHAN` vs 示例 `WEIGHBRIDGE_TELECOM` | 称重上报拒收 |
| Q2 | 成品 `-02` 是否预登记 | 成品通道 4xx |
| Q3 | 同一 `L` 是否三通道全开 | 项目配置模型 |
| Q4 | `deviceID` 01/02 与地磅 `inOutType` 0/1 | 称重现网 `FromRecord` 把 `InOutType` 写死为 0，进出必须按快照映射 |
| Q5 | 基址 8899 环境差 | `appsettings` / Refit BaseAddress |

## 验收口径（服务端）

1. 称重记录只打 `lantu/saveRecord`，`buildLicenseNo = L`，无心跳。  
2. 卡口进出打 `inoutRecord/save`，`buildLicenseNo = L`。  
3. 成品打同一 `save`，`buildLicenseNo = L-02`，其余与卡口同 schema。  
4. 进出不入库 `UrbanWeighingRecords`；称重不入库进出表。  
5. 不把 `dataSource` 写入卡口/成品；不把 `-02` 拼到地磅或卡口原值。
