# 04 · 现网差距与开放问题

## 现网事实

`GovSyncManager.ProcessRecordAsync` 只处理 `UrbanWeighingRecord`，调用 `IGovSyncHttpClient.PostWeightAsync`，payload 由 `GovSyncWeightPayload.FromRecord` 生成（同时带重量相关字段与 `deviceID`/`siteType`/`areaCode`）。这是历史「单一场地进出 save」形态，**不是**设计稿中的三通道拆分。

因此：即使客户端已有 `UrbanPassageRecord`，不改 UrbanManagement 则进出 **既不上云也不上报**。

## 相对客户端进出 change 的缺口

| 已有 | 缺失（本夹范围） |
|------|------------------|
| 客户端 `UrbanPassageRecord` + LPR 路由 | 服务端表与 Receive |
| 客户端混合列表 + 卡口/成品 tab | UM **新增卡口页、成品页**（与称重页并列；本期查看、不上审批） |
| 设计稿三通道 | 卡口/成品/地磅 **独立出站代码**（允许重复）；Worker 按通道分流 |
| 称重 `ReceiveAsync` | 进出上云与附件绑定 |

## 开放问题（继承设计稿，服务端视角）

本节 Q1–Q5 **均已决**。下面保留实现约束，不再当联调未知项。

| ID | 决定 |
|----|------|
| **Q1** | 地磅 `dataSource` **恒为** `WEIGHBRIDGE_XIAOSHAN`。不要用示例里的 `WEIGHBRIDGE_TELECOM`，不要做成可配项（除非以后 change 明确改口）。 |
| **Q2** | 平台方 **看 `buildLicenseNo` 后缀**：有 `-02` → 成品；**无后缀** → 卡口。不是「必须先登记一条名为 `L-02` 的虚拟场地」才能识别。我方成品通道仍只拼一次 `-02`；卡口/地磅永不拼。 |
| **Q3** | 同一物理场地共用一份原值 `L`（地磅/卡口打 `L`，成品打 `L-02`）。平台侧卡口与成品是 **独立代码、各自重复实现**。UrbanManagement **同样**：卡口与成品用独立代码路径（上云入口、出站组包、Worker、列表页），**允许重复**，禁止「一个 Passage 上传 + if 后缀」揉成一支。地磅保持第三条独立路径。 |
| **Q4** | 领域进出（`UrbanInOutType` 等）与萧山报文码 **不是同一套值**。实现 **特定 Converter**，仅在 UrbanManagement **上传 Gov 时**调用：地磅走 `inOutType` 0/1，卡口/成品走 `deviceID` 01/02（及同套的 `siteType` 等）。落库仍存领域枚举；**禁止**现网 `FromRecord` 把 `InOutType` 写死为 0。Converter 为纯转换（static / 目标 payload 的 `From*` 委托），**不**注册 DI、**不**当 Service 逐字段赋值。卡口 Converter 与成品 Converter **分开实现**（可重复），不要共用一个「进出通道 Converter」再靠后缀分叉。 |
| **Q5** | 萧山 Gov **上报接口的 host**（scheme + host + port，不含具体 path）在 **UrbanManagement 独立配置**（如 `appsettings` / 运维配置）。不要写死 SyncDoc 示例 `172.18.34.209:8899`，也不要写死管线 demo `191.12.15.58:8899`，不要跟客户端本机配置绑死。三通道 path 不同（`lantu/saveRecord` vs `inoutRecord/save`），默认 **共用同一 host**；若现场地磅与场地接口不在同一基址，再拆两个 BaseAddress，仍全部在 UM 配。 |

### Q2 / Q3 对实现的含义

```text
平台：  save + L      → 走他们的「卡口」代码
        save + L-02   → 走他们的「成品」代码（与卡口独立、可重复）

我方：  来自 LPR 卡口  → 卡口落库 / 卡口页 / 卡口出站（buildLicenseNo = L）
        来自 LPR 成品  → 成品落库 / 成品页 / 成品出站（buildLicenseNo = L-02）
        地磅 LPR      → 称重落库 / 称重页 / 地磅出站（另一 path + L）
```

- 同一 URL **不能**成为「共用一套 C# 再参数化后缀」的理由；平台自己都是两套实现。
- 表可以仍是一张进出表 + `PassageSource`（避免成品第二张同构表），但 **Application / 出站 / 页面** 按通道拆开。
- 分流键仍是记录种类（来自 LPR 卡口 / 成品），**不要**用「有没有重量」或事后看后缀反推种类。

## 验收口径（服务端）

1. 称重记录只打 `lantu/saveRecord`，`buildLicenseNo = L`，无心跳；`dataSource` **恒为** `WEIGHBRIDGE_XIAOSHAN`。  
2. 卡口进出打 `inoutRecord/save`，`buildLicenseNo = L`（无 `-02`）。  
3. 成品打同一 path 的 `save`，`buildLicenseNo = L-02`；卡口与成品出站代码独立、允许重复。  
4. 进出不入库 `UrbanWeighingRecords`；称重不入库进出表。  
5. 不把 `dataSource` 写入卡口/成品；不把 `-02` 拼到地磅或卡口原值。  
6. 出站进出码只经各通道 Converter（地磅 `inOutType`、卡口/成品各自 `deviceID`），不以库内枚举原样当萧山字段、不写死进。  
7. Gov 上报 host 只读 UM 独立配置，不写死文档/管线 IP。
