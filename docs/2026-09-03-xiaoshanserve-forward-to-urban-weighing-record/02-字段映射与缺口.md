# 02 · 字段映射与缺口

## 2. 硬缺口（实现前必须定）

### 2.1 `ClientRecordId` 幂等键

Modern Receive **强制**非空 Guid，并以此去重。Legacy 报文无此字段。

可选策略：

| 策略 | 优点 | 风险 |
|------|------|------|
| A. 每次 `Guid.NewGuid()` | 实现简单 | 客户端重试产生重复称重行 |
| B. 确定性 Guid（如 UUID v5：`AccessCode|snapTime|carNo|deviceID|goodsWeight`） | 同报文重试幂等 | 字段碰撞 / 合法修正被当成同一条需约定 |
| C. 适配层本地映射表（旧主键 ↔ Guid） | 可控 | 又引入状态存储 |

**调研建议默认 B**，与 INT-006 一并拍板；哈希盐写入配置。

### 2.2 `ProId` / 项目主数据

- XiaoShanServe：`ProId` 字符串，库在 `XiaoShan.db`
- UM：`GovProject.Id` 为 Guid，`AccessCode` 为接入码

同机也不共享 DB → 适配层必须：

1. 用报文 `buildLicenseNo`（或凡东码换出的城管码）查 **UM** `GovProject`
2. `ProId = project.Id`，`ProName = project.ProName`
3. 查不到 → 拒收（对齐现网「对接码未接入」）

凡东码：仅可在 XiaoShanServe 过渡期用其本地 `FdBuildLicenseNo` 表换码；UM 侧 **不再**存凡东码。长期应推动客户端直接报城管 `AccessCode`。

### 2.3 图片

```text
snapImages[] base64
    → IFileService.SaveAndCompressImagesAsync(..., AttachType.Lpr 或 UrbanPhoto)
    → List<Guid> AttachmentIds
    → ReceiveAsync
```

注意：

- AttachType 仅允许 Lpr(5) / UrbanPhoto(6)
- 多图时序：Legacy 不区分 LPR/现场图；可全部 `UrbanPhoto`，或首张 Lpr 其余 UrbanPhoto（需产品确认）
- XiaoShanServe 现行本地落盘路径 **不应**再作为权威存储；以 UM `AttachmentFile` 为准，避免双份磁盘

### 2.4 重量单位

Spec：`TotalWeight` = **千克**。Legacy `goodsWeight` / `grossWeight` 现网亦为 kg 语义 → 直接 decimal，**不要**再 ×1000。

## 3. ApiController 现行权重逻辑（须复现）

```text
goodsWeight → syncData.goodsWeight
若 grossWeight 有值且 > 0 → 覆盖为 grossWeight 字符串
```

转发到 UM 时应对齐，避免与历史 XiaoShanServe 行为漂移。

## 4. 响应契约

XiaoShanServe 成功时大致：`{ success, msg, code: 200 }`（经 `JsonDate(result)`）。

UM Legacy stub：`code: 501`。

对外兼容要求：地磅客户端是否硬编码 `code==200` / `success==true`。实现 INT-006 或转发层时 **保持旧响应形状**，内部再调 Receive。
