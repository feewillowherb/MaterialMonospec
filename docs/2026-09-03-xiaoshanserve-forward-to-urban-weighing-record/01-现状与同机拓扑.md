# 01 · 现状与同机拓扑

## 1. XiaoShanServe 现行入站

入口：`repos/Fdsoft.Weight.GovClient/FdSoft.MaterialSys.Gov.XiaoShanServe/Controllers/ApiController.cs`

- 路由：`[Route("Api/[action]")]` → **`POST /Api/Post`**
- Body：`dynamic` → `mGovRequestWeight`（Newtonsoft）
- 校验：
  - `buildLicenseNo` 与 `fdBuildLicenseNo` 皆空 → 拒收
  - `fdBuildLicenseNo` → 查本地 `GovProject.FdBuildLicenseNo`，回填城管 `buildLicenseNo` / `ProId` / `ProName`
  - `buildLicenseNo` → 查 `GovProject.BuildLicenseNo`
- 副作用：
  - Base64 `snapImages` 落盘 `{FilesPhysicalPath}/TempUpload/{buildLicenseNo}/{ticks}_{i}.jpg`
  - 插入本地 SQLite 表 `Gov_SyncData`（`SyncType=0` 待同步）
- 出站：`ExplortStatisticBgService` 轮询待同步行，拼 `mGovRequestWeight`，POST `GovAddress`（`appsettings.json` 现为政府 `inoutRecord/save`）

本地库与配置：

| 项 | 现状 |
|----|------|
| DB | `XiaoShan.db`（SqlSugar，`conn_db_type: 2`） |
| 文件根 | `FilesPhysicalPath`（例 `D:\Findong.XiaoShan\`） |
| 项目表 | `Gov_Project`：`ProId` 为 **string**；仍含 `FdBuildLicenseNo` |

## 2. UrbanManagement 现行接收

### 2.1 Modern（目标落点）

`IUrbanWeighingRecordAppService.ReceiveAsync(UrbanWeighingRecordReceiveInputDto)`：

- 校验 `ClientRecordId != Guid.Empty`、`ProId` 非空 Guid
- 按 `ClientRecordId` 幂等：已存在则更新可纠正字段，**不**追加附件
- 新建：映射到 `UrbanWeighingRecord`（`AccessCode = input.BuildLicenseNo`）
- 可选 `AttachmentIds` → `UrbanWeighingRecordAttachment`
- **不**写入 `GovSyncData`（entity 语义化决策 D19）

实体要点（`UrbanWeighingRecord`）：

- `ClientRecordId` Guid（唯一）
- `PlateNumber` / `TotalWeight`(kg) / `WeighingTime`
- `VehicleColor` / `PlateColor` / `VehicleType` / `DeviceId`
- `AccessCode` / `SiteType`(`UrbanSiteType`) / `ProId`(Guid) / `ProName`
- 出站同步字段：`SyncType`(`SyncStatus`) 等，由 UM Worker 推政府

附件：先 `IFileService.SaveAndCompressImagesAsync(base64[], buildLicenseNo, AttachType)` 得 Guid 列表，再塞进 Receive。

### 2.2 Legacy（同路由、WIP）

`LegacyApiController`：

- 路由同样是 **`Api/[action]` → `POST /Api/Post`**
- 注释写明：接受旧版 GovClient POST
- 解析字段与 XiaoShanServe `mGovRequestWeight` **同形**（含 `fdBuildLicenseNo`、`snapImages`）
- `LegacyGovSyncAppService.ProcessLegacyRequestAsync` **固定**返回 `(false, "WIP: legacy endpoint unavailable", 501)`

即：UM **已经预留了与 XiaoShanServe 相同的入站门面**，缺的是 INT-006 实现，而不是新协议。

### 2.3 UM `GovProject`

- 主键 `Id` 即业务 `ProId`（Guid）
- 接入码属性：`AccessCode`（原 `BuildLicenseNo`）
- **已移除** `FdBuildLicenseNo`
- 同步开关：`IsSyncEnabled`

XiaoShanServe 本地 `Gov_Project` 与 UM `GovProjects` **不是同一库**；同机部署也不自动共享项目表。

## 3. 同机部署拓扑（用户前提）

```text
地磅/旧客户端
      │  POST /Api/Post  (mGovRequestWeight JSON)
      ▼
┌─────────────────────────────────────────────┐
│ 同一物理机 / 同一 IIS 或两进程               │
│                                             │
│  XiaoShanServe (.NET 6, SqlSugar SQLite)    │
│       ApiController → GovSyncData           │
│       BgService ──► 政府 API                │
│                                             │
│  UrbanManagement (ABP, EF SQLite/…)         │
│       LegacyApiController → 501 WIP         │
│       ReceiveAsync → UrbanWeighingRecord    │
│       GovSync Worker ──► 政府 API           │
└─────────────────────────────────────────────┘
```

### 3.1 冲突点

| 冲突 | 说明 |
|------|------|
| 路由同名 | 两边都是 `/Api/Post`；不能无差别绑同一站点根路径 |
| 端口 | 必须用不同 port / 不同站点 / 反代路径前缀区分 |
| 项目主数据 | 对接码、ProId 两套库；转发前须约定以 **UM `GovProject.AccessCode`** 为准 |
| 出站双报 | 若 XiaoShanServe 仍写 `GovSyncData` 并推政府，同时 UM 收到后 Worker 再推 → **同一车次双报** |

### 3.2 期望数据流（目标）

```text
地磅客户端 → LegacyApiController /Api/Post（薄门面）
           → LegacyGovSyncAppService          ← 转换核心（IngestSource=Legacy）
                → IFileService + ReceiveAsync
           → UrbanWeighingRecord.IngestSource = Legacy
           →（仅）UM GovSync Worker → 政府
```

XiaoShanServe 不承担转换；切流后停其对该流量的 `GovSyncData` 插入与出站。Modern Receive 路径写 `IngestSource = Modern`。
