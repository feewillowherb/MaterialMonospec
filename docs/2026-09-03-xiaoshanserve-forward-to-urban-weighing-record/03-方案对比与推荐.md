# 03 · 方案对比与推荐

## 分层（已确认）

| 层 | 类型 | 职责 |
|----|------|------|
| `LegacyApiController` | HTTP 门面 | `JsonElement` → `LegacyGovSyncRequestInputDto`；返回旧版 `{ success, msg, code }` |
| **`LegacyGovSyncAppService`** | **转换业务核心** | AccessCode/`ProId` 校验、重量/SiteType/`ClientRecordId`、存图→`AttachmentIds`、调用 `ReceiveAsync`、组装 `LegacyGovSyncOutputDto` |
| `IUrbanWeighingRecordAppService` / `IFileService` | Modern 能力 | 幂等入库与附件；**不**懂旧报文形状 |

**禁止**把映射/换码/幂等键生成写进 Controller 或 XiaoShanServe。

## 方案一览

| 方案 | 做法 | 状态 |
|------|------|------|
| **B. UM Legacy（INT-006）** | 转换核心在 `LegacyGovSyncAppService`；切流到 UM `/Api/Post` | **已确认** |
| A. XiaoShanServe HTTP 调 UM | 仅运维切流过渡；**不得**在 Serve 侧重做转换 | 非核心；尽量不做 |
| C. 直连 Modern Receive | 改客户端协议 | 非本需求 |

均须：**只写 `UrbanWeighingRecord`，禁止 `GovSyncData` 双写**；政府出站只走 UM Worker。

## A · XiaoShanServe → UM HTTP

```text
Client → XiaoShanServe /Api/Post
       → (可选本地凡东码换 AccessCode)
       → HTTP localhost:{umPort}/api/.../upload + receive
       → 返回旧版 success/msg/code
```

**优点**

- 对外 URL / 端口可不变
- 凡东码换码可继续用 XiaoShanServe 本地表（过渡）

**缺点**

- 两进程运维；鉴权、超时、部分失败（图已传记录未建）要处理
- 易误留 `Insertable(GovSyncData)` → 双报
- 与 INT-006 目标重复，债务搬家

**同机配置要点**

- `appsettings` 增加 `UrbanManagement:BaseUrl`、上传/Receive 路径、内部密钥或机器账号
- **关闭**本进程 `ExplortStatisticBgService` 对该来源的出站，或直接不写 `GovSyncData`
- 磁盘：优先把 base64 交给 UM，不在 XiaoShanServe 再存权威副本

## B · `LegacyGovSyncAppService` 实装（已确认）

```text
Client →（反代或改绑）→ LegacyApiController /Api/Post
       → LegacyGovSyncAppService.ProcessLegacyRequestAsync   ← 转换核心
            查 GovProject by AccessCode（fd 码若保留仅在此层过渡换码）
            IFileService.SaveAndCompressImagesAsync
            构造 UrbanWeighingRecordReceiveInputDto（ClientRecordId 策略）
            IUrbanWeighingRecordAppService.ReceiveAsync
            return LegacyGovSyncOutputDto
       → Controller 映射旧版 JSON
```

Service 内建议顺序（实现时写入 tasks）：

1. 拒收：无 `buildLicenseNo`（及约定的换码失败）  
2. 解析重量（对齐 XiaoShanServe：`grossWeight>0` 覆盖）与 `WeighingTime`  
3. 查 `GovProject` → `ProId` / `ProName`  
4. 存图 → `AttachmentIds`  
5. 生成 `ClientRecordId` → `ReceiveAsync`  
6. 异常 → `success=false` + 明确 `msg`/`code`（业务拒收 vs 501 仅用于未实现）

**同机切流**（与转换核心正交）：IIS 反代 / 改绑 port / 停 XiaoShanServe 入站；Serve 侧**不**复制上述步骤。

## A / C（非核心）

- **A**：若必须短时保 XiaoShanServe URL，只做反向代理到 UM `/Api/Post`，**禁止**在 Serve 内映射字段。  
- **C**：直连 Modern 需改客户端，不在本夹范围。

## 明确不做

| 做法 | 原因 |
|------|------|
| 转换写在 `LegacyApiController` 或 XiaoShanServe `ApiController` | 违背已确认 D1 |
| Receive 同时 Insert `GovSyncData` | 违反 D19；双报风险 |
| 把 `snapImages` 路径塞回实体 | 实体已无 `SnapImages` |
| 共享 SQLite 直写对方表 | 绕过 Receive 幂等与附件模型 |
| 用 tuple 做映射返回值 | 仓库 C# 约定：命名 `record` |
