## 1. 一句话

产品口语里的「上传日志」实际是：**管理端发起、经 Realtime 的 SignalR 反向拉取** MaterialClient.Urban 本机 `Logs/` 下的 `.log`，在 Realtime 进程落盘到 `ClientLogs/`，再由 Admin 页面浏览 / 下载。客户端不会主动把日志 POST 到 HTTP API。

## 5. 与切流 / 诊断的关系

- 该功能**依赖 Realtime 单实例**（Hub 静态状态）；切 IIS→Docker 后行为不变，但 Realtime 容器重启 = 所有在线「可拉日志」客户端需重新 `RegisterLogCapability`。
- 缓存目录在 Realtime 容器的 `um-clientlogs` volume（`/app/ClientLogs`），与业务附件 `Uploads` 分离。
- 排查「拉日志失败」优先看：Realtime 文件日志、Hub 是否映射、客户端是否 Connected 且能力已注册、Admin→Realtime internal HTTP 是否 200。
