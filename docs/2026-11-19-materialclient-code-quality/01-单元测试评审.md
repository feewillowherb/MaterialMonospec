## 补强顺序

1. 门禁先纳入已有 UI 和 Urban 测试，留存 TRX 与 Cobertura。对偶发的 Mock 内存检查先明确测量对象和运行隔离条件。
2. 优先覆盖 Urban 上传失败与重试。用生产服务加可控 HTTP 响应和临时 SQLite，检查重试后的请求、附件关联以及最终同步状态。预期以相应 OpenSpec 和接口契约为准。
3. 用可控事件和完成信号覆盖称重匹配及跨周期恢复，再用临时 SQLite 验证写入中途失败、回滚与重启恢复。用定向变异验证测试确实能抓到去重失效、周期状态串用和提前标记同步成功。
4. 按跳过原因恢复可确定性执行的行为用例，依赖实体地磅、相机、打印机的项由独立设备验证承接。

本次评审采集运行证据并抽查断言，未执行变异测试、现场设备验证，也未修改测试或产品实现。
