# 00 调研总览 — Recycle Web 表结构讨论

> 生命周期：`ACTIVE`  
> 知识状态：独立建表方向沿用 2026-11-16 的 ADOPTED；列、表名、DbContext 仍是 `PENDING_VALIDATION`。  
> 类型：设计讨论（非 OpenSpec change，非产品通过）

先读本文件，再读 [`01-候选表与待决问题.md`](01-候选表与待决问题.md)。

## 1. 这条讨论解决什么

资源化网页现在是 `UrbanManagement.XiaoShanResource` 的内存 mock，工程内没有 `DbContext`。工控宿主已经能在本地落下 `WeighingRecord`（模式 301），上传仍停在「我方 Recycle receive API 尚未接入」。

本夹用来讨论我方平台上的 Recycle 表：车辆信息池、合同、日产量、运输清单，以及它们怎么接住工控上传的车牌、毛重、时间和照片。讨论结论留在本夹。要改库或改页面，另开 OpenSpec change，并要有 Human `APPROVED`。

## 2. 已经定下的边界

来源：[`docs/2026-11-16-materialclient-recycle-resource-alignment/`](../2026-11-16-materialclient-recycle-resource-alignment/00-调研总览.md)，其中独立建表见 [`03-urbanmanagement-recycle实现.md`](../2026-11-16-materialclient-recycle-resource-alignment/03-urbanmanagement-recycle实现.md)，四页字段见 [`04-业务闭环.md`](../2026-11-16-materialclient-recycle-resource-alignment/04-业务闭环.md)。

| 项 | 结论 | 状态 |
|----|------|------|
| 业务表不复用城管 `GovProjects`、称重接收表、卡口表 | 资源化主存用自己的表 | ADOPTED |
| 可以与城管同一个 SQL Server / Database | 「独立」指表和模型归属 | ADOPTED |
| 表间用逻辑 `{Related}Id` | 不做数据库外键，不做 EF 关系映射 | ADOPTED |
| 运输清单是工控毛重落点 | 生产管理是日产量，不是过磅落点 | ADOPTED |
| 净重 = 毛重 − 车辆池皮重 | 工控不上传皮重、净重，也不强制合同号、产品、收货凭据 | ADOPTED |
| 现有 mock change | `add-xiaoshan-resource-web`、`add-xiaoshan-resource-production-transport` 继续不落库 | ADOPTED |

Git 基线仍是 Mode B 的 `dev-recycle-resource-alignment`。本夹不代替那条分支上的提交。

## 3. 本夹不决定

- 市平台第二跳 Worker、HMAC、厂标识配置。
- Web 工程从 `XiaoShanResource` 改名，Cookie 和 compose 名。
- 渣土进厂、物料进场、废弃物、回填（§2.1、§2.3、§2.8、§2.9、§2.10）。
