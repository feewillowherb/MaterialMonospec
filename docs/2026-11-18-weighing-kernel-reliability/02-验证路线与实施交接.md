# 验证路线与实施交接

先读 [00-调研总览.md](00-调研总览.md)。本文件是调研路线，不是已执行实验结果。

## 待验证问题

| 顺序 | 问题 | 最小实验与观察 | 对路线的影响 |
|---|---|---|---|
| 1 | 唯一稳定任务能否跨周期串牌或污染新周期 recordId？ | 已执行，见 [03-FEV-跨周期串数据.md](03-FEV-跨周期串数据.md)。两条时序都成立 | 周期身份要覆盖抓拍前、插入前和 recordId 回写。只在抓拍结束后查一次不够 |
| 2 | 同周期重复创建有哪些实际入口？ | 搜索全部调用点；先构造两个调用在 Insert 前同时到达的测试，再区分生产链是否可到达；覆盖 Urban 开关开/关 | 决定幂等范围，不由检查一次 recordId 代替并发保护 |
| 3 | 失败分别停在哪个阶段？ | 注入抓拍异常、Insert 失败、事务完成失败及记录提交后附件失败；观察后续动作、数据库状态、日志和状态 ID | 决定结果类型与可重试阶段，避免重试已提交创建 |
| 4 | 下磅失败是否污染下一周期？ | 在改牌与 Finalize 分别注入失败，记录缓存、周期 ID 和下一车信息；验证恢复后是否丢失待收尾记录 | 决定保留何种待恢复状态，避免无条件 ResetCycle |

第 1 项已在测试宿主执行。第 3、4 项已完成 Insert、改牌读取及 Finalize 边界异常注入，见 [06](06-异常注入与恢复调查.md)；事务完成、附件及完整同步链尚未全部验证。风险复现与候选修复方案的可行性是两个问题，复现成功不等于方案 FEASIBLE。

## 执行约束

- 优先复用现有测试基础设施，用显式屏障和有界完成信号控制时序，不靠固定延迟制造偶现。
- 后续若要增加测试代码，先读取子仓 AGENTS 与适用 traits，遵守对应分支及测试约定；本次不修改子仓。
- 不改生产数据库、真实地磅或现场车牌数据。需要诊断 API 的实验先核对环境与现行 Graph 合同；本 topic 不授权直接 cook。
- 每次实验记录代码基线、输入、命令、实际结果及可复用证据路径；没有执行就保持待验证。失效基线不继续作为当前结论。
- 研究停止条件：证据已足以决定实现范围与设计边界，或新的实验不会改变路线；不以固定实验数量替代判断。

## 产品实施前的决定

1. 迟到采集结果允许丢弃或形成不完整记录；B 车不得使用无法确认归属的旧结果。已确认规则及诊断字段要求以 [04-已确认业务决策.md](04-已确认业务决策.md) 为准。补查设备请求关联能力，不能假设周期号能识别所有回包。
2. 明确同周期唯一建单身份，以及重新上磅、同车再次称重和 Urban 缓存的边界。
3. 无图片、无车牌不得阻塞同步，已获 Human APPROVED；仍需明确其他失败的用户可见行为和恢复责任，并核查同步链契约。

形成上述可评审方案并取得 Human APPROVED 后，再在主仓 openspec 中创建 change。建议周期隔离与并发防重联合设计，失败反馈与收尾恢复按依赖拆分实施；不预先承诺所有内容必须合成一个大型 change。

运行时验收需覆盖普通模式与受影响的 Urban 模式、正常称重、晚到识别、异常离磅、失败恢复和连续车辆。测试完成与 Capability Acceptance 分开报告，不以本 topic 的静态结论宣布交付。
