# 02 根因与代码路径

> 知识状态：下列路径与行为对照当前 `repos/MaterialClient` 源码为 `CONFIRMED`。

## 1. 根因一句话

同一次判稳把 `OnWeightStabilizedAsync(闭包吨数)` 入队两次；第二次建单无防重；音响占满共享异步槽后迟到执行，落成「上一车吨数 + 当时车牌」的新票。

## 2. 双入队（同帧）

文件：`repos/MaterialClient/src/MaterialClient.Common/Services/AttendedWeighing/AttendedWeighingService.cs`  
方法：`OnWeightAndStatusChanged`

1. `WaitingForStability → WeightStabilized` 且 `GetLastCreatedWeighingRecordId() == null`  
   → `Enqueue(OnWeightStabilizedAsync(weightToUse))`（日志：`status transition`）
2. `ProcessStatusTransition`（含策略扩展 + **播报**入队）
3. `UpdateStatusAndNotify(WeightStabilized)`
4. backup：`newStatus == WeightStabilized && IsStable && recordId == null`  
   → **再** `Enqueue(OnWeightStabilizedAsync(weightToUse))`（日志：`backup check`）

第一次入队尚未执行，故 `recordId` 仍为 null，backup 几乎总会在同一次回调里再入队一次。

## 3. 建单无防重（与 spec 不符）

Spec（`openspec/specs/attended-weighing/spec.md`）：

> WHEN CreateWeighingRecordAsync is called but recordId is already non-null  
> THEN SHALL not create a second record

实现：`WeighingRecordService.CreateWeighingRecordAsync` **没有**读 `GetLastCreatedWeighingRecordId()` 做跳过；每次调用都 `InsertAsync`，成功后再 `SetLastCreatedWeighingRecordId`。

因此两次排队的 `OnWeightStabilizedAsync` 只要都跑到建单，就会两张库记录。

## 4. 闭包吨数

```csharp
var weightToUse = stability.StableWeight ?? weight;
EnqueueAsyncOperation(async () => await OnWeightStabilizedAsync(weightToUse));
```

`weightToUse` 在入队瞬间固定。迟到执行时不会重读地磅；`OnWeightStabilizedAsync(decimal currentWeight)` 的参数名易误解为「当前活重」，实际是闭包值。

## 5. OffScale 清周期

`WaitingForDeparture → OffScale`（及若干异常离磅）→ `RewriteAndResetCycleAsync` → `WeighingStateManager.ResetCycle()`：

- `_lastCreatedWeighingRecordId` → null  
- 清本周期 LPR / 车辆信息缓存  

迟到的第二次建单：

- 仍用旧闭包吨数；
- 车牌取当时 `GetMostFrequentPlateNumber()` / LockedAt（常已是下一车或晚到事件）。
