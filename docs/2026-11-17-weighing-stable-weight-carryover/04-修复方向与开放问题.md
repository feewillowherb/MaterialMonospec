## 1. 候选改法（按杠杆）

| 优先级 | 改动 | 作用 |
|--------|------|------|
| P0 | 同帧只允许一条建单入队：status-transition 已入队则跳过 backup；或 backup 仅在「已是 WeightStabilized 但从未入队」的后续采样使用 | 去掉同吨双任务源 |
| P0 | `CreateWeighingRecordAsync` 开头：若 `GetLastCreatedWeighingRecordId() != null` 则直接 return（对齐 attended-weighing spec） | 防真·双建库 |
| P1 | 入队携带 `cycleToken` / 世代号；`ResetCycle` 递增世代；执行建单前校验世代，过期则丢弃 | 挡住 OffScale 后的迟到闭包建单 |
| P1 | 音响移出称重 `Merge(5)` 关键路径（独立队列 / fire-and-forget / 短超时少重试） | 降低拖尾 |
| P2 | 建单时若需二次确认，重读当前稳定窗，而非仅信闭包参数（须定义与活读数的允许差） | 降低「旧吨数」语义 |

## 2. 不建议当作根治的做法

- 只修现场音响、不改双入队/防重：拖尾减轻，同帧双建仍可能。
- 只在 UI 去重：库里仍有两张错误业务单。
- 把 backup 整段删掉前：先确认是否仍有「状态已 WeightStabilized 但首次入队丢失」的真实缺口；有则改成带「已调度」标志的单次补建，而不是无防重的第二次 `Insert`。
