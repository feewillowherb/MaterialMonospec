## 复用边界

- 旧表不改名，仅转移 Context 所有权，可复用既有接续模式；但两个 Context 不能长期同时管理同一表的结构。
- 拆成新的产品表并移动历史记录，涉及新的数据分类、主键/关联保留与读写切换，超出现有保留原表方案的证明范围。
- CREATE TABLE IF NOT EXISTS 不会修复既有表缺列或结构不兼容；历史文档已明确极旧 Urban 表缺列需要另行处理。
- 两个产品初始迁移的 Down 为空，不能据此宣称支持自动无损回退。
- 设置复制依赖原 Settings 表和 UrbanSettingsJson 列的实际存在及内容；必须核对支持的旧库版本，不能认为 EXISTS 条件能覆盖所有旧 schema。
- 此次只找到模型排除测试，未确认覆盖所有历史版本的数据库升级、断电中断、备份恢复测试或现场验收证据。tasks 勾选不等于这些能力已有证据。
