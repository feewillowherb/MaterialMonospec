# 02 — 登录逻辑问题清单

权威实现（MaterialClient `main` 及同源逻辑）：

- `HikvisionLprService`
- `HikvisionService`（含 soft-reset）

## 1. `IsOnline`：Login 后立刻 Logout

**位置**：`HikvisionLprService.IsOnline`

```text
TryLogin → NET_DVR_Logout(userId)
```

**问题**：

- 制造大量短连接；关闭方式易表现为 **TCP RST**（与现场 30+ RST 方向一致）。
- 与 LPR 长会话 / Listen 抢同一设备连接配额。
- 测在线目的与「维持可收报警会话」冲突。

## 2. LPR 抓拍：按需 Login + 缓存，停止时不 Logout

**位置**：`TriggerCaptureAsync` → `_deviceKeyToUserId`；`StopAsync` 仅 `StopListen`

**问题**：

- 启动阶段 **不** Login，仅 `StartListen`；首次抓拍才 Login。
- 缓存会话在 `StopAsync` / 退出路径上 **不** 成对 Logout。
- 与探针「先 Login 再 Listen 再 Shoot」顺序不同（探针更接近长会话）。

## 3. 监控与 LPR 两套会话缓存

**位置**：

- LPR：`HikvisionLprService._deviceKeyToUserId` + `HikvisionSdk`
- 监控：`HikvisionService.deviceKeyToUserId` + 嵌套 `NET_DVR` P/Invoke

**问题**：

- 同一相机可被登录两次。
- soft-reset 只清监控字典并 `NET_DVR_Cleanup`；LPR 侧 `_listenHandle` / `_deviceKeyToUserId` 可能变成**僵死句柄**。
- 共享进程级 `NET_DVR._initialized`：LPR 仅在下次 `EnsureInitialized` 时发现 soft-reset 并重 Init，**不重建 Listen**。

## 4. soft-reset 与 LPR 不同步（有摄像头时）

**位置**：`HikvisionService.TrySoftResetSdkAsync`（`6d8a4dcc` 引入）

**触发**：`CaptureJpegFromStreamBatchAsync` 整批失败。

**动作**：Logout 监控缓存 → `Cleanup` → Delay → `Init`。

**缺口**：

- 不通知 `HikvisionLprService` 重建 `StartListen`。
- LPR 仍以为 `_listenHandle >= 0`「已启动」。
- **无摄像头时不会触发**（见总览）；有摄像头时会直接毁掉收牌通道。

## 5. Shoot 成功 ≠ 收到数据（静默失败）

**位置**：`TriggerCaptureAsync`

只判断 `NET_DVR_ContinuousShoot` 返回值；不确认回调。

**问题**：UI / 日志显示「已触发」，无牌无图也不报 Error——与现场「没报错收不到」一致。

## 6. 回调可观测性弱

- ITS 等多为 `LogDebug`；未进回调时 INF 空白。
- 「无车牌」被 `Contains("车牌")` 判无效；有图时发空车牌事件，测试 UI 曾显示为空（已有分支 `fix/lpr-test-capture-show-no-plate` 改善展示，不解决「回调未进」）。

## 7. 启动路径不自动布防（非本次主因，但需记）

`DeviceManagerService` 仅 `hikvisionLprService.StartAsync()`（Listen）。

探针已证明本现场 **不依赖** 布防也能收；故缺布防 **不是** 当前 Urban 收不到的主因，但部分固件/场景仍可能需要 `SetupAlarmChan` + V31。
