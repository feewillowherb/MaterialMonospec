# 05 — Listen 入站 9960 被本机防火墙丢弃

- **日期**：2026-09-16（晚间现场复验）
- **角色**：`192.168.6.100` = LPR（相机）；`192.168.6.200` = PC（Urban）
- **Listen**：Urban 使用 `SystemSettings.Urls` 解析端口，现场为 **9960**

## 1. 结论

**Urban 已 `StartListen` 且 `netstat` 显示 LISTENING 时，仍可能收不到牌。**  
根因是本机 **入站 TCP 9960 被防火墙 / 安全过滤丢掉**：LPR 发 SYN，PC **不回 SYN-ACK**，握手失败，报警短连建不起来。

放行入站（或临时关闭防火墙）后回传恢复。  
此问题与「会话 Login/Logout / soft-reset」正交；会话修复不能替代防火墙放行。

## 2. 证据链

| 步骤 | 观察 |
|------|------|
| Wireshark | `100 → 200:9960 [SYN]`，随后 `[TCP Retransmission]`，**无** `200 → 100 [SYN, ACK]` |
| `netstat` | `TCP 192.168.6.200:9960 0.0.0.0:0 LISTENING`，PID 属 `MaterialClient.Urban.exe` |
| 处置后 | 入站放行 → 握手成功 → 业务可收回调 |

说明：**LISTENING ≠ 入站可达**。进程绑口成功只证明本机有监听套接字；WFP / Windows 防火墙仍可在握手前丢弃 SYN。

## 3. 与早期「已排除防火墙」的关系

`01` 曾因「同机探针可收」排除防火墙。更精确说法：

- 探针可收 → 设备与网段具备推送能力，**不排除** Urban 进程路径上的入站策略差异（规则按程序、配置变更、配置文件启用时机等）。
- 本次二分标准：`LISTENING` + **有 SYN 无 SYN-ACK** → 优先查本机入站过滤，而不是继续只查会话代码。

## 4. 现场操作（管理员）

放行（推荐保留规则）：

```powershell
New-NetFirewallRule -DisplayName "Urban LPR Listen 9960" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 9960 -Profile Any
```

临时验证（验证后务必恢复）：

```powershell
Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False
```

确认监听进程：

```powershell
netstat -ano | findstr ":9960"
tasklist /FI "PID eq <pid>"
```

## 5. Wireshark 过滤（本现场）

```text
tcp.port == 9960 and ip.addr == 192.168.6.200
```

期望正常回传：

1. `100 → 200:9960 [SYN]`
2. `200 → 100 [SYN, ACK]`
3. 随后短连接数据 / FIN

仅有 (1) 且重传 → 入站未达协议栈完成握手（防火墙优先）。

## 6. 运维建议

- 安装 / 部署 Urban 时 **显式** 增加 Listen 端口入站规则（端口以现场 `Urls` 为准，不必写死 9960）。
- **安装包**：`repos/MaterialClient/scripts/installer/*.iss` 在 `ssPostInstall` 用 `netsh` 按 **程序路径** 写入入站/出站 Allow（`profile=any`），并清除该 exe 上旧 Block；卸载时删除。新装可避免依赖「专用/公用」弹窗。
- 诊断口诀：先 `netstat`，再抓 **SYN-ACK**，再查应用日志；不要用「有 LISTENING」直接判定网络 OK。
- 已装机器若尚未重装：仍可用第 4 节命令手工放行，或重跑带新 iss 的安装包。
