# 01 — 现状与证据

## 1. 现象

| 侧 | 表现 |
|----|------|
| Urban | `监听服务启动成功: 0.0.0.0:9960`；`已触发海康威视设备抓拍`；**无** ITS / 无效车牌 / `收到 LPR 事件` |
| 探针（新包，`arm.enabled=false`） | 跳过 `SetupAlarmChan` 与 `SetDVRMessageCallBack_V31`；Listen + ContinuousShoot 后约 1s 有 `CALLBACK 0x3050` 并落盘 |

结论：设备与网络具备推送能力；**Urban 进程内未进入（或未可见）Listen 回调**。

## 2. 探针关键日志（节选）

```text
STEP arm PASS ... SKIPPED SetupAlarmChan_V50 (arm.enabled=false)
STEP listen PASS ... StartListen_V30 ok ... 0.0.0.0:9960
STEP shoot PASS ... ContinuousShoot accepted (await StartListen callback only; no SetupAlarmChan)
CALLBACK cmd=0x3050 plate=无车牌 imageBytes=... path=...\captures\..._its.jpg
```

含义：与 Urban 日常路径（仅 Listen + Shoot）对齐时，探针仍能收图。

## 3. Urban 关键日志（节选）

```text
监听服务启动成功: IP=0.0.0.0, Port=9960, ListenHandle=0
Hikvision LPR service started successfully
已触发海康威视设备抓拍: Device=camera_1
已触发测试抓拍: Device=camera_1
```

之后无回调相关 INF/WRN（现场多次复现）。`ContinuousShoot` 成功故 UI **无报错**。

## 4. Wireshark

- 显示过滤建议：`tcp.port == 9960 or ip.addr == 192.168.6.100`
- 回传专项：`ip.src == 192.168.6.100 and tcp.dstport == 9960`
- 现场观察：短时间内 **30+ 条 TCP RST**，方向均为 **Source `.200` → Destination `.100`（相机 8000）**
- 单帧 RST 示例：PC 临时端口 → `192.168.6.100:8000`，着色 `TCP RST`，`Len: 0`

含义：本机在频繁**异常复位**到相机 SDK 控制口的连接，与短生命周期 Login/Logout、重复建连一致。RST 本身不等于 9960 无数据，但是会话不稳的强信号；仍须用 9960 过滤确认入站是否存在。

## 5. 已排除 / 已修正

| 项 | 说明 |
|----|------|
| 缺 `SetupAlarmChan` / V31 | 探针关臂仍可收 → 排除为 Urban 必选项 |
| 空闲 `netstat` 仅 LISTENING | 探针空闲同样 LISTENING；报警多为短连 → 不能单靠 LISTENING 判通 |
| `6d8a4dcc` soft-reset（无摄像头） | soft-reset 仅在批量监控抓拍全失败时触发；无 `CameraConfigs` 不会调用 |
| Windows 防火墙（早期） | **曾误排除**（因同机探针可收）。晚间复验：Urban LISTENING + LPR SYN 无 SYN-ACK → 入站过滤；见 [05](./05-Listen入站9960被防火墙丢弃.md) |

## 6. 现场二分（已补全）

抓拍瞬间 Wireshark（角色：`.100`=LPR，`.200`=PC）：

- **有** `100 → 200:9960 SYN` 且 **无** SYN-ACK → 入站未达（防火墙优先，见 05）
- **有** SYN-ACK / 短连，仍无应用日志 → SDK/回调 / 会话（见 02–04）
- **无** `→ 9960` 入站 → 设备报警主机未指向本机或设备侧未推
