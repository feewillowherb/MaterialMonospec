# 03 - 优化改造路线与分阶段落地建议

知识状态：`PENDING_VALIDATION`（待 Human 确认路线与 UI 细节后，按 OpenSpec `propose → apply → archive` 流程拆包实施）。生命周期：`ACTIVE`。

---

## 1. 无论是否迁移 Vue，都应落地的 6 项核心优化

以下优化属于信息架构与交互体验改进，不绑定特定前端框架：

### 1.1 导航与信息架构收敛
- **下线冗余页**：移除 `/recycle/device-status` 路由与导航项（遵循「Urban/Recycle 非称重运维统一」原则）。
- **修正路由高亮与页面标题**：确保精确路由 + 段边界匹配，修复 `/weighing-approval` 与 `/weighing` 冲突；每个页面设置正确的 `document.title`。
- **项目管理双产品收敛（待确认）**：评估将 `/`（城管项目）与 `/recycle-projects`（资源化项目）保持两项导航，或合并为单一「项目管理」+ 顶部产品 Tab（全部 / 城管 5001 / 资源化 5020）；品牌标题同步审视是否调整为更中性的运维平台名称。

### 1.2 列表页体验标准化
- **URL Query 驱动筛选状态**：将搜索词、产品类型、日期区间、状态筛选、当前页码同步到 URL Query，刷新页面或分享链接不丢状态（替代进程内 `IPageFilterStateStore`）。
- **日期快捷选择与空态引导**：称重记录、异常审批、通行记录提供「今日 / 近 3 天 / 近 7 天 / 自定义」快捷区间；空数据时明确提示「当前时间范围暂无数据，可尝试扩大查询区间」。
- **卡口进出 & 成品进出补齐筛选与分页**：改变当前写死拉取 50 条的现状，补齐项目/车牌/时间筛选与分页，并移除 `min-width: 1400px` 硬编码横滚，改用合理列宽 + 右侧固定操作列。

### 1.3 面向运维派单的「异常聚焦」视角
- 在项目管理/设备监控页增加一键筛选「**仅看异常**」（涵盖：掉线超时、客户端在线但关键外设异常、待处理告警），降低运维从 128+ 项目里逐页翻找的成本。
- 明确区分客户端类型徽标（新客户端 SignalR vs 老客户端 `GovClient` HTTP 降级），避免运维误以为老客户端支持远程日志或实时外设监控。

### 1.4 媒体预览与交互修复
- 称重/通行照片支持统一灯箱预览（缩放、切换全景/车牌双图、无图时展示具体异常原因而非空白）。
- 彻底消除 `eval` 下载文件等 hack，统一使用标准 `Blob` / 流式下载。
- 清理 `_Host.cshtml` 中已无人使用的外链 `cdn.jsdelivr.net` ECharts 脚本，避免内网首屏阻塞。

### 1.5 客户端日志与 OTA 控制台交互加固
- **客户端日志**：保留拉取结果横幅/通知（不再被列表刷新清空），支持按客户端搜索、批量下载进度提示与失败原因直显。
- **客户端更新（OTA）**：清晰展示当前版本、目标版本、在线状态与推送结果反馈，支持按项目/产品筛选。

### 1.6 布局与视觉体系推倒重做（2026-11-27 已确认）
- **彻底告别旧 Layui 壳**：不再保留 `.layui-layout-admin`、旧顶部假多标签栏以及把所有筛选框硬塞进 `card-header` 一行的拥挤布局；不再兼容旧 `admin.css` / `components.css`。
- **新版工作台骨架**：
  - 左侧可折叠主导航 + 简洁顶栏（当前页标题、快捷刷新、当前账号与退出）；
  - 页面主体采用「独立结构化筛选条 → 撑满视口剩余高度的 `el-table` 吸顶滚动容器（全表头拖拽调宽 + 记忆列宽） → 固定底部分页条」三段式全屏工作台；
  - 结合 `iiot-field-ops-product`（信息架构与运维动线）+ `impeccable` `Operate` 模式（视觉系统与排版抛光）全新定调。

## 2. 若选择「方案 B：迁移 Vue 3 + Element Plus」的分阶段路线

建议沿用 `UrbanManagement.Recycle` 已验证的工程模式（`src/UrbanManagement.Admin/client/` → Vite 构建至 `src/UrbanManagement.Admin/wwwroot/`），拆为 **3 个独立 OpenSpec change / 会话** 推进：

### Stage 1：前端底座、BFF 补齐与布局壳 + 项目管理（Effort：**M**，~15万–25万 token）
- **后端准备**：
  - `UrbanManagement.Admin` 新增 `GET /api/session` 与 `/api/admin/client-logs/*`、`/api/admin/client-ota/*` 薄代理端点（复用 `UrbanAdmin.Session` Cookie 鉴权）。
  - 保留原有 `Login.cshtml` 与 `/logout` 不变。
- **前端脚手架**：
  - 建立 `src/UrbanManagement.Admin/client/`（Vue 3 + TypeScript + Vite + Element Plus + `vue-router`），封装统一 `http` 客户端（含 401 跳 `/login` 与统一错误提示）。
  - 实现管理布局壳（侧栏、顶栏、响应式、动态 `document.title`）。
- **首批核心页面**：
  - 迁移「项目管理」（含城管/资源化视图、状态统计、同步开关、设备详情弹窗、授权文件下载）。

### Stage 2：称重、异常审批与通行类页面（Effort：**M**，~20万–30万 token）
- **公共媒体组件**：
  - 基于 `el-image` / 自定义轻量组件实现全景+车牌双图画廊、灯箱缩放、审批页本地选图替换（原生 `<input type="file">`，告别 `file-picker.js`）及修改历史时间线。
- **业务页面**：
  - 迁移「称重记录」（URL Query 筛选、快捷日期、分页、照片弹窗、重置同步）。
  - 迁移「异常审批」（异常原因筛选、审批弹窗、附件与图片替换）。
  - 迁移「卡口进出」「成品进出」（抽取共享通行列表组件消除两页重复代码，补齐筛选与分页，消除 `1400px` 横滚）。

### Stage 3：客户端运维页面、下线 Blazor 与回归验收（Effort：**M**，~15万–25万 token）
- **业务页面**：
  - 迁移「客户端日志」（在线客户端、远程目录树/文件浏览、按日期/勾选拉取、缓存管理与批量 ZIP 下载）。
  - 迁移「客户端更新」（OTA 包目录、在线客户端列表、推送更新触发与结果展示）。
- **收口与清理**：
  - `UrbanManagementAdminModule.cs` 切换为 `MapFallbackToFile("index.html").RequireAuthorization()`，移除 Blazor Server 注册与全部 `.razor` / `wwwroot/css/components.css` / `wwwroot/public/style/admin.css` / 遗留 JS。
  - 更新 `UrbanManagement.Gateway/appsettings.json` 移除 `/_blazor` 路由；更新打包/部署脚本（含 `npm run build`）与 `openspec/specs/`（替代或归档 `blazor-admin-layout`）。
  - 跑通 Observe Graph（更新 `admin-ui-layout-observe` 断言）并在 138 实验室验证登录、鉴权、各业务主路径。

## 3. 若选择「方案 A：留在 Blazor Server」的最小优化路线（Effort：**S–M**，~10万–30万 token）

若决定短期不迁 Vue，建议聚焦高性价比改动，避免在 Blazor 里过度造轮子：
1. **第一批（S，~8万–15万 token）**：修复 U1 路由前缀、U3 `HeadOutlet` + `ClientLogs` `<PageTitle>`、U2 `aria-current`、移除 `/recycle/device-status`、删除 `_Host.cshtml` 无效外链 ECharts CDN、消除 `ProjectManagement.razor` 的 `eval` 下载。
2. **第二批（S–M，~10万–20万 token）**：消除卡口/成品 `1400px` 硬滚并补齐基础筛选；为称重/审批增加日期快捷按钮与空态引导；拆分 `WeighingApproval.razor` / `ClientLogs.razor` 弹窗子组件降低维护阻力。
